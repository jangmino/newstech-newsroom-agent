# 공식 저장 자료 선택·재승인 (M3)

외부 API가 꺼져 있거나 조회에 실패해도 기존에 확보한 공식 자료로 실습을 이어갈 수 있습니다.
실제 조회 오류를 성공으로 바꾸지 않으며 참가자가 저장 자료를 선택하고 조건을 다시 승인해야
합니다. [ADR 0011](decisions/0011-explicit-public-data-snapshot.md)에 따라 기존 공개 발췌의
사용 범위를 테스트에서 참가자 실습까지 확장했습니다. 가상 자료와 구분합니다.

## 화면에서 확인하기

1. ‘조회 자료’에서 **공식 저장 자료 · 확보 시점 기준**을 선택합니다.
2. ‘질문 해석 방식’을 **모의 규칙**으로 두고 아래 질문 중 하나를 분석합니다.
   - `전국 시·도 15-29세 청년 고용률 2020-2024년 연간 증감 폭 비교`
   - `삼성전자 2022-2024년 연간 연결 매출액 증감 폭 비교`
3. 저장 자료의 원래 조회 시각·공식 출처 링크·지원 범위·단위·검증 한계를 확인합니다.
   이 단계에는 숫자 표·브리핑·사람 검토가 없습니다.
4. 조건을 확인·편집하고 **이 조건으로 조회**를 눌러 저장 자료로 계산합니다.
5. 근거·브리핑·비교·원자료 표에 공식 저장 자료임을 표시하고 원래 시각을 유지합니다.
   모든 검토 체크는 0/4로 시작합니다. 체크 완료는 기사 사용 승인이 아닙니다.

실제 조회 오류 뒤에는 **저장 자료로 조건 다시 확인**을 누를 수 있습니다. 기존 편집 조건을
보내 지원 범위를 검사하고 저장 자료 안내를 표시합니다. 이 버튼은 실행 승인이 아닙니다.
원래 오류를 ‘전환하기 전 실제 조회 안내’로 남기고 별도의 조건 승인을 기다립니다.
미지원 조건은 안내 후 비워 재선택하게 하며 다른 연령·지표·기간을 임의로 채우지 않습니다.
질문·모드·해석 방식 변경은 이전 결과·비교·검토를 초기화하고 늦은 응답을 무시합니다.

직접 질문 분석에서 Gemini를 선택하면 기존처럼 질문만 Gemini에 보냅니다. 공공자료 모드와
독립적입니다. 오류 뒤 편집 조건을 유지하는 전환은 외부 해석을 다시 하지 않습니다.
네트워크 없이 확인하려면 모의 규칙을 선택합니다.

## 자료와 시각

| 자료 | 범위 | 원래 확보 시점 |
|---|---|---|
| KOSIS | 15~29세 연간 고용률, 17개 시도, 2020~2024년 85개 셀. 전국/수도권/비수도권 시도별 부분 선택 | 2026-09-16 12:11:07 UTC |
| OpenDART | 삼성전자 2022·2024년 사업보고서 연결 매출액, 증감 폭/률 | 2026-09-16 11:44:05 UTC, 연도별 세부 시각 보존 |

`captured_at`은 저장 발췌를 확보한 원래 조회 완료 시각입니다. 별도의 파일 저장 시각이나
패키지 빌드 시각을 꾸며내지 않습니다. `evidence.retrieved_at`과 행별 조회 시각도 현재 승인
시각으로 바꾸지 않습니다. KOSIS의 `last_changed_at`은 자료 최종수정일로 별도 표시합니다.
확보 이후 개정·정정은 반영되지 않으며 최신성·통계 해석·기사 사용을 보증하지 않습니다.

수치·공개 식별자·원래 조회 시각은 기존 공개 발췌와 같습니다. 파일 위치와 사용 범위 안내만
바꿨습니다. [OpenDART 원문 대조 기록](OPENDART_SMOKE_TEST.md),
[KOSIS 계약](KOSIS_EMPLOYMENT.md)과 [원표 대조 기록](KOSIS_SMOKE_TEST.md)의 한계를 유지합니다.
현재 모드가 live이면 실패·만료 캐시를 저장 자료로 자동 대체하지 않습니다.

## 설정

```text
FALLBACK_SNAPSHOT_ENABLED=true
```

기존 설정을 실제 snapshot 허용 스위치로 연결했습니다. `.env`에 없으면 기본 true이며
변경 시 백엔드 재시작이 필요합니다. 이번 작업에서 `.env`나 키는 변경하지 않았습니다.
이 설정은 `LIVE_API_ENABLED`, `PUBLIC_DATA_MODE`, 공급자 활성화·키와 독립적입니다.
저장 자료 읽기에는 외부 API 키·공공자료 캐시·HTTP 한도를 쓰지 않습니다.
기본 참가자 자료 모드는 계속 mock입니다. `false`이면 계획·실행 모두 503으로 중단합니다.

## API 계약

기존 `/plan`, `/execute`의 `mode`에 `snapshot`을 추가합니다. mock/live는 계속 지원하고
이전 `/analyze`는 mock 호환 경로로 유지합니다. snapshot 분석의 지원 선택값은 기존 live와
같으며 모호성은 조건 편집으로 해결해야 합니다.

`POST /api/v1/plan`:

```json
{"question":"삼성전자 2022-2024년 연간 연결 매출액 증감 폭 비교","mode":"snapshot","interpretation_method":"mock_rules"}
```

오류 뒤 전환은 이 요청에 기존 `conditions` 객체를 추가합니다. 이 필드는
`mode=snapshot` 및 `interpretation_method=mock_rules`일 때만 허용합니다.
자료원과 질문이 다르면 422로 중단합니다. 응답의 `conditions_preserved=true`는 기존 입력을
받아 검증했다는 뜻이며 지원하지 않는 필드는 비우고 `required_fields`와 한국어 안내를 제공합니다.

계획·실행 응답의 새 필드 `snapshot`은 mock/live에서 null, snapshot에서 아래 구조입니다.
자료원 미정 계획도 null입니다. 계획에는 수치·근거·브리핑이 없습니다.

| 필드 | 의미 |
|---|---|
| `snapshot_id` | 확인하고 승인할 불변 저장 자료 버전 |
| `source`, `title` | `kosis|opendart`, 참가자용 자료명 |
| `captured_at` | 원래 확보한 조회 완료 시각, ISO 형식 |
| `coverage`, `unit` | 지원 범위와 입력 단위 |
| `source_urls` | 공식 원표 또는 공시 원문 링크, 인증 URL 없음 |
| `caveats` | 저장 자료·개정 미반영·검증 한계·사람 검토 안내 |

`POST /api/v1/execute`는 기존 `question`, `conditions`, `approved=true` 외에
`mode=snapshot`, 계획에서 확인한 `snapshot_id`를 요구합니다. 누락·형식 오류는 422이며
mock/live 요청에 `snapshot_id`를 넣어도 422입니다. 실행 시 허용 설정·조건·자료원·버전·
전체 원본의 무결성을 다시 검사합니다. 성공 시 `evidence.data_mode=snapshot`, `cache=null`,
원래 시각·출처와 `snapshot`을 반환합니다. 계산 출처는 계속 `kosis|opendart`이며 확보 방식은
`data_mode`로 구분합니다. 일반 응답은 고정 mock 예시, `verification_status=review_required`입니다.

| 실패 | HTTP | `detail.code` |
|---|---|---|
| 저장 자료 사용 비활성 | 503 | `snapshot_disabled` |
| 버전 불일치 | 409 | `snapshot_changed` |
| 파일 없음·무결성·정규화 오류 | 503 | `snapshot_unavailable` |
| 지원 조건·자료원 불일치 | 422 | `invalid_conditions` |

기존 `detail.message/field_errors` 구조의 한국어 안내를 사용하며 저장 파일 경로·원문 오류를
노출하지 않습니다. snapshot 전용 오류는 `Cache-Control: no-store`입니다. 오류 응답에는
근거·브리핑이 없습니다. 실제 조회 실패의 응답 계약도 유지합니다.

## 패키지와 갱신

공개 원본은 [snapshot_data](../apps/api/src/newsroom_agent/snapshot_data/)에 한 부만 보관하고
테스트도 같은 파일을 사용합니다. `providers/snapshot.py`가 허용된 파일명·버전·SHA-256을
검사하고 전체 자료를 기존 정규화 규칙으로 검증한 뒤 승인 조건의 부분 자료를 선택합니다.
live와 snapshot이 같은 계산·브리핑 구성 함수를 사용합니다. 요청의 경로나 URL을 읽지 않습니다.
읽기에는 Python의 [패키지 리소스 API](https://docs.python.org/3.12/library/importlib.resources.html)를 사용합니다.

기존 [Hatch 패키지 파일 선택](https://hatch.pypa.io/latest/config/build/#packages)에 따라
JSON을 wheel/sdist에 포함하며 기존 Dockerfile의 `COPY apps/api/src`에도 포함됩니다.
새 저장 서비스·DB·배포 형태는 추가하지 않습니다. 갱신은 원문·단위·이용조건 확인 후 새 버전과
해시·검증 기록을 포함한 코드 변경으로 합니다. 자동 저장·다운로드·갱신은 없습니다.

## 검증과 남은 범위

자동 테스트는 환경 파일과 실제 네트워크를 차단합니다. 계획의 수치 비노출, 엄격한 승인,
편집 조건 유지, 모호성·범위 검사, 버전 변경, 파일 누락·변조·비정상 값, 원래 시각 보존,
정확한 계산, live 실패 유지, UI 재승인·검토 초기화·늦은 응답 무시를 검사합니다.
패키지에 두 원본이 포함되고 저장소 밖에서도 읽히는지 별도로 확인합니다.

2026-09-16 구현 검증:

- `UV_OFFLINE=1 make check`: 백엔드 554개·프론트엔드 113개 테스트, Ruff·TypeScript·빌드 통과.
- wheel·sdist에 두 JSON이 포함되고 wheel을 저장소 밖에서 읽어 두 자료원을 정규화함을 확인.
- 기존 발췌와 수치·출처·원래 시각이 동일함을 비교. 사용 범위 안내와 파일 위치만 변경.
- 로컬 브라우저에서 두 자료원의 승인 전 비노출, 승인 후 저장 자료 표시와 계산을 확인.
  KOSIS 조건 변경·재승인 시 이전 결과 비교와 검토 0/4 초기화도 확인.
- 자동 테스트와 위 브라우저 확인에서 실제 Gemini·OpenDART·KOSIS 호출은 실행하지 않음.
- `git diff --check` 통과. 추적·추가 대상 126개 파일의 비밀정보 검사에서 발견 0건,
  실제 `.env`는 변경하지 않았고 Git 제외 상태를 확인.

후속 **행사용 접근코드**는 [접근 계약](WORKSHOP_ACCESS.md)으로 완료했습니다.
저장 자료도 같은 요청별 코드 검사를 거칩니다. [요청 ID·구조화 로그](REQUEST_LOGGING.md)도
완료했습니다. [읽기 전용 실습 운영 상태 화면](OPERATIONS_STATUS.md)에서 파일 사용 가능
여부·범위·원래 시각을 확인할 수 있습니다. [개인 임시 stage](STAGE_SMOKE_TEST.md),
[30명 단기 부하 시험](STAGE_LOAD_TEST.md), [장애·저장 자료 전환 리허설](FALLBACK_REHEARSAL.md)도
완료했습니다. 마지막 검증은 로컬 모의 장애와 stage 비활성 경로로 한정합니다.
기관 전환·실제 공급자 클라우드 연결과 장애·행사 조건의 부하 확인·분산 호출 정책은 남아 있습니다.
