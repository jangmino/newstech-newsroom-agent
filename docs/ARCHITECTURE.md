# 아키텍처

## 배포 단위

로컬에서는 프론트엔드와 백엔드를 따로 실행합니다. 스테이징과 행사 환경에서는 운영 부담을 줄이기 위해 한 개의 Cloud Run 서비스로 배포합니다.

```text
Participant browser
        │
        ▼
React/Vite UI
        │ /api/v1/*
        ▼
FastAPI
        │
        ├─ Query planner / single orchestrator
        ├─ OpenDART adapter
        ├─ KOSIS adapter
        ├─ Calculation and validation
        ├─ Brief composer
        └─ Cache / labeled snapshot fallback
```

## 책임 분리

| 계층 | 책임 |
|---|---|
| 프론트엔드 | 질문 입력, 조건 확인·수정, 근거와 브리핑 표시, 상태 안내 |
| 오케스트레이터 | 질문 구조화, 자료원 선택, 도구 호출 순서 결정, 추가 질문 |
| 공급자 어댑터 | 인증, API 호출, 오류를 내부 공통 형식으로 변환 |
| 계산·검증 | 숫자 정규화, 단위 확인, 증감률·순위 계산, 누락값 점검 |
| 브리핑 구성 | 확인된 사실, 한계, 후속 취재 질문 구성 |

## 중요한 경계

- 브라우저는 외부 API 키를 알지 못합니다.
- LLM은 숫자 계산의 최종 권위가 아닙니다.
- 공식 API 응답이라고 해서 해석이 자동으로 정확해지는 것은 아닙니다.
- live 데이터와 snapshot 데이터는 결과에 명확히 표시합니다.
- 한 요청이 두 공공데이터를 임의로 결합하는 기능은 초기 범위에서 제외합니다.

## M1 조건 편집·승인 흐름

참가자 화면은 `/api/v1/plan`으로 질문을 해석한 뒤 대상·지표·기간·비교 기준과
자료원별 추가 조건을 편집합니다. 선택값은 백엔드가 제공하고, 미해결 조건이 있으면
한국어 안내와 함께 승인을 막습니다. 변경 항목에는 처음 제시된 값과 ‘수정됨’을 표시합니다.

‘이 조건으로 조회’를 누르면 `/api/v1/execute`에 승인 플래그와 조건 전체를 보냅니다.
서버는 조건을 다시 검증하며, 질문에서 원래 조건을 다시 선택하지 않고 승인된 조건과
자료 모드로 근거와 브리핑을 만듭니다. 계획 단계에는 근거·브리핑을 생성하거나 반환하지 않습니다.

질문이나 조건을 바꾸면 클라이언트가 화면의 승인·결과·검토 표시를 지우고 진행 중인 요청을 취소합니다.
조건만 바꿀 때는 비교용으로 직전 성공 결과 한 건을 메모리에 유지하며 재승인 전에는 숨깁니다.
요청 버전도 확인하므로 늦게 도착한 이전 응답이 새 조건의 결과로 표시되지 않습니다.
서버에 계획이나 승인 이력을 저장하지 않습니다. 단일 오케스트레이터와 기존 두 실습
시나리오를 유지합니다. 자료 조회는 기본 mock이며 아래 M2의 명시적 설정과 참가자 선택으로
Gemini 해석과 OpenDART/KOSIS 실제 조회를 각각 사용할 수 있습니다.

모의 결과는 승인된 조건, 단위, 설계된 계산식, 생성 시각, 주의사항을 표시합니다.
청년 고용에는 가상 숫자와 계산 결과가 있으며, 기업 실적의 `raw_values`는 빈 배열입니다.
API의 검증 상태는 계속 `review_required`입니다. 화면의 실습 검토 진행 상태와 구분합니다.
기존 `/api/v1/analyze`는 호환 경로로 남으며 승인 절차를 강제하지 않습니다.
상세 계약과 지원 조건은 [API 문서](../apps/api/README.md)에 정리합니다.

## M1 응답 비교

승인된 `/api/v1/execute` 응답은 기존 결과 필드에 `general_response`를 추가합니다.
일반 응답은 기존 두 질문 유형별로 작성한 고정 문장이고 `data_mode=mock`,
`generation_method=scripted`를 명시합니다. 모델 호출이나 새 데이터 공급자는 없습니다.
계획 응답과 이전 `/api/v1/analyze` 계약에는 이 필드를 추가하지 않습니다.

같은 질문 아래 일반 응답 예시와 근거 기반 브리핑을 나란히 표시합니다. 조건 변경 시
비교 화면 전체를 무효화하며, 재승인하면 일반 예시는 그대로 두고 근거 기반 결과에
새 조건을 반영합니다. 비교표는 조회 조건·자료원·단위와 계산식·시각·원자료·사람 검토를
살펴보도록 돕습니다. 일반 응답은 숫자가 없고 청년 고용의 근거 기반 응답만 가상 숫자를
계산합니다. 공식 통계가 아닌 실습 자료임을 표시하고,
기존의 승인 조건·계산 근거·주의사항 패널을 함께 유지합니다.

## M2 준비: 가상 수치 계산

`providers/mock_employment.py`는 승인 조건에 맞는 2020~2024년 가상 지역 자료를
선택합니다. `calculations.py`는 공급자나 모델과 독립적으로 Decimal 연산·입력값 검증·
증감 폭/률·순위를 담당합니다. 실제 KOSIS 조회나 공식 지역 코드는 사용하지 않습니다.
숫자와 기간 범위, 결측·0 기준값 등 실습 규칙은
[ADR 0003](decisions/0003-synthetic-mock-calculations.md)에 기록합니다.

계획 응답은 `available_years`만 안내하며 수치는 승인 후에만 반환합니다.
실행 응답의 `calculation`은 입력값·변화값·순위·계산 불가 상태·경고를 제공합니다.
`evidence.raw_values`에도 승인된 시작·종료 값과 단위를 남기며, 자료명·계산 시각·
브리핑에 가상 자료임을 표시합니다. 누락값은 0으로 바꾸지 않고, 모두 계산 불가하면
1위를 만들지 않습니다. 단위 불일치나 비정상 숫자는 계산을 중단하고 한국어 오류를 반환합니다.
이 필드는 기업 실적 실행에서는 `null`이며, 기존 `/analyze` 응답에는 추가하지 않습니다.

## M1 사람 검토 상태

승인 결과가 있을 때만 `ReviewSession`을 표시합니다. 참가자는 승인 조건·자료 출처와
시각·계산 근거·해석 한계의 네 항목을 확인하고, 체크 수에 따른 진행 상태를 봅니다.
근거 기반 브리핑의 상태 링크도 같은 값을 표시합니다. 전체 체크는 실습 항목 확인을
뜻하며 사실 검증 완료나 기사 사용 승인이 아닙니다. 일반 응답 예시는 별도 검토 대상입니다.

체크 상태는 해당 결과 컴포넌트의 메모리에만 있습니다. 결과의 `request_id`를 키로
사용하고, 질문·조건 변경이나 다시 분석·조회 시 결과와 함께 컴포넌트를 제거합니다.
같은 조건의 재조회도 새 검토로 시작합니다. 기존 요청 버전 검사로 무효화된 응답은
다시 검토 패널을 만들 수 없습니다. 새로고침 시에도 상태가 사라집니다.

새 API나 저장소는 없습니다. `brief.verification_status`를 변경하거나 서버에 체크
내용을 보내지 않으며 `/plan`, `/execute`, `/analyze` 계약을 유지합니다.
상태와 검증 시나리오는 [사람 검토 흐름](REVIEW_FLOW.md)을 참고합니다.

## M1 조건 변경 전후 비교

`App`은 같은 질문 해석 세션 안에서 직전 성공한 `ExecutionResponse` 한 건을 메모리에
유지합니다. 새 승인 응답이 유효한 요청 버전으로 도착했을 때만 이를 비교 기준으로 사용하고
직전 성공 결과를 갱신합니다. 조건 편집·조회 중·요청 실패 시 모든 결과와 비교를 숨깁니다.
실패나 늦은 응답은 비교 기준을 갱신하지 않습니다. 질문 변경·예시 선택·재분석·새로고침은
비교 기준까지 초기화합니다. 결과가 세 건 이상이어도 직전 결과와 이번 결과만 남습니다.

`resultComparison.ts`는 질문·자료원이 같고 승인 조건이 달라졌는지 확인합니다.
비교는 대상·지표·기간·비교 기준과 추가 필터를 기준으로 하며 요청 ID·시각·필터 키 순서는
조건 변경으로 취급하지 않습니다. 같은 조건 재조회에는 전후 비교를 표시하지 않습니다.

`ConditionComparison`은 조건 차이, 각 응답의 자료원·단위·시각·계산식·한계와 가상 지역별
입력값·변화값·순위를 표시합니다. 대상 제외와 누락·0 기준값을 구분하고, 브라우저에서
두 변화값을 빼거나 순위를 다시 계산하지 않습니다. 기업 실적은 수치 없이 조회 설계를 비교합니다.
새 결과의 검토 체크는 항상 초기화되며 과거 체크 이력을 보관하지 않습니다.
새 API·DB·브라우저 저장소·실제 공급자 호출은 없습니다. 기존 API 계약과 타입을 유지합니다.
상세 규칙은 [조건 변경 전후 비교](CONDITION_COMPARISON.md)에 기록합니다.

## M1 오류·모호성 실습 안내

`workshopScenarios.ts`는 기존 청년 고용 질문에 사용할 세 장면의 설명과 예시 조건만
정의합니다. `WorkshopGuide`는 현재 계획·입력 조건·요청 상태·실제 모의 계산 결과에서
안내를 도출합니다. 별도 완료 플래그나 가짜 오류·계산 결과를 만들지 않습니다.

장면 선택은 질문·결과·비교 기준·검토를 초기화하고, 분석 요청도 자동 실행하지 않습니다.
예시 조건 적용과 기간 수정은 기존 조건 편집과 같은 무효화 경로를 사용합니다.
조건을 채워도 참가자가 별도로 승인해야 `/execute`를 호출합니다. 지원하지 않는 기간은
기존 클라이언트·서버 검증이 거부하고, 0 기준값·누락값은 기존 가상 자료에서 계산합니다.
다른 기간의 계산 가능 결과는 원래 기간의 결측을 복구했다는 뜻이 아님을 안내합니다.

질문 변경·예시 질문 선택은 안내를 닫습니다. 같은 질문 재분석은 안내만 유지하고 결과와
비교 기준을 초기화합니다. 안내만 닫을 때는 입력·결과·검토를 유지합니다. 요청 중 장면을
바꾸면 기존 요청 버전 검사로 늦은 응답을 무시합니다. 안내 상태도 브라우저 메모리에만
있습니다. API 계약·프론트엔드 응답 타입·자료원·실습 핵심 질문을 변경하지 않습니다.
참가자 단계와 회귀 검증은 [오류·모호성 실습 안내](WORKSHOP_SCENARIOS.md)에 기록합니다.

## M2 질문 구조화 어댑터와 검증

`QuestionPlanner`는 질문을 받아 내부 `StructuredQuestion` 형식의 JSON 문자열을
반환합니다. 기본값은 `MockQuestionPlanner`이고, 참가자 선택과 서버의 두 활성화 설정이
모두 허용할 때만 `GeminiQuestionPlanner`가 클라이언트를 생성합니다.
`planning.py`가 엄격한 형식·자료원·지원 조건 검증을 거쳐 계획을
만듭니다. 해석기는 승인·계산·조회·브리핑 도구에 접근하지 않습니다.

형식 오류나 자료원 충돌은 안전한 503으로 중단합니다. 지원하지 않거나 불확실한
조건은 입력란을 비우고 한국어 확인 안내를 반환합니다. 공개 선택 이유와 안내는
서버가 만들고, 원래 출력·공급자 오류 내용은 노출하지 않습니다. 두 자료원이 함께
언급되면 질문을 나누도록 요청합니다. 지원 범위 검사가 의미 해석의 정확성을 보증하지는 않습니다.

`/plan`은 `interpretation_method=mock_rules|gemini`를 받으며 성공 응답에 해석 방식과
`interpretation_model`을 표시합니다. `/execute`는 해석기를
다시 호출하지 않고 공통 규칙으로 승인 조건과 질문의 자료원 범위를 검증합니다.
`/analyze`는 기존 라우팅과 계약을 그대로 유지합니다. 화면은 해석 방식을 표시하고,
처음 해석의 확인 안내와 현재 편집 조건의 검증을 구분합니다.
상세 계약·오류·제외 범위는 [질문 구조화 문서](QUESTION_PLANNING.md)에 기록합니다.

Gemini 요청은 JSON Schema와 고정 system instruction을 사용하며 검색·도구·자동 함수
호출을 제공하지 않습니다. SDK 재시도를 끄고 클라이언트는 요청 종료 시 닫습니다.
프로세스 내부 호출 제한과 HTTP 타임아웃을 적용하고, 오류 시 한국어 안내로 중단합니다.
해석 방식 변경은 조건·결과·비교·검토를 초기화하며 늦은 응답도 무시합니다.
설정·요청량·실제 호출 미검증 범위는 [ADR 0004](decisions/0004-gemini-planning-with-mock-evidence.md)를 따릅니다.
후속 로컬 실제 호출 네 건의 결과와 남은 검증 범위는 [확인 기록](GEMINI_SMOKE_TEST.md)에 있습니다.

## M2 OpenDART 승인 조회

`providers/opendart.py`는 두 연도의 연간 연결 매출액을 순차 조회하고,
`opendart_financials.py`가 회사·연도·보고서·계정·통화·금액을 검증합니다.
`live_financials.py`는 승인 조건 재검증 뒤에만 클라이언트를 생성합니다.
`calculations.financial_change`가 Decimal로 증감 폭/률을 계산하고 고정 문장으로
브리핑을 구성합니다. LLM은 조회·계산·브리핑 작성에 관여하지 않습니다.

`/plan`·`/execute`의 OpenDART `mode=live`는 삼성전자 2022·2024년 연결 매출액만 지원합니다.
전역 live, 공공자료 live 허용, OpenDART 활성화와 키 설정을 모두 검사합니다.
계획에는 `data_mode`를 추가하며 근거·계산값을 반환하지 않습니다. 실행에는 별도
`financial_calculation`을 추가하고 `evidence.raw_values`에 정확한 정수 문자열과
계정·접수번호·원문 링크·연도별 조회 시각·공개 요청 인자를 남깁니다.
고용 순위용 `calculation`과 이전 `/analyze`는 유지합니다.

자료 모드는 해석 방식과 독립적입니다. 모드 변경 시 조건·결과·비교·검토를 초기화하고
늦은 응답을 무시합니다. `FinancialEvidence`는 원 단위 문자열을 Number로 바꾸지 않고
표시하며, 일반 응답은 계속 고정 모의 예시로 구분합니다. 동일 자료 모드의 직전 성공
결과만 조건 비교에 사용합니다. 사람 검토 상태는 계속 `review_required`입니다.

재시도·리다이렉트·환경 프록시·자동 fallback을 사용하지 않고 키 포함 URL과 원래
오류를 노출하지 않습니다. 요청별 HTTP/전체 수신 시간 제한과 응답 크기 상한을 적용하고
한 연도라도 실패하면 부분 결과를 반환하지 않습니다.
[조회 계약](OPENDART_REVENUE.md), [ADR 0006](decisions/0006-opendart-approved-live-flow.md),
[원문 대조 기록](OPENDART_SMOKE_TEST.md)을 참고합니다.

## M2 KOSIS 승인 조회

`providers/kosis_employment.py`는 네트워크·설정 접근 없이 15~29세 고용률의 공식 표·분류·
단위와 17개 시도·2020~2024년 범위를 검사합니다. 요청 연간 코드 `Y`와 실제 응답의 `A`를
구분하고, 명시한 지역·연도별 셀의 중복·누락·비수치·단위 불일치를 중단합니다.
공개 API 발췌의 사용 범위는 아래 M3 snapshot에서 명시적으로 확장했습니다.
원래 값·최종수정일·조회 시각을 구분합니다.

`providers/kosis.py`는 고정된 자료 API에 한 번 요청합니다. 전역 live와 공공자료 live 허용,
`KOSIS_ENABLED`·키 설정을 검사하며 OpenDART 설정에 의존하지 않습니다. `/plan`에는
자료 조회가 없습니다. `/execute`는 자료원·모드별 조건 검증 후 `live_employment.py`로
분기합니다. 승인된 대상·연령·지표·기간만 요청하고 해석기를 다시 호출하지 않습니다.

`calculations.rank_changes`로 시작·종료 연간 값의 증감 폭/률과 순위를 계산합니다.
`calculation.data_origin=kosis`로 mock을 구분하고 모든 중간 연도 값도 `raw_values`에
남깁니다. 0 기준 증감률은 순위에서 제외하지만 통계 부호·누락 셀·단위 오류는 조회 전체를
실패시킵니다. 일부 응답으로 전체 지역 순위를 만들지 않습니다.

`KosisEvidence`는 공식 표 링크·연간 공표값·시도/표/항목/연령 코드·최종수정일을 표시합니다.
`CalculationTable`·응답/조건 비교·검토 항목도 출처에 맞는 한국어 안내를 사용합니다.
승인 전 숨김·편집 후 재승인·검토 초기화는 유지하며 실제 결과를 가상 자료로 표시하지 않습니다.
브리핑은 고정 문장과 검증된 계산으로 구성하고 일반 응답은 계속 mock입니다.

요청당 최대 85개 셀, HTTP/전체 수신 제한 20초·2MB 상한이며 재시도·리다이렉트·환경
프록시·자동 fallback이 없습니다. 전송 로그와 오류에서 키 포함 URL을 노출하지 않습니다.
[자료 계약](KOSIS_EMPLOYMENT.md), [ADR 0008](decisions/0008-kosis-approved-live-flow.md),
[실제 확인 기록](KOSIS_SMOKE_TEST.md)을 참고합니다. 기존 `/analyze`는 계속 mock 전용입니다.

## M3 공공자료 캐시와 요청 공유

`public_data_cache.py`의 `PublicDataCache`는 FastAPI lifespan마다 공급자별로 생성합니다.
`/execute`의 승인·조건·자료원·활성화 검증 뒤 각 실행 함수가 정규화 자료를 요청합니다.
캐시는 공개 조회 조건으로 만든 키를 사용하며 비교 기준·질문·키는 포함하지 않습니다.
완료 자료의 TTL·LRU와 진행 작업 사전을 분리하고 같은 키만 작업을 공유합니다.

전체 정규화 성공 후에만 TTL을 시작하고, 저장값과 응답값은 복사하여 분리합니다.
만료 후 실패 시 이전 자료를 반환하지 않습니다. 요청 취소는 공유 작업을 취소하지 않으며
서버 종료 시 작업을 취소·회수합니다. 한 프로세스의 한 ASGI 이벤트 루프에서만 사용합니다.
여러 워커·Cloud Run 인스턴스 간 저장·공유·호출 제한을 제공하지 않습니다.

`ExecutionResponse.cache`에 사용 방식·저장/만료 시각·TTL·경과 초를 추가합니다.
기존 `Evidence`와 `/analyze` 계약을 바꾸지 않으며 원래 조회 시각을 유지합니다.
`CacheNotice`와 브리핑·검토·조건 비교에서 자료 재사용을 표시합니다. 승인마다 계산과
브리핑·요청 ID를 새로 만들고 검토를 초기화합니다. [계약·검증](PUBLIC_DATA_CACHE.md)과
[ADR 0009](decisions/0009-process-public-data-cache.md)를 참고합니다.

## M3 공공자료 호출 제한

`public_data_limits.py`의 자료원별 공유 제한기를 OpenDART/KOSIS 어댑터에 주입합니다.
승인·조건·활성화 검증과 캐시 확인 뒤 실제 HTTP 경계에서만 횟수와 동시 실행 수를 검사합니다.
기본값은 자료원마다 최근 60초 시작 30회·동시 2회이며 캐시 hit/공유 대기자는 추가로 세지 않습니다.
OpenDART는 연도별 두 호출을 별도로 셉니다. 실패·취소도 시작 횟수에 포함하고 동시 실행
자리는 반환합니다. 부분 결과는 저장하지 않고 대기열·자동 재시도·자동 fallback은 없습니다.

429 `public_data_rate_limited|public_data_busy`는 한국어 메시지·자료원·`scope=process`를
포함하며 횟수 제한에만 예상 초와 `Retry-After`를 제공합니다. 참가자는 조건을 유지하고
직접 재승인하며 오류 시 이전 결과·검토 상태를 숨깁니다. Gemini의 기존 한도는 독립적입니다.
프로세스 재시작 시 초기화되며 worker/인스턴스 간 공유하지 않습니다.
[ADR 0010](decisions/0010-process-public-data-limits.md), [설정·오류 계약](PUBLIC_DATA_LIMITS.md)을 참고합니다.

## M3 공식 저장 자료

`providers/snapshot.py`는 패키지 안의 고정 JSON·버전·SHA-256을 확인하고 기존 순수
정규화 함수를 사용합니다. KOSIS 전체 85개 셀 또는 OpenDART 두 연도를 검증한 뒤 조건의
부분 자료만 사용합니다. `compose_employment/compose_financials`의 결정론적 계산과 브리핑
구성을 live와 공유합니다. 네트워크·키·live 캐시·호출 한도·런타임 파일 쓰기는 없습니다.

`/plan`의 `mode=snapshot`은 조건과 저장 자료 메타데이터만 반환합니다. 선택적으로 기존
`conditions`를 받아 외부 재해석 없이 지원 범위를 확인합니다. `/execute`는 엄격한 승인과
`snapshot_id`를 받아 설정·조건·자료원·버전을 다시 검사합니다. `FALLBACK_SNAPSHOT_ENABLED`는
live 설정과 독립적입니다. 결과의 `evidence.data_mode=snapshot`, `snapshot`과 원래 시각으로
저장 자료를 구분하며 `cache=null`입니다. 이전 `/analyze`의 mock 계약을 유지합니다.

`SnapshotNotice`는 승인 전에 출처·원래 확보 시각·범위를, 승인 후에는 저장 자료 사용을
표시합니다. 실제 조회 오류는 그대로 반환하며 참가자의 전환·재승인 없이는 실행하지 않습니다.
자료 모드가 바뀌면 비교·검토를 초기화하고 다른 저장 자료 버전끼리도 비교하지 않습니다.
미지원 범위·자료 누락·무결성 오류는 대체 자료 없이 중단합니다.
[ADR 0011](decisions/0011-explicit-public-data-snapshot.md), [계약·검증](SNAPSHOT_FALLBACK.md)을 참고합니다.
