# 아키텍처

## 배포 단위

로컬에서는 프론트엔드와 백엔드를 따로 실행합니다. 스테이징과 행사 환경에서는 운영 부담을 줄이기 위해 한 개의 Cloud Run 서비스로 배포합니다.

```text
Participant browser
        │
        ▼
React/Vite UI
        │ /api/v1/*
        ▼
FastAPI
        │
        ├─ Query planner / single orchestrator
        ├─ OpenDART adapter
        ├─ KOSIS adapter
        ├─ Calculation and validation
        ├─ Brief composer
        └─ Cache / labeled snapshot fallback
```

## 책임 분리

| 계층 | 책임 |
|---|---|
| 프론트엔드 | 질문 입력, 조건 확인·수정, 근거와 브리핑 표시, 상태 안내 |
| 오케스트레이터 | 질문 구조화, 자료원 선택, 도구 호출 순서 결정, 추가 질문 |
| 공급자 어댑터 | 인증, API 호출, 오류를 내부 공통 형식으로 변환 |
| 계산·검증 | 숫자 정규화, 단위 확인, 증감률·순위 계산, 누락값 점검 |
| 브리핑 구성 | 확인된 사실, 한계, 후속 취재 질문 구성 |

## 중요한 경계

- 브라우저는 외부 API 키를 알지 못합니다.
- LLM은 숫자 계산의 최종 권위가 아닙니다.
- 공식 API 응답이라고 해서 해석이 자동으로 정확해지는 것은 아닙니다.
- live 데이터와 snapshot 데이터는 결과에 명확히 표시합니다.
- 한 요청이 두 공공데이터를 임의로 결합하는 기능은 초기 범위에서 제외합니다.

## 추후 추가할 운영 장치

- 프로세스 내부 동시 실행 제한
- 캐시와 요청 중복 제거
- 실행 ID를 포함한 구조화 로그
- API별 타임아웃·제한적 재시도
- 민감정보 제거
- 부하 시험 시나리오
