## 실제 공식 자료와 원문 대조

### KOSIS

공식 API로 3개 표의 ITM/PRD/CMMT 메타데이터 9건과 실제 연간/월간 자료를 조회했다.
원본 메타데이터는 `event_data/`, 테스트 값은 `tests/fixtures/event/`에 보존한다.

확인했다. 최신 연간 2025, 월간 2026-08을 승인 가능한 종료 시점으로 고정했다.

차원 검증을 수행했으며 모든 원문 화면 셀까지 대조했다는 의미는 아니다.

제공되는 본문과 목록의 차이를 테스트한다. 기간 내 해당 유형 0건과 요청 오류를 구분한다.

### Gemini 및 공식 저장 사례

수동 4개 사례의 해석·공식 자료 조회·일반 응답은 각각 성공했다. 첫 근거 브리핑은
4건 중 1건 성공, 3건 실패였다. 당시 실패의 상세 분류가 없어 원인을 단정하지 않는다.
실패한 3건은 운영자가 이미 조회된 근거로 별도 재생성해 출력 검증을 통과했다. 자동 재시도는
추가하지 않았다. 현재 실패 trace는 예외 종류를 남긴다. 저장 4개 사례는 실제 자료와 실제
모델 출력이며 생성 이력·시각을 보존한다. 공시 저장 브리핑은 목록 근거로 작성된 것이며
본문 전체 요약으로 소개하지 않는다. 공시 본문 발췌는 사람 검토에 별도로 제공된다.

후보 빌드 `bd724d4b-2269-4ca3-a6e0-d70092125728`, 이미지
`sha256:6145ba06976adbc547dbd000147e7d7ebadd730fbec904c0471551adbfba3f93`.
기능 체크포인트 `a60b34e`. 후보 revision `newsroom-stage-event-20260918`, 이전 revision
`newsroom-stage-part2b-20260917`를 롤백 대상으로 유지했다.

수동 검증 명령은 `scripts/event_rehearsal.py`이며 접근코드를 출력하지 않고 고정 조건과
최대 호출 예산을 사용한다. 30개 흐름은 20초 이상 간격, 최대 90 Gemini 호출이다.
자동 테스트나 실제 참석자 30명 시험이 아니다. API 사용량 한도의 한계까지 고의로 밀어붙이지 않는다.
실제 행사장 Wi-Fi·Windows 브라우저·30명 참가자 동시 진행·기관 운영 책임 인계는
아직 시행하지 않았으며 행사 운영 완료와 구분한다.

## 브리핑 안정성 보완

첫 후보 stage의 네 실행은 조회/일반 응답/저장 재생을 통과했으나 근거 브리핑은
1/4만 성공해 트래픽을 전환하지 않았다. 별도 실제 출력 진단에서 유효한 슬롯 ID가 인용
목록에서 빠진 사례와 한계/후속 질문에 숫자 날짜·근거 ID를 직접 쓴 사례를 확인했다.
슬롯의 실제 참조 ID는 코드로 인용 목록에 연결하고, 미등록 ID·직접 생성 숫자 거부는 유지한다.
한계/후속 질문까지 슬롯 규칙을 명시했다. SDK 출력 단계에서 중단된 건도 있었지만 초기
실패의 종료 사유는 저장하지 않았으므로 전부 토큰 초과라고 단정하지 않는다.

[공식 Gemini 안내](https://ai.google.dev/gemini-api/docs/generate-content/thinking)에 따라
행사 Gemini 3 계열은 계획·근거·일반 응답 모두 동일한 LOW 추론 수준을 사용한다.
출력 상한은 계획 2048, 두 응답 4096으로 유지했다. 생각 내용은 요청/노출하지 않는다.
별도 네 공식 저장 근거를 사용한 LOW 실제 생성은 4/4 출력 검증을 통과했다.
수동 운영 스크립트도 HTTP 성공 외에 브리핑 성공률 90% 이상을 완료 기준으로 검사한다.

로컬 Chrome에서 공식 저장 자료 선택 → 조건만 표시 → 승인 → 근거·사람 검토 표시,
검토 보류, 사례 변경 시 결과·검토 모두 숨김을 확인했다. 산출물 내용과 다운로드 버튼의 Blob 생성·현재 검토/근거 보존은 동작 테스트에서
검증했다. 브라우저 다운로드 이벤트 확인이 제한되어 DOM에 링크를 붙이고 URL 해제를
늦추는 호환성 보완을 적용했다. 브라우저 보안 정책이 다운로드 기록 화면 접근을 차단하여
그 방법으로 파일 저장 완료를 확인하지 않았고 우회하지 않았다. 실제 행사 Windows 다운로드는 별도 확인 대상이다.

### 공식 저장 자료 동시 재생

수정 후보에서 30개 세션을 동시에 시작해 승인된 저장 결과 30회와 저장 일반 응답 30회를
조회했다. 60/60 HTTP 200, 조건·자료 모드·브리핑 계약 일치. 클라이언트 최대 동시 요청
30개, 외부 Gemini/OpenDART/KOSIS 호출 0회. 결과 응답 p95 309ms, 일반 응답 p95 244ms.
이는 한 네트워크에서 실행한 HTTP 동시성 확인이며 30명 브라우저/행사장 시험은 아니다.

화면 점검에서 다른 질문의 결과가 조건 변경 비교에 남는 문제를 수정했다. 같은 질문의
조건 수정은 직전 승인 결과를 비교하지만, 질문·자료 모드·저장 사례가 바뀌면 비교 기준도
초기화한다. 회귀 테스트를 추가했다. 이 마지막 변경은 프론트엔드뿐이며 30개 live 흐름을
검증한 후보와 최종 후보의 백엔드 공급자·계산·브리핑 코드는 동일하다.
