# 2부 다섯 조사 사례: 사용법과 계약

구현 결정은 [ADR 0021](decisions/0021-investigation-scenarios.md), 자료 범위는
[공식 자료 구성](INVESTIGATION_DATA.md), 완료 증거는 [검증 기록](INVESTIGATION_VALIDATION.md)을 따른다.

## 참가자 흐름

1. **2부 · 내 질문으로 조사하기**에서 A~E 사례를 고르거나 관련 질문을 직접 적는다.
2. **조사 계획 제안받기**를 누른다. Gemini는 검증된 자료 범위로 질문을 해석한다.
   모호하거나 지원 밖의 조건이면 질답으로 구체화한다. 이 단계는 수치를 조회하지 않는다.
3. **02 조사 계획**에서 대상·기간·비교 방법·자료 방식을 확인한다.
   새 다섯 사례에는 API 매개변수 입력 폼을 두지 않았다. 변경은 **계획을 말로 수정하기**로 한다.
4. **이 계획으로 조사**를 누른다. A~C는 실제 API 또는 명시적으로 고른 공식 저장 원자료,
   D~E는 원문 대조한 공식 저장 원자료를 사용한다. D/E는 승인 화면에서 이를 별도로 고지한다.
5. 요약·관찰·한계·후속 취재와 비교표를 읽는다. E는 사업 비중 막대도 확인한다.
   비교표 아래 근거 번호와 **04 조회·계산·본문 상세**에서 원문·수식·조회 시각을 확인한다.
6. 원하면 **실제 일반 모델 응답 비교하기**를 별도로 실행한다. 같은 질문·승인 조건을 전달하며,
   일반 응답에는 공식 조회 근거를 보내지 않는다. 추가 Gemini 호출 1회다.
7. **05 사람의 검토**에서 사실과 근거, 부족한 해석, 후속 질문, 데스크 확인·수정 초안을 남긴다.
   내려받기 JSON에는 비교표·원자료 버전·AI 원본·검토 기록이 함께 포함된다.

질문·계획 수정과 재조회는 결과·검토 상태를 초기화한다. 기록이 필요하면 먼저 내려받는다.
브리핑·인용은 기사 사용 승인이나 원인 입증이 아니다. 자동 기사 작성·발행은 제공하지 않는다.

## API 계약 확장

기존 `/api/v1/analyze`, 행사 endpoint와 기본 계약을 유지한다. 새 별도 세션·DB는 없다.

- `GET /api/v1/event/catalog`에 `investigations[]`를 추가한다.
  `tool,title,question,source,steps,calls,archive_only,start,end` 등 공개 범위만 포함한다.
- `EventConditions.tool`에 `births,migration,prices,compensation,business_mix`를 추가한다.
  각 도구의 대상·지표·기간·연령 허용 범위는 서버 카탈로그가 검증한다. 모델이 표 코드나 URL을 만들지 않는다.
- `POST /api/v1/event/plan`과 `/stream`: 이전과 같은 질문·질답·수정 계약.
  새 도구도 `ready / needs_clarification / unsupported`와 필드 오류를 반환한다.
  값·순위·브리핑을 계획 응답에 넣지 않는다.
- `POST /api/v1/event/execute`와 `/stream`: `approved:true`, 승인 조건, 자료 방식이 필요하다.
  `mode`에 `archive`를 추가한다. `live`는 A~C의 새 실제 조회, `archive`는 다섯 사례의
  검증 원자료 재계산+새 브리핑, 기존 `snapshot`은 사전 생성된 고정 결과 재생이다.
  D/E의 `live` 요청, 기존 도구의 `archive` 요청은 안내 오류로 거부한다. 조용히 바꾸지 않는다.
- `EventResult.analysis`는 기존 응답에서는 `null`, 새 사례에서는 다음 구조다.
  `title`, `source_version`, `method[]`, `focus_ids[]`, `tables[]`.
  각 표는 `title,columns[],rows[][],evidence_ids[],note`를 제공한다.
  `facts`의 근거 번호가 표·브리핑·계산에 공통으로 연결된다.
- 브리핑에 전달하는 사실은 기본 최대 24개, E 최대 40개다. 전체 사실은 결과에 보존한다.
  수치·기간·순위는 신뢰된 슬롯으로 렌더링한다. E는 시작/종료 사업 비중과 마지막 해 증가분을 구분한다.
- `data_mode`와 일반 모델 비교 계약에도 `archive`를 추가한다. 승인 조건은 변경 없이 반환한다.
- 동일 조건·방식의 자료 계산은 기존 TTL 캐시/동시 요청 공유를 사용한다. 모델 응답은 공유하지 않는다.
  실제 조회는 기존 공공자료 대기·동시성 제한을 사용하며 취소·요청 번호·진행 안내를 유지한다.

## 실패와 미지원 범위

조건·표·항목·분류·기간·중복 셀을 검증한다. 결측을 0으로 만들지 않는다. B에서 같은 기간의
인구 분모가 없으면 비율을 제외하고 표시한다. C의 말단 품목이 빠지면 전체 기여도 순위를 멈춘다.
지역 경계 변경·정정·분류 차이는 설명하며 단순 일반적 주의사항만으로 `부분 조회`라고 표시하지 않는다.

공급자 실패는 한국어 안내와 재승인을 요구한다. 브리핑 실패 시 확보한 비교표·근거는 유지한다.
새 다섯 사례의 공식 저장 원자료는 Gemini 장애를 해결하는 수단은 아니다. 기존 고정 결과 재생으로
전환할 때도 사례를 선택하고 다시 승인해야 한다.

D/E 임의 회사·기간, 경북 외 시군 상세, 임의 표 조합, 원인 자동 입증, 시장 전체 CB,
반도체 여러 자료원 결합, CMS·기사 발행, 자사 파일럿은 이번 범위 밖이다.
