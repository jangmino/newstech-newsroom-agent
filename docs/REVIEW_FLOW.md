# 사람 검토 상태 (M1 · mock)

참가자는 승인된 결과의 조건·근거·한계를 읽고, 확인한 항목을 체크합니다.
이 기능은 **실습 진행 표시**입니다. 사실 검증 완료, 기사 사용 승인, 원자료의 신뢰성
보증을 뜻하지 않습니다. 가상 자료와 모의 응답은 실제 취재 근거로 사용할 수 없습니다.

## 참가자 흐름

‘이 조건으로 조회’ 후 결과가 도착하면 ‘05 · 사람의 검토’ 패널이 나타납니다.
계획 단계, 조회 중, 요청 실패 시에는 검토 패널이 없습니다.

| 확인 항목 | 확인할 내용 |
|---|---|
| 승인된 조회 조건 | 대상·지표·기간·비교 기준·연령 등 추가 조건 |
| 자료의 출처와 시각 | 실제 공식 자료 조회가 아닌 모의 결과이며, 시각도 공식 조회 시각이 아님 |
| 원자료와 계산 근거 | 청년 고용: 가상 입력값·단위·계산식·순위·계산 불가 여부 / 기업 실적: 숫자·계산 결과가 없고 계산식은 조회 설계임 |
| 해석의 한계와 추가 취재 | 브리핑의 한계와 추가 취재 질문 |

| 체크 수 | 진행 상태 |
|---|---|
| 0/4 | 실습 검토 전 |
| 1~3/4 | 실습 검토 중 |
| 4/4 | 실습 검토 항목 확인 완료 |

모든 체크는 처음에 해제되어 있으며 참가자가 직접 선택합니다. 체크를 해제하면 상태도
즉시 되돌아갑니다. 브리핑의 상태 링크는 같은 진행 상태를 표시하고 검토 패널로 이동합니다.
일반 응답 예시는 체크 대상에 포함하지 않으며 ‘사람 검토 필요’ 표시를 유지합니다.
누락값이나 0 기준값이 있어도 그 한계를 읽고 확인할 수 있습니다. 체크로 경고를 없애거나
계산 불가 값을 유효한 숫자로 바꾸지 않습니다.

## 수명과 API 경계

- 체크 상태는 현재 결과에만 연결됩니다. 질문·예시 질문·조건·질문 해석 방식을 바꾸면
  결과와 함께 사라집니다. Gemini 해석도 검토 상태를 승인하거나 이어받지 않습니다.
- 조건 변경 전후 비교에는 과거 승인 결과를 보여주지만 과거 검토 체크는 보관하거나
  이어받지 않습니다. 이번 결과는 항상 0/4부터 시작합니다.
- 같은 조건으로 다시 조회하거나 질문을 다시 분석해도 초기화됩니다.
- 재조회 실패·재시도 뒤의 결과는 새 검토로 시작합니다. 늦게 도착한 이전 응답은 복원하지 않습니다.
- 새로고침하면 초기화됩니다. DB, localStorage, sessionStorage, 서버 저장, 로그인은 사용하지 않습니다.
- API 응답과 프론트엔드 API 타입은 그대로이며 `brief.verification_status`는 `review_required`입니다.
  체크 내용은 서버로 전송하지 않습니다. `/api/v1/analyze` 호환 동작도 그대로입니다.

## 검증

`make test-web`으로 프론트엔드 동작 테스트를 실행합니다. 기존 Node 20·Vite 5 환경에
맞는 Vitest 3과 React Testing Library·jsdom을 개발 의존성으로 사용합니다.
[Vitest 설치 조건](https://v3.vitest.dev/guide/)과
[Testing Library API](https://testing-library.com/docs/react-testing-library/api/)를 참고합니다.

테스트 실행기는 dotenv 로딩을 비활성화합니다. 테스트는 직접 작성한 모의 응답으로
진행하고, 선언되지 않은 fetch와 XMLHttpRequest 요청, 브라우저 저장소 쓰기를 막습니다.
승인 전·로딩 중 숨김, 체크·해제, 두 질문 유형의 문구, 각 조건·질문·재조회·실패·늦은 응답·
앱 재시작에 따른 초기화를 검사합니다. `make check`와 CI에도 이 검사를 포함합니다.

수동 확인은 두 질문에서 각각 체크·해제하고, 모두 체크한 뒤 조건을 바꿔 재승인합니다.
키보드 Tab·Space로 체크할 수 있는지, 모바일에서 항목과 진행 상태를 읽을 수 있는지,
모든 상태에서 ‘기사 사용 승인이 아님’ 안내가 유지되는지도 확인합니다.
