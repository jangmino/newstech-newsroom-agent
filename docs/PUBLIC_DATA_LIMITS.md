# 공공자료 호출·동시 실행 제한 (M3)

승인 후 OpenDART·KOSIS HTTP 호출이 몰릴 때 서버에서 바로 중단하고 참가자에게 안내합니다.
캐시를 재사용하는 사람 수와 실제 외부 요청 수를 구분합니다.
[ADR 0010](decisions/0010-process-public-data-limits.md)을 따릅니다.

## 참가자 경험

- 한도 안에서는 기존 조건 승인·근거·브리핑·사람 검토 흐름을 유지합니다.
- 호출 횟수가 차면 자료원과 요청 한도 안내, 예상 대기 초를 표시합니다. 예상 시간은
  다른 요청에 따라 달라질 수 있으며 조회 성공을 보장하지 않습니다.
- 동시에 진행하는 외부 조회가 많으면 잠시 후 ‘이 조건으로 조회’를 다시 누르도록 안내합니다.
  종료 시점을 알 수 없으므로 임의의 대기 시간을 표시하지 않습니다.
- 질문·수정한 조건은 유지하고 이전 근거·브리핑·검토·조건 비교는 숨깁니다.
  자동 재시도·자동 승인·mock/snapshot 대체는 없습니다. 직접 재승인에 성공하면 검토는 0/4입니다.
- 캐시에 유효한 자료가 있거나 같은 조회를 이미 진행 중이면 추가 외부 한도를 쓰지 않습니다.
  원래 자료 시각과 재사용 여부, 승인 후 표시, 사람 검토 원칙은 그대로입니다.

## 설정과 계산 단위

```text
PUBLIC_DATA_REQUESTS_PER_MINUTE=30
PUBLIC_DATA_MAX_CONCURRENT_REQUESTS=2
```

`.env`에 없으면 기본값을 사용합니다. 값 변경은 백엔드 재시작 후 적용합니다.
두 값 모두 OpenDART와 KOSIS에 각각 독립적으로 적용하며 합산하지 않습니다.
앱의 보호 설정이며 제공기관·계정의 공식 할당량을 의미하지 않습니다.
범위는 각각 1~300회, 1~30회입니다. OpenDART 두 연도를 정상 완료하려면 분당 한도를
최소 2회 이상으로 설정해야 합니다. Gemini는 기존 `REQUESTS_PER_MINUTE`와
`MAX_CONCURRENT_REQUESTS`를 따르며 이 한도를 공유하지 않습니다.

| 항목 | 처리 |
|---|---|
| 횟수 | 실제 HTTP 요청을 시작하기 직전부터 최근 60초의 시작 횟수, 단조 시계 사용 |
| 동시 실행 | 요청 시작부터 응답 본문을 읽고 연결을 닫을 때까지, 기다리는 참가자 수와 별개 |
| KOSIS | 승인한 지역·기간의 연간 자료 묶음 조회 1회 |
| OpenDART | 시작/종료 연도 각각 1회, 두 번째 요청은 그 요청의 시작 시점으로 계산 |
| 실패·시간 초과·취소 | 이미 시작한 요청 횟수는 유지, 동시 실행 자리는 항상 반환 |
| 한도 때문에 거절 | 요청을 보내지 않고 횟수도 늘리지 않음 |
| 캐시 적중·동일 조회 공유 | 추가 요청과 추가 횟수 없음, 진행 중 작업 자체에는 한도 적용 |
| 캐시 비활성 | 매 승인마다 실제 HTTP 한도를 적용, 제한을 끄는 설정이 아님 |
| mock·`/analyze`·질문 해석·`/health` | 공공자료 한도를 쓰지 않음 |

승인·조건·자료원·활성화·키 설정 검증이 먼저입니다. 한도 초과는 대기열에 넣지 않고
즉시 반환합니다. 횟수와 동시 실행이 모두 찼으면 횟수 제한을 우선 안내합니다.
OpenDART 첫 연도가 성공해도 두 번째가 거절되면 전체 실행을 실패 처리합니다.
부분 자료·실패는 캐시하지 않고 다음 승인 때 두 연도를 다시 요청합니다.
만료된 캐시는 한도를 우회하거나 오류 대신 표시하는 용도로 쓰지 않습니다.

공유 작업을 기다리던 참가자가 취소해도 실제 HTTP 작업은 계속 실행될 수 있습니다.
이때 동시 실행 자리도 작업 종료까지 유지합니다. 서버 종료는 진행 작업을 취소·회수합니다.

## API 계약

`POST /api/v1/execute`의 기존 성공 계약은 유지합니다. 아래 오류만 추가합니다.

```json
{
  "detail": {
    "code": "public_data_rate_limited",
    "message": "현재 서버의 KOSIS 조회 요청 한도에 도달했습니다. 입력한 조건은 유지됩니다. 자동으로 다시 조회하지 않습니다. 잠시 후 ‘이 조건으로 조회’를 다시 눌러 주세요.",
    "field_errors": {},
    "source": "kosis",
    "scope": "process",
    "retry_after_seconds": 23
  }
}
```

| 경우 | HTTP | `detail.code` | `retry_after_seconds` | 헤더 |
|---|---|---|---|---|
| 횟수 초과 | 429 | `public_data_rate_limited` | 가장 오래된 시작이 60초 창에서 빠질 때까지 올림한 1~60초 | `Retry-After: <초>`, `Cache-Control: no-store` |
| 동시 실행 초과 | 429 | `public_data_busy` | `null` | `Cache-Control: no-store`, `Retry-After` 없음 |

`source`는 `kosis|opendart`, `scope`는 `process`입니다. 근거·브리핑·캐시 자료는 오류에
포함하지 않습니다. 공급기관이 반환한 429는 기존 `kosis_rate_limited` 또는
`opendart_rate_limited`로 구분합니다. 프론트엔드는 새 횟수 제한 코드와 정상 정수 범위의
대기 값에만 예상 시간을 덧붙입니다. 기존 오류의 메시지·필드 오류 계약도 유지합니다.
HTTP 429, 선택적인 `Retry-After`, 오류 응답의 캐시 금지는
[RFC 6585 §4](https://www.rfc-editor.org/rfc/rfc6585#section-4)를 참고합니다.

## 구현 범위와 검증

`public_data_limits.py`는 자료원별 시작 시각 목록·동시 실행 수만 메모리에 보관합니다.
짧은 잠금으로 입장을 원자적으로 검사하며 HTTP 대기 중 잠금을 보유하지 않습니다.
백엔드가 공유 제한기를 어댑터에 주입하며 어댑터는 검증 후 HTTP 경계에서 사용합니다.
질문·키·URL·참가자 식별자는 저장하지 않습니다. `.env`와 실제 키를 변경하지 않았습니다.

가짜 시계·모의 HTTP 전송·화면 동작으로 다음을 검증합니다. 자동 테스트는 `.env`를 읽거나
실제 공급자에 연결하지 않습니다.

- 60초 경계·초 올림·거절 후 시간창 유지·스레드 간 동시 입장.
- 실패·시간 초과·취소 후 자리 반환과 이미 시작한 횟수 유지.
- 캐시 적중·공유 요청의 추가 횟수 없음, 만료 후 제한, 캐시 비활성 시에도 제한.
- 자료원별 독립 한도, OpenDART 연도별 시작 시각·부분 성공 폐기와 재승인.
- 승인/조건 검증·mock·이전 API·질문 해석과의 분리, 한국어 429 계약·헤더.
- 공유 조회를 기다리던 요청 취소 시 실제 HTTP 자리 유지.
- 화면의 조건 유지·오류 안내·자동 재시도 없음·검토 초기화·늦은 오류 무시.

2026-09-16 `UV_OFFLINE=1 make check`에서 백엔드 516개·프론트엔드 94개 테스트,
Python lint·TypeScript 검사·웹/백엔드 빌드가 통과했습니다. 기존 테스트 의존성의
사용 중단 예정 경고 2건은 남아 있습니다. `git diff --check`도 통과했습니다.
Git 변경 후보를 포함한 파일 120개에서 현재 키 값·인코딩 값·비밀키 패턴이 없음을 확인했고,
`.env`는 Git에서 제외되어 있습니다. 이번 검증은 실제 공급자 호출을 하지 않았습니다.
로컬 서버 재시작 후 mock 질문 분석·승인 전 실행 차단·승인 결과와 웹 응답도 확인했습니다.

단일 프로세스의 동작 검증이며 행사 30명 부하 시험이 아닙니다. 재시작하면 한도가
초기화되고 worker/Cloud Run 인스턴스마다 별도로 셉니다. 행사 전체·일일·키별 할당량이나
사용자별 접근 제한을 보장하지 않습니다. 분산 정책, 접근코드, 구조화 로그, Secret Manager,
실제 stage 배포와 행사 부하 시험은 남아 있습니다. 후속 [명시적 snapshot
fallback](SNAPSHOT_FALLBACK.md)을 적용했습니다. 저장 시점·출처를 밝히고 참가자가
선택·재승인한 경우에만 사용합니다. 다음 최소 단위는 행사용 접근코드입니다.
