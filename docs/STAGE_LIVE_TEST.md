# 개인 stage의 Gemini·공공자료 실제 연결 확인

[ADR 0016](decisions/0016-personal-stage-live-validation.md)에 따라 개인 GCP에서 기존 두
질문의 전체 흐름을 확인합니다. 기관 계정 요청·환경 이전은 마지막 인계 단계로 미루며
개발과 live 시험을 막지 않습니다. 새 질문·자료원·DB·계정 인증은 추가하지 않습니다.

## 구성과 범위

- 기존 단일 Cloud Run·공유 접근코드·리소스·비용 알림을 유지합니다.
- `infra/stage.env.yaml`은 첫 mock 배포용으로 유지합니다. 이번에는 명시적으로
  `infra/stage-live.env.yaml`을 사용하여 전역 live·Gemini·OpenDART·KOSIS를 켭니다.
- 기존 개인 API 키는 같은 개인 프로젝트 Secret Manager에 공급자별로 저장합니다.
  숫자 버전을 고정하고 런타임에 개별 Secret 읽기 권한만 줍니다. 빌드에 키를 주지 않습니다.
- 키는 로컬 설정에서 메모리로 읽어 stdin으로 전달하며 값·`.env`를 출력하거나 업로드하지
  않습니다. `infra/stage-live-secrets.local.json`에는 Secret 이름·버전만 두고 Git에서 제외합니다.
- 기존 검증 이미지 digest로 트래픽 0인 후보 리비전을 만듭니다. 기본 URL은 이전
  리비전에 두고 후보 확인 후 전환합니다. 변경 명령은 항상 계정·프로젝트·리전을 명시합니다.
- 자동 테스트는 모의 전송만 사용합니다. 아래 수동 점검은 실제 호출·비용이 발생합니다.

Gemini 키를 Secret Manager에 보관해도 키의 원래 소속 프로젝트·결제는 바뀌지 않습니다.
이번에는 기존 키의 소규모 연결을 확인했으며 소속 프로젝트의 사용량·결제·할당량 점검은
다음 live 부하 시험 전에 수행합니다. stage 프로젝트의 월 1만원 알림이 Gemini 비용까지
포함한다고 가정하지 않습니다. [Gemini 프로젝트와 API 키의 결제 관계](https://ai.google.dev/gemini-api/docs/billing#projects-and-api-keys)를 따릅니다.

참가자는 입장 뒤 **Gemini · 실제 모델**, **공식 실제 자료 · OpenDART / KOSIS**를 선택합니다.
화면 초기 선택은 계속 모의 규칙·모의 자료이며 설정을 켜도 자동으로 호출하지 않습니다.
분석은 Gemini만 호출하고 공공자료는 **이 조건으로 조회** 이후에만 조회합니다.
일반 응답 예시는 고정 모의 문장, 근거 브리핑은 공식 수치와 결정론적 계산입니다.

## 배포 명령 준비

로컬 Secret 참조 파일은 `infra/stage-live-secrets.example.json`의 형식을 사용합니다.
파일에는 값·`latest`·다른 공급자 항목을 넣을 수 없습니다. 도구는 명령을 출력할 뿐
Secret 생성·배포를 자동으로 실행하지 않습니다. 고정 이미지와 복귀 리비전을 먼저 확인합니다.

```bash
python3 scripts/stage.py live-plan \
  --config infra/stage-config.local.json \
  --provider-secrets infra/stage-live-secrets.local.json \
  --image-digest sha256:<64_HEX_DIGEST> \
  --revision-suffix live-<DATE> \
  --rollback-revision <VERIFIED_PREVIOUS_REVISION>
```

`deploy_candidate`는 Secret 네 개(접근코드 포함)와 공개 설정을 적용하며 IAM 공개 범위를
바꾸지 않습니다. 기존 트래픽은 유지하고 `live-check` 태그로 후보를 확인합니다.
`promote`는 검증한 후보로 100% 전환하고 임시 태그를 지웁니다. `rollback`은 이전
리비전으로 되돌리고 임시 태그도 지웁니다. 복귀용 이미지·Secret 버전을 먼저 폐기하지 않습니다.
[Secret 주입](https://docs.cloud.google.com/run/docs/configuring/services/secrets)과
[트래픽 전환·롤백](https://docs.cloud.google.com/run/docs/rollouts-rollbacks-traffic-migration)을 따릅니다.

## 제한된 수동 API 확인

```bash
apps/api/.venv/bin/python scripts/stage_live.py \
  --base-url https://<CANDIDATE_OR_APPROVED_STAGE_HOST> \
  --access-code-file .cache/stage-workshop-code.txt \
  --report .cache/stage-live-<DATE>-01.json \
  --allow-live
```

코드 파일은 소유자만 읽을 수 있어야 하고 보고서 경로는 새 파일이어야 합니다.
HTTPS origin만 허용하며 리다이렉트·환경 프록시·자동 재시도는 없습니다. 전체 240초,
요청당 55초, 순차 **19개 HTTP 요청**입니다. 실패 시 다음 단계로 넘어가지 않습니다.

1. stage/live 설정·코드 보호·공급자 설정·캐시·두 저장 자료를 외부 호출 없이 확인합니다.
2. KOSIS, OpenDART 질문을 각각 Gemini로 한 번 해석하고 명시한 여섯 조건과 비교합니다.
   계획에 근거·브리핑이 있거나 조건이 다르면 멈춥니다.
3. 비교 기준을 증감률로, KOSIS 대상/기간을 수도권/2021-2024로 수정합니다. 승인 false는
   422로 거부되어야 합니다. 승인 true 결과의 조건·출처·단위·시각·계산식·검토 필요를 확인합니다.
4. 비교 기준만 증감 폭으로 바꿔 재승인합니다. 새 결과·요청 ID와 원자료 캐시 hit를 확인합니다.
5. 같은 편집 조건으로 공식 저장 자료를 명시적으로 선택합니다. 승인 전 비노출·별도 승인·
   원래 확보 시각·저장 자료 표시를 확인합니다. 실제 공급자 장애를 인위적으로 만들지 않습니다.

한 실행의 Gemini 요청은 최대 2회, 실제 승인 요청은 공급자별 최대 2회입니다. 캐시가 없는
첫 정상 조회라면 OpenDART HTTP 2회·KOSIS 1회이며 재승인은 캐시를 씁니다. 캐시가 작동하지
않거나 인스턴스가 바뀌면 이론상 OpenDART 최대 4회·KOSIS 최대 2회까지 시작될 수 있습니다.
보고서는 요청 수·상태·시간·검증된 요청 ID·캐시 상태만 기록하고 질문·조건·원문 응답·
키·접근코드·개인 프로젝트 URL을 넣지 않습니다. 실제 공급자 호출 수와 앱 요청 수를 구분합니다.

브라우저 확인·필요한 재확인을 포함한 이번 작업 전체 상한은 Gemini 6회, OpenDART 8회,
KOSIS 4회입니다. 실패한 요청도 포함하고 재실행을 무작정 반복하지 않습니다.

## 브라우저 확인과 장애 전환

기존 두 질문 각각에서 Gemini+실제 자료 선택 → 분석 → 승인 전 비노출 → 조건 수정 →
승인 → 실제 자료·검토 0/4를 확인합니다. 하나를 체크하고 조건 변경·재승인 시 초기화와
캐시 표시를 확인합니다. 질문 변경도 이전 결과·검토를 초기화해야 합니다.

실제 조회 실패가 발생하면 한국어 오류와 요청 ID를 남기고 참가자가 저장 자료를 선택합니다.
계획 전 실패와 실행 후 실패의 차이·조건 유지·재승인은 [장애 리허설](FALLBACK_REHEARSAL.md)을
따릅니다. 이번 stage에서 오류가 없었다면 공급자 장애 복구까지 시험했다고 기록하지 않습니다.
의도적인 장애·실패 후 UI 전환은 계속 오프라인 테스트와 기존 리허설 근거로 구분합니다.

## 남은 범위

소규모 연결 성공은 30명 live 사용·지속 부하·동시 최초 입장·행사장 브라우저 검증을
대신하지 않습니다. 개인 환경에서 후속 검증을 계속하고 기관 계정·프로젝트·기관 키·운영
책임 전환은 마지막 인계 단계에서 진행합니다. 운영 절차는 [가이드](OPERATOR_GUIDE.md)를 따릅니다.

## 2026-09-17 API·배포 확인 기록

- 이전 검증 이미지(배포 소스 `2bae7cc`)를 재사용했습니다. 이후 제품 런타임 코드 변경은
  없으며 이번 추가는 배포/점검 도구·오프라인 테스트·문서입니다. 추가 이미지 빌드는 없었습니다.
- 개인 프로젝트에 공급자 Secret 세 개를 만들고 버전 1로 고정했습니다. 각 Secret 정책에는
  기존 런타임의 읽기 권한만 있으며 접근코드 버전·공개 범위·리소스·비용 알림은 유지했습니다.
- 후보 리비전의 기본 트래픽 0% 상태에서 11:37 KST에 API 확인을 시작했습니다.
  두 질문의 명시 조건을 Gemini가 모두 기대대로 해석했습니다.
- 총 **19개 앱 HTTP 요청**: 200 14회, 의도한 승인 차단 422 4회, 코드 없는 접근 차단
  401 1회. 예상 밖 오류·계약 불일치 0건입니다. 편집 조건과 근거 조건이 일치했습니다.
- 이 API 확인의 실제 공급자 요청은 **Gemini 2회·OpenDART 2회·KOSIS 1회**입니다.
  두 실제 최초 실행은 cache miss, 비교 기준 수정 후 재승인은 모두 hit였습니다.
  저장 자료 실행은 원래 확보 시각·출처와 별도 승인을 유지했습니다.
- 두 모델 요청은 약 3.88초·6.86초, 실제 자료의 첫 실행은 약 0.38초·0.64초였습니다.
  표본이 두 건뿐이므로 부하 성능 지표로 사용하지 않습니다.
- 통과 후 기존 stage URL을 live 리비전 100%로 전환하고 후보 태그를 제거했습니다.
  배포의 네 Secret 참조·숫자 버전·공급자 Secret 권한을 확인했으며 요청 ID 19개가
  해당 리비전의 앱 로그와 일치했습니다. 개인 식별자는 Git 제외 로컬 배포 기록에만 둡니다.
- Git 제외 기록: `.cache/stage-live-20260917-01.json`, `.cache/stage-live-deployment.json`,
  `.cache/stage-live-plan-20260917.json`. 보고서·배포 기록에는 비밀 값을 넣지 않았습니다.
- `make doctor`, `UV_OFFLINE=1 make check` 통과: 백엔드 **728개**(26개 추가),
  프론트엔드 **175개**, Ruff·TypeScript·웹/백엔드 빌드 통과. 기존 의존성 경고 2건은 남습니다.

브라우저에서도 기존 공개 URL과 접근코드로 두 질문의 Gemini 해석·승인 전 비노출·수정 표시·
최종 승인 조건·공식 근거를 확인했습니다. KOSIS는 수도권/2021-2024/증감률, OpenDART는
증감률로 수정했고, 두 결과 모두 검토 1/4 → 조건 변경 시 숨김 → 재승인 후 0/4를 확인했습니다.
질문 변경 시 이전 근거·검토도 초기화됐습니다. 브라우저의 네 승인 실행은 모두 기존 원자료를
재사용했고 원래 조회 시각·기한을 표시했습니다. 화면 점검 뒤 OpenDART 실제 결과를 열어 두었습니다.

API·브라우저를 합친 **이번 수동 검증의 공급자 호출은 Gemini 4회·OpenDART 2회·KOSIS 1회**로
정한 상한 이내입니다. 실제 공급자 오류는 발생하지 않았으므로 클라우드에서 장애를 일으키고
복구한 것으로 기록하지 않습니다. 실패 후 UI 전환은 기존 모의 장애 리허설과 자동 테스트,
stage의 저장 자료 별도 승인 확인으로 구분합니다.

`git diff --check`와 변경 문서 14개의 상대 링크 159개 검사를 통과했습니다. Git 추적·추가
대상 169개 파일과 로컬 기록 4개의 비밀정보 검사에서 발견 0건입니다. `.env`·접근코드·
로컬 Secret 참조·실행 보고서는 Git에서 제외되며 `.env`는 수정하지 않았습니다.
