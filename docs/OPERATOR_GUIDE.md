# 행사 운영자 가이드

진행자는 참가자의 조건 승인·출처 확인·사람 검토를 안내하고, 기술 담당자는 배포·접근·
로그·장애 복구를 맡습니다. 같은 사람이 두 역할을 맡아도 시작·중단·종료 결정은
[행사 점검표](EVENT_CHECKLIST.md)에 기록합니다. 이 문서는 운영 절차이며 실행 완료 기록이 아닙니다.

## 현재 준비 범위

2026-09-17 기준 **M3 운영 준비 중**입니다. 개인 임시 stage에서 mock·공식 저장 자료,
공유 접근코드, 30명 단기 API 부하 시험, 장애 전환 리허설을 확인했습니다.
후속으로 [Gemini 해석+두 공공자료의 stage 실제 연결](STAGE_LIVE_TEST.md)도 소규모로
확인했습니다. 실제 모드 부하·지속 사용·동시 최초 입장·행사장 브라우저 확인은 남아 있습니다.
과거 확인 결과는 [배포](STAGE_SMOKE_TEST.md), [부하 시험](STAGE_LOAD_TEST.md),
[장애 리허설](FALLBACK_REHEARSAL.md)에 있으며 행사 당일 확인을 대신하지 않습니다.

개인 stage는 사용자 승인으로 개발·live 검증에 계속 사용합니다. 기관 계정·프로젝트 요청은
마지막 인계 단계로 미룹니다. 실제 행사 소유자·결제·키·접근코드·운영 책임은 인계 시
확정하고 선택한 모드를 검증한 뒤 시작합니다. 기관 자격증명은 Secret Manager에
보관합니다. 개인 Secret을 기관에 복사하지 않습니다. [환경 책임](ENVIRONMENTS.md),
[기관 교체 절차](STAGE_DEPLOYMENT.md), [ADR 0015](decisions/0015-temporary-personal-stage.md)를 따릅니다.

| 역할 | 시작 전에 정할 책임 |
|---|---|
| 진행자 | 질문·자료 모드 안내, 전체 재시도 중지, 저장 자료 전환·실습 종료 안내 |
| 기술 담당자 | 배포 식별·접근 확인, 요청 ID 조사, 복구·롤백·공개 접근 종료 및 확인 |
| 주최 측 결정 담당자 | 행사 시작/중단/재개, 비용·로그 보관·자원 폐기 일정 결정 |

## 전날 준비

1. 점검표를 Git 제외 로컬 기록이나 주최 측의 제한된 문서 공간에 복사합니다. 담당자·행사
   시간·환경 소유자·URL·이미지 digest·리비전·사용할 모드·복구 기준 리비전을 적습니다.
   키·코드 값은 적지 않습니다. 변경 명령에는 계정·프로젝트·리전을 명시합니다.
2. 행사 환경과 선택한 모드에서 승인·조건 수정·결과·검토 초기화·장애 전환을 확인합니다.
   실제 모드는 공급자별 최소 연결 확인과 행사 조건의 부하 검증을 먼저 완료해야 합니다.
   모의 규칙과 저장 자료만 사용하더라도 행사장 네트워크·브라우저 확인이 필요합니다.
3. 접근코드 배포 경로, 비용 알림 수신자, 로그 열람 권한·보관 기간, 중단 시 연락 경로와
   종료 후 공개 여부를 정합니다. 코드를 URL·채팅 공개방·화면 공유·Git에 넣지 않습니다.
4. 진행자의 설명 자료도 준비합니다. 서버나 인터넷이 안 되면 같은 서버의 저장 자료도
   사용할 수 없습니다. 별도 오프라인 앱은 구현되어 있지 않습니다.

## 시작 30분 전 확인

진행자와 기술 담당자가 아래 순서로 확인하고 점검표에 시작 가능 여부를 기록합니다.
하나라도 실패하면 해당 모드의 시작을 보류합니다. 다른 모드로 진행하려면 그 모드의
확인과 주최 측 결정을 남기고 참가자에게 변경을 알립니다.

1. 배포 URL·환경 소유자·현재 리비전이 전날 확인한 대상과 같은지 확인합니다.
   새 브라우저 탭에서 입장 화면을 열고, 코드 없이 실습 API에 접근되지 않는지 확인합니다.
   stage/event의 공개 `/api/v1/access`는 `required: true`, `available: true`여야 합니다.
2. **행사 접근코드**로 **실습 입장** 후 **실습 운영 상태 보기**를 엽니다.
   **상태 다시 확인**으로 확인 시각·공급자 설정·저장 자료·캐시/한도를 읽습니다.
   현재 개인 live stage의 기대값은 세 공급자 **설정상 허용 · 실제 연결 미확인**, 두 저장 자료
   **사용 가능 · 파일 확인됨**입니다. mock 리비전으로 복귀하면 세 공급자는 **사용 꺼짐**입니다.
3. **설정상 허용 · 실제 연결 미확인**은 키 유효성·모델 접근·공급자 가동·남은 할당량의
   확인 결과가 아닙니다. 상태 화면은 외부 API를 호출하지 않고 설정과 저장 파일만 읽습니다.
   접근코드를 아는 참가자도 볼 수 있으며 관리자 제어 화면은 아닙니다.
4. 아래 두 질문으로 사용할 모드의 승인 흐름을 확인합니다. 분석 후 아직 근거·브리핑이
   없어야 합니다. 조건 한 곳을 수정하여 수정 표시를 보고 **이 조건으로 조회**를 누릅니다.
   최종 조회 조건·자료원·단위·원래 조회 시각·계산식·한계·검토 0/4를 확인합니다.
5. 검토 항목 하나를 체크한 뒤 조건을 바꿉니다. 결과·검토가 숨겨지고 재승인 후 0/4로
   시작하는지 확인합니다. 요청 ID 한 건이 앱 로그에서 조회되는지도 기술 담당자가 확인합니다.
6. 현재 자료 모드, 장애 시 전환 방식, 중단 연락 경로를 참가자에게 알리고 시작합니다.

| 질문 | 지원 범위와 수정 예시 |
|---|---|
| 전국 시·도 15-29세 청년 고용률 2020-2024년 연간 증감 폭 비교 | 공식 자료: 17개 시도·15~29세 연간 고용률·2020~2024년. 수도권, 2021-2024, 증감률로 수정 가능 |
| 삼성전자 2022-2024년 연간 연결 매출액 증감 폭 비교 | 공식 자료: 삼성전자·2022/2024년·연간 연결 매출액. 비교 기준을 증감률로 수정 가능 |

mock은 가상 자료입니다. 공식 자료의 지원 범위·수치와 같다고 설명하지 않습니다.
공식 저장 자료는 확보 시점 기준이며 최신 개정을 반영하지 않습니다. 실제 조회 자료도
캐시에서 재사용되면 원래 조회 시각을 읽습니다. 모의 규칙+mock/저장 자료는 외부 호출이
없지만 Gemini 질문 해석을 선택하면 질문이 모델에 전송됩니다. 일반 응답 예시는 항상
고정 모의 문장입니다. 검토 4/4는 실습 확인 상태이며 사실 검증 완료나 기사 사용 승인이 아닙니다.

## 장애 시 중단·전환·재개

진행자는 참가자에게 반복 클릭을 멈추도록 안내하고 **발생 시각·자료 모드·자료원·단계·
문의용 요청 번호**를 받습니다. 요청 번호가 없는 연결 오류에는 없다고 기록합니다.
조건·출처가 다른 결과나 승인 전 결과가 보이면 전체 실습을 멈추고 기술 담당자가 조사합니다.

| 증상 | 조치와 재개 조건 |
|---|---|
| 화면이 안 열림·연결 실패 | URL·행사장 네트워크·서비스 상태 확인. snapshot도 접근 불가하면 설명 자료로 전환. 같은 행사 환경에서 입장과 승인 흐름 확인 후 재개 |
| 접근 오류 401 | 공유 코드를 비공개 경로로 다시 확인하고 재입장. 결과·검토는 초기화되므로 조건부터 다시 확인. 여러 명에게 반복되면 기술 담당자에게 전달 |
| 접근 설정 오류 503 | 기술 담당자가 환경·Secret 버전·런타임 읽기 권한 점검. 참가자 코드 재입력을 반복하지 않음. 정상 입장과 코드 없는 접근 차단 확인 후 재개 |
| Gemini 해석 오류 | 오류·문의 번호 기록 후 **모의 규칙**을 명시적으로 선택하고 재분석. 조건 확인·수정·승인은 다시 진행. 모델 복구로 설명하지 않음 |
| 실제 자료 비활성·설정/인증 오류 | 설정·키 접근 문제를 기술 담당자가 확인. 진행 중 즉석 live 활성화 대신 검증된 저장 자료 모드로 명시적 전환하거나 해당 실습 중단 |
| 요청 제한 429 | 화면의 대기 안내를 따르고 자동/전체 반복 조회 금지. 한 번의 재승인도 참가자가 선택. 반복되면 저장 자료 전환 또는 중단 |
| 실제 자료 시간 초과·서비스 오류 | 아래 저장 자료 전환 절차 사용. 실제 공급자 복구는 기술 담당자의 별도 최소 확인 후 선언 |
| 모호성·지원 범위 오류 422 | 한국어 안내에 따라 참가자가 조건을 수정하고 재승인. 운영자가 연령·기간·지표를 몰래 대체하지 않음 |
| 저장 자료 버전 변경 409 | 질문을 다시 분석하고 새 출처·시각·범위를 읽은 뒤 재승인. 이전 버전으로 강행하지 않음 |
| 저장 파일 없음·손상·비활성 503 | 해당 실습 중단. 검증된 파일/설정을 복구하고 계획·승인 흐름 확인 후 재개. mock 수치를 공식 자료로 대신 표시하지 않음 |
| 예상 밖 500·승인 조건/출처 불일치·검토 초기화 실패 | 결과 사용과 해당 실습을 중단하고 요청 ID로 조사. 검증된 리비전 복구 또는 수정 후 승인·출처·검토 흐름 재확인 |

**저장 자료로 이어가는 순서**

1. 계획을 받기 전에 실패했다면 조회 자료를 **공식 저장 자료 · 확보 시점 기준**으로
   바꾸고 질문을 다시 분석합니다. 기존 승인 조건이 없는 단계입니다.
2. 조건 승인 후 실제 조회가 실패했다면 **저장 자료로 조건 다시 확인**을 누릅니다.
   수정 조건·이전 오류·문의 번호가 남는지 확인합니다. 이 버튼 자체는 조회 승인이 아닙니다.
3. 확보 시각·자료원·범위·단위를 다시 읽고 **이 조건으로 조회**를 눌러야 결과가 나옵니다.
   최종 조건이 승인 조건과 같고, 저장 자료 표시와 검토 0/4가 있는지 확인합니다.
4. 저장 자료 준비 자체가 실패하면 중단합니다. 복구 후 질문을 다시 분석하고 편집 조건을
   다시 입력·확인해야 합니다. 서버는 참가자의 조건·검토 이력을 복원하지 않습니다.

진행자 안내: “실제 조회는 실패했습니다. 지금부터는 미리 확보한 공식 자료를 사용합니다.
저장 시점과 범위를 확인하고 다시 승인해 주세요. 최신 자료나 기사 사용 승인을 뜻하지 않습니다.”
자세한 재현 순서는 [장애 리허설](FALLBACK_REHEARSAL.md)을 따릅니다. 자동 재시도·자동 전환은 없습니다.

## 기술 담당자의 조사와 복구

Cloud Logging에서 대상 프로젝트와 발생 시각을 선택한 뒤 아래 필터의 서비스명·요청 ID를
대입합니다. 키·코드·질문·인증 헤더·원문 네트워크 로그를 오류 기록에 붙이지 않습니다.

```text
resource.type="cloud_run_revision"
resource.labels.service_name="SERVICE_NAME"
jsonPayload.event="http_request"
jsonPayload.request_id="REQUEST_UUID"
```

`status_code`, `error_code`, `duration_ms`를 확인합니다. `outcome=completed`만으로 성공이라
판단하지 않습니다. 앱 로그는 허용 필드만 기록하지만 플랫폼 요청 로그의 URL/IP/사용자
에이전트 등은 별도 관리 대상입니다. [로그 계약](REQUEST_LOGGING.md)을 따릅니다.

배포 문제이면 [배포 절차](STAGE_DEPLOYMENT.md)에 따라 같은 프로젝트의 검증된 이전
리비전으로 트래픽을 되돌리고 입장·승인·저장 자료·검토 흐름을 다시 확인합니다.
롤백에 필요한 이미지와 해당 리비전의 고정 Secret 버전을 먼저 폐기하지 않습니다.
새 인스턴스의 메모리 캐시는 비어 있으며 참가자 결과·검토를 서버에서 복원하지 않습니다.
복구 확인 시각과 주최 측 재개 결정을 점검표에 남깁니다.

## 종료와 공개 접근 중단

1. 진행자는 참가자에게 **실습 나가기**를 안내합니다. 현재 탭의 코드·질문·결과·검토가
   초기화됩니다. 나가기는 서버를 닫거나 다른 참가자의 접근을 막는 기능이 아닙니다.
2. 기술 담당자는 주최 측이 정한 종료 후 공개 범위를 적용합니다. 앱에는 전체 종료 버튼이나
   코드 만료 기능이 없습니다. 공개 접근을 닫으려면 Cloud Run의 **Invoker IAM 검사 활성화**와
   **`allUsers`의 `roles/run.invoker` 제거**를 모두 확인합니다. 현재 개인 stage는 후자의
   바인딩으로 공개되어 있습니다. 콘솔에서 서비스 보안을 인증 필요/IAM으로 변경할 때도
   변경 내역을 확인합니다. 이 절차는 실제 대상 확인 후 담당자가 수행합니다.
3. 변경 후 Google 인증·접근코드를 보내지 않는 새 요청으로 기존 배포 URL이 플랫폼에서
   거절되는지 확인합니다(일반적으로 403). 남아 있는 다른 서비스 URL·리비전 태그 URL도
   확인합니다. IAM 권한자의 접근은 별개이며, 이미 브라우저에 표시된 결과가 원격 삭제되지는
   않습니다. [Cloud Run 공개 접근 설정](https://docs.cloud.google.com/run/docs/authenticating/public)을 따릅니다.
4. 접근코드 유출이 의심되면 공개 접근부터 닫고 코드를 교체한 새 리비전을 검증한 뒤
   재공개 여부를 결정합니다. Secret 비활성화만으로 실행 중인 인스턴스가 즉시 멈춘다고
   가정하지 않습니다. 환경변수 Secret은 인스턴스 시작 때 읽으므로 새 버전 주입·배포와
   이전 리비전 접근 차단을 함께 확인합니다. 값은 출력하지 않습니다.
   [Cloud Run Secret 동작](https://docs.cloud.google.com/run/docs/configuring/services/secrets)에 근거한 운영 절차입니다.
5. 종료 시각·접근 차단 확인·남겨 둘 자원·로그 보관 기한·Secret/자원 정리 담당자와 일정을
   기록합니다. 서비스·이미지·빌드 소스 버킷·Secret·로그·IAM·비용 알림을 목록화하고,
   기관 이전과 롤백 필요성을 확인한 뒤 정리합니다. 종료 안내 자체가 자원 삭제는 아닙니다.

현재 설정한 월 1만원 비용 알림은 자동 지출 차단이 아닙니다. 최소 인스턴스 0이나 공개
접근 차단만으로 비용이 0원이 되는 것도 아닙니다. 이미지·Secret·로그 등 남은 자원과
실제 청구 내역을 담당자가 확인합니다. [비용 알림의 한계](https://docs.cloud.google.com/billing/docs/how-to/budgets)를 참고합니다.
