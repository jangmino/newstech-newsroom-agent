# 2부: 자유 질문에서 근거 기반 브리핑까지

결정: [ADR 0017](decisions/0017-two-part-research-workshop.md). 기존 안내형 실습은 1부로 보존한다.

## 참가자 흐름

1. 상단에서 **2부 · 자유 질문과 AI 브리핑**을 선택한다.
2. 모의 자료로 연습하거나 **공식 실제 자료**와 **Gemini**를 선택한다.
3. “SK하이닉스 최근 실적이 좋아졌는지 숫자로 확인하고 싶어” 같은 질문을 입력한다.
4. 자료원 선택 이유, 회사, 지표, 제공 기간에 기초한 제안을 읽는다. 질문에 없던 조건은
   제안으로 표시한다. 회사·지표·기간의 모호성은 한국어 안내로 확인한다.
5. “삼성전자로 바꾸고 최근 2년 매출만 봐줘”처럼 수정 요청을 보내거나 조건 폼을 고친다.
6. **이 조건으로 조회**를 누른 뒤 자료·코드 계산·브리핑을 확인한다.
7. 브리핑의 `[F1]` 같은 근거 번호로 원자료·계산 행을 찾아 출처와 시각을 확인한다.
8. 검토 항목을 확인한다. 완료 체크는 실습 표시이며 기사 사용 승인이 아니다.

질문·조건·작성 중인 수정 요청·모드 변경은 결과를 숨긴다. 재조회와 1부/2부 전환도 검토를
초기화한다. 늦은 응답이 이전 결과를 복원하지 않는다. 새로고침 시 내용은 사라지며 DB는 없다.

## 지원 범위

| 자료원 | 대상·지표 | 기간·기준 |
|---|---|---|
| OpenDART 실제 | 공식 회사 목록에서 식별한 상장회사 한 곳, 매출액·영업이익 | 확인된 12월 결산 사업보고서, 연속 2~5년, 연결·원화 |
| KOSIS 실제 | 15~29세 고용률, 전국/수도권/비수도권의 시도 비교 또는 개별 시도 | 검증된 `101 / DT_1DA7015S / T90 / 75`, 연간 2020~2024년 |
| 모의 자료 | 삼성전자·SK하이닉스·현대자동차의 가상 숫자, 지역의 가상 고용률 | 2020~2024년, 외부 자료 호출 없음 |

모의 회사 목록은 연습용이며 실제 기업 성과의 snapshot이 아니다. 실제 회사 검색은 이 세
회사로 제한하지 않는다. 보고서 존재가 선택한 연결 계정의 존재를 보증하지는 않는다.
표준 매출 계정 `ifrs-full_Revenue`/`ifrs_Revenue`, 영업이익 `dart_OperatingIncomeLoss`가
각각 하나인 경우만 사용한다. 누락·중복·다른 통화·잘못된 숫자는 전체 조회를 중단한다.
임의 계정명을 비슷한 표준 계정으로 대체하지 않는다.

기업의 연간 변화와 전체 기간의 변화는 코드로 계산한다. 영업손실은 음수로 유지한다.
증감률은 시작값이 양수일 때만 계산하며 0·음수이면 원자료와 계산 불가 이유를 표시한다.
고용률 변화량 단위는 `%p`, 상대 증감률은 `%`다. 지역별 비율을 평균내지 않는다.
Gemini는 제공된 계산값을 설명하며 새로운 계산이나 원인·정책 효과를 만들어 내지 않는다.

## 계획과 승인 경계

2부 계획에서는 OpenDART 회사 목록·사업보고서 목록을 확인할 수 있다. 이는 자료를 조회할
수 있는지 알아보는 메타데이터이며 재무 수치는 포함하지 않는다. KOSIS는 검증된 카탈로그로
조건을 제안한다. 숫자·계산 결과·브리핑은 계획 응답에 없다. 실행 요청의 엄격한 `approved=true`
검사 이후에만 수치 조회·캐시 사용·Gemini 브리핑을 수행한다.

모델이 알 수 없는 조건은 명시적 제안으로 채우거나 확인 질문으로 남긴다. 지원 범위를 벗어난
명시 조건은 자동 대체하지 않는다. 회사 후보가 여러 개이면 참가자가 회사를 선택하고 계획을
다시 확인한다. 제공 연도가 부족하면 승인하지 않고 기간을 수정하도록 안내한다.

## API 계약

`POST /api/v1/research/plan`

```json
{
  "question": "SK하이닉스 최근 실적이 좋아졌는지 확인하고 싶어",
  "mode": "live",
  "interpretation_method": "gemini"
}
```

자연어 수정은 같은 질문과 `previous_conditions`, `revision`을 보낸다. 응답은 `conditions`,
`selection_reason`, `proposals`, `clarification_questions`, `field_errors`, `companies`,
`available_years`, `available_entities`, `available_metrics`, `metadata_notice`, 해석 방식·모델·
자료 모드·요청 ID를 제공한다. 원자료·브리핑은 포함하지 않는다.

`conditions`는 `selected_source`, `entity`, `company_code`, `metrics[]`, `start_year`, `end_year`,
`comparison`, `statement_basis`, `age_range`, `frequency`다. 회사 코드는 모델 출력이 아니라
서버가 확인한 값이다. 사용자 수정 조건은 실행 서버에서 다시 검증한다.

`POST /api/v1/research/execute`는 `question`, `mode`, `approved: true`, `conditions`,
`briefing_method: scripted|gemini`를 받는다. 실행 응답은 승인 조건 전체와 원자료/계산
`facts`, 출처·표/보고서명·한계, 캐시 표시, `brief`를 반환한다. 각 근거에는 ID, 대상·지표·기간·
값·단위·계산식·출처 링크·조회 시각·정규화 상세가 있다.

브리핑은 `status: complete|failed`, `generation_method`, `model`, `content`, `error`,
`verification_status: review_required`다. `content`의 요약·관찰에는 `evidence_ids`를 붙인다.
Gemini 작성 실패 시 `content=null`과 한국어 오류를 반환하고 조회 근거는 보존한다.
작성 실패를 규칙 문장으로 몰래 대체하지 않는다. 재시도는 참가자의 별도 승인이다.
HTTP 오류는 기존 한국어 `detail`·요청 ID·접근코드 보호를 따른다.

기존 `/api/v1/plan`, `/api/v1/execute`, `/api/v1/analyze`는 기본 동작과 계약을 유지한다.
프론트엔드 타입은 `researchTypes.ts`에 함께 관리한다.

## Gemini 작성과 한계

Gemini는 승인 조건·정규화된 근거·결정론적 계산·주의사항만 받는다. 출력 문장의 수치는
`{{F1.value}}` 같은 근거 슬롯으로 지정하고 서버가 원래 값으로 바꾼다. 없는 근거 ID,
인용하지 않은 슬롯, 임의 숫자·URL·알 수 없는 슬롯은 거부한다. 근거의 실제 출처 링크는
서버가 만든 값만 표시한다. 문장의 의미·증감 방향·인과관계 전체가 자동 검증되는 것은 아니다.
모델 지시와 사람 검토를 함께 사용하며 생성 결과를 검증된 기사로 표시하지 않는다.

## 설정·호출량

- 기본 개발/테스트는 mock. Gemini 계획은 기존 `LIVE_API_ENABLED`와 `GEMINI_PLANNER_ENABLED`가 필요하다.
- Gemini 브리핑은 별도의 `GEMINI_BRIEFING_ENABLED=true`와 전역 live 허용이 필요하다.
- 실제 수치 조회는 기존 `PUBLIC_DATA_MODE=live`와 공급자별 활성화·백엔드 키가 필요하다.
- 모델 요청은 기존 Gemini 한도를 공유하며 계획·수정마다 1회, 승인 브리핑마다 1회다.
- OpenDART는 회사 목록 최초 1회·회사별 보고서 목록 1회·승인 후 연도당 1회(최대 5회).
  메타데이터는 프로세스에 24시간, 정규화 수치는 기존 캐시 TTL로 보관한다.
- KOSIS는 승인 후 1회. 캐시 재사용은 원래 조회 시각을 보존하고 재승인한다.
- 모든 모델·공공자료 요청은 제한·타임아웃을 적용한다. 자동 재시도·임의 도구 호출은 없다.
- 30명 live 사용은 기존 1부 부하 결과로 보증하지 않는다. 질문 계획+브리핑의 모델 호출량을
  반영해 후속 부하 확인을 해야 한다.

## 제외 범위와 검증

여러 회사 비교, OpenDART와 KOSIS 결합, 모든 통계표 검색, 다른 연령·통계 주제, 분기·월간,
별도 재무제표, 사용자 계정·DB·기사 작성/발행은 제외한다. 공식 저장 자료 fallback은 1부의
기존 검증 질문 범위로만 제공한다. 다른 기업의 결과를 삼성전자 snapshot으로 대체하지 않는다.

자동 검증은 `test_research.py`, `ResearchWorkshop.test.tsx`에서 공급자 모의 전송과 가상
응답으로 실행한다. 실제 자격증명·환경 파일·외부 네트워크는 사용하지 않는다. 전체 완료 시
`make check`, `git diff --check`와 비밀정보 Git 포함 여부를 확인한다. 소규모 실제 확인과
개인 stage 배포 결과·오류·재승인은 [확인 기록](RESEARCH_VALIDATION.md)에 있다.
코드 구현이나 소수 성공 사례를 모든 질문의 모델 품질 검증으로 표현하지 않는다.
