# ADR 0010: 공공자료 HTTP 호출의 프로세스 내 제한

- 상태: 구현 완료
- 날짜: 2026-09-16
- 관련: ADR 0009, M3 운영 안전장치

## 결정

OpenDART와 KOSIS의 실제 HTTP 요청 시작 직전에 자료원별 제한을 적용한다.
`PUBLIC_DATA_REQUESTS_PER_MINUTE=30`은 최근 60초 동안의 요청 시작 횟수,
`PUBLIC_DATA_MAX_CONCURRENT_REQUESTS=2`는 응답을 읽고 닫을 때까지의 동시 요청 수다.
두 설정을 자료원마다 독립적으로 적용한다. 제공기관의 공식 한도가 아니라 앱의 보호 기본값이다.
Gemini의 기존 한도와 분리한다.

- 캐시 적중과 동일 조회를 기다리는 참가자는 추가 한도를 쓰지 않는다.
- OpenDART 두 연도 조회는 각각 1회다. 두 번째 요청이 거절되면 부분 결과를 저장하거나 표시하지 않는다.
- 실패·시간 초과·취소도 이미 시작한 요청 횟수에는 포함한다. 동시 실행 자리는 항상 반환한다.
- 거절은 횟수를 소비하지 않는다. 대기열, 자동 재시도, 자동 자료 대체를 추가하지 않는다.
- 승인과 조건 검증을 통과한 실제 조회만 제한한다. mock, 질문 해석, `/health`는 영향을 받지 않는다.

## 계약과 범위

한도 초과는 HTTP 429와 `public_data_rate_limited`, 동시 실행 초과는 HTTP 429와
`public_data_busy`를 반환한다. 한국어 메시지와 `source`, `scope=process`,
`retry_after_seconds`를 제공한다. 횟수 제한에만 예상 대기 초와 `Retry-After`를 넣는다.
응답에는 `Cache-Control: no-store`를 지정한다. 참가자는 조건을 유지한 채 직접 재승인한다.

단일 프로세스의 메모리와 단조 시계를 사용하며 재시작 시 초기화한다. 여러 worker/Cloud Run 인스턴스,
프로젝트 전체, 개인별 또는 일일 총량을 통제하지 않는다. 인증·DB·분산 제한은 이 결정에 포함하지 않는다.
행사 배포 전에 기관 소유 키의 실제 할당량, 인스턴스 수와 행사 부하를 함께 확인해야 한다.
