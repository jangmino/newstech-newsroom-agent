# ADR 0015: 개인 GCP의 임시 stage와 기관 환경 재배포

- 상태: 개인 임시 stage 배포 완료, 기관 전환 대기
- 날짜: 2026-09-16

## 결정

사용자는 기관 GCP 계정을 받기 전 개인 계정으로 임시 stage를 만들고 나중에 교체하도록
요청했다. 기관 소유만 허용하던 기존 규칙에 이 임시 개발·배포 검증 환경의 예외를 둔다.
행사 환경은 계속 기관·주최 측 소유 자원과 자격증명을 사용한다.

- 기존 업무 프로젝트를 자동 선택하지 않는다. 사용자가 지정한 개인 계정과 전용 프로젝트를
  명시하고, 결제 계정과 비용 알림 금액은 사용자에게 확인한다. 기존 CLI 기본 프로젝트는
  바꾸지 않으며 명령마다 계정·프로젝트·리전을 전달한다.
- React 정적 파일과 FastAPI의 단일 Cloud Run 이미지 구조를 유지한다. 서울 리전,
  요청 기반 과금, 최소 0·리비전 최대 1 인스턴스, 1 vCPU·512 MiB·동시 요청 8로 시작한다.
  이는 30명 부하 검증 결과나 엄격한 비용 상한·분산 호출 한도를 뜻하지 않는다.
- 첫 stage는 `APP_ENV=stage`, live 공급자 모두 비활성화, mock·공식 저장 자료로 검증한다.
  접근코드는 Secret Manager의 고정 버전으로 주입한다. 로컬 공급자 키를 자동 복사하지 않는다.
- 런타임과 빌드 서비스 계정을 분리한다. 런타임에는 필요한 개별 Secret의 읽기 권한만,
  빌드에는 전용 이미지 저장소 쓰기·로그 쓰기·소스 버킷 읽기를 부여한다. 서비스 계정 키
  JSON을 생성하지 않는다. 빌드 중에는 Secret 값을 전달하지 않는다.
- `.env`, 키, 로컬 설정, 캐시와 Git 이력은 업로드·Docker 빌드 입력에서 제외한다.
  명시적으로 허용한 빌드 파일만 업로드한다. 개인 계정/프로젝트 식별자는 로컬 설정으로 분리한다.
- 배포는 기본 IAM 비공개로 준비한다. 브라우저에서 공유 코드로 접근할 공개 URL은
  사용자가 이 공개 범위를 선택한 경우에만 연다. 개인 정보·실제 취재 자료는 사용하지 않는다.
- 기관 환경은 프로젝트 소유권 이전에 의존하지 않고 같은 코드와 배포 설정으로 새로 만든다.
  기관 결제·IAM·Secret을 주입하고 새 URL의 승인·검토·장애 흐름을 검증한 뒤 전환한다.
  개인 Secret 값을 기관으로 복사하지 않으며 개인 자원 폐기는 목록 확인 후 진행한다.

## 비용과 검증

Cloud Run 외 Cloud Build·Artifact Registry·Secret Manager·로그/네트워크 비용도 발생할 수
있다. 예산 알림은 자동 차단이 아니다. 임시 환경의 비용·권한·공개 범위를 구체화해 확인한다.
자동 테스트는 계속 오프라인으로 수행한다. 클라우드 접속·이미지 빌드·배포 후 smoke 확인은
수동 운영 검증으로 구분한다. 기관 전환·30명 부하 시험·행사 리허설은 후속 범위다.

2026-09-17 사용자가 개인 결제 연결·월 1만원 비용 알림·공개 URL과 접근코드 구성을 승인했다.
Cloud Build·Secret Manager·Cloud Run의 생성·배포·mock/snapshot 확인을 완료했다.
[실제 확인 기록](../STAGE_SMOKE_TEST.md)을 참고한다.
