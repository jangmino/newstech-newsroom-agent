# ADR 0019 — 행사 요청 대기와 진행 상태

- 결정일: 2026-09-30
- 상태: 공개 반영 완료, 혼합 조건 재시험 통과·간헐 연결 장애 근본 원인은 미확정
- 근거: 사용자가 30명 동시 요청 보강 계획과 후보 배포·실제 부하 검증을 승인함.

단일 Cloud Run 프로세스 안에서 행사 요청 최대 40개를 접수한다. 공급자별 FIFO 대기와
기존 호출량·동시 실행 제한을 함께 적용한다. 대기 누적 120초, 요청 전체 180초를 상한으로
하며 무한 대기·무제한 재시도를 하지 않는다. 기존 JSON 계약은 유지하고 행사 화면에는
POST 스트림 계약을 추가한다. 진행 상태·결과·오류를 전송하며 자동 재접속은 하지 않는다.

대기 중 취소는 외부 호출을 시작하지 않는다. 이미 전송한 Gemini 호출은 과금 취소를
보장하지 않고 실행 자리를 실제 종료까지 유지한다. 공공자료 공유 조회는 남은 승인
요청이 있으면 유지하고 마지막 대기자가 떠나면 취소한다. 재승인·질문 변경 시 검토와
이전 응답을 무효화한다. DB·인증·멀티에이전트·영속 작업 큐는 추가하지 않는다.

공급자가 명시한 짧은 Retry-After가 있는 HTTP 429만 최대 1회 재시도한다. 결제·키·권한,
모델 출력 오류, 일일 한도, 응답 수신 여부가 불명확한 타임아웃은 자동 재시도하지 않는다.
402는 결제 오류로 별도 안내한다. 원문·키·질문을 진단 로그에 남기지 않는다.

Cloud Run 후보는 동시 HTTP 80, 요청 제한 210초, 1 CPU/512 MiB/최대 인스턴스 1을
사용한다. 외부 호출 동시 수와 HTTP 동시 수는 다르다. 행사 시간 최소 인스턴스 1 운영과
종료 후 0 복귀 명령을 제공하며 상시 과금 설정으로 바꾸지 않는다. 여러 인스턴스로의
확장은 전역 한도 공유 설계가 필요하므로 이 결정에 포함하지 않는다.

실제 호출 검증은 5→15→30명, 동일 조건과 서로 다른 조건을 구분한다. 초기 예산은
Gemini 계획·브리핑·일반 응답 최대 300회와 명시적 429 재시도 최대 300회다. 실제 소비는
단계별로 기록하며 실패 시 확대를 멈춘다. 95%가 120초 이내 완료하는 것을 목표로 하고,
자료 제공 실패·모델 품질 실패·혼잡 실패는 별도로 집계한다. 자동 테스트는 모의 전송만
사용한다. 한도·대기·취소·상태 격리·접근 보호·비밀정보 비노출을 검사한다.

## 2026-09-30 공개 반영 예외 승인

기존 공개 버전에도 재현되는 KOSIS 연결 장애로 혼합 조건 운영 시험은 미통과다.
사용자는 이를 인지하고 대기·취소 보강을 먼저 공개한 뒤 연결 조사를 계속하도록 승인했다.
이 반영을 KOSIS 장애 해소나 전체 행사 운영 합격으로 간주하지 않는다.

후속 진단 후보에서 동일 혼합 30개 조건을 재시험해 계획·조회·브리핑·일반 응답을
모두 확인한 뒤 `queuee`로 최종 전환했다. 원인은 확정하지 못했으므로 안전한 단계
진단과 행사 직전 새 조건 확인을 유지한다. 초기 실패 기록도 EVENT_VALIDATION.md에 보존한다.
