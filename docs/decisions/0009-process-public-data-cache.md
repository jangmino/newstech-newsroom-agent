# ADR 0009: 승인 후 공공자료의 프로세스 내부 캐시

- 상태: 구현 완료
- 날짜: 2026-09-16

M3의 첫 단위로 같은 공식 원자료의 반복 조회와 동시 중복 호출을 줄입니다.
DB·파일 저장·인증·배포 구조 변경은 없습니다. 메모리 공유의 범위와 수명을 명시합니다.

- OpenDART의 정규화된 두 연도 자료 한 쌍, KOSIS의 정규화된 연간 자료 묶음만 저장합니다.
  원래 조회 시각·공표 문자열·출처·수정일은 그대로 보존합니다. 질문·승인·브리핑·검토 상태,
  인증키·인증 URL·공급자 원문 응답은 캐시 키나 값에 넣지 않습니다.
- 요청마다 승인·조건·자료원·서버 활성화·키 유무를 먼저 검사합니다. `/plan`·mock·
  `/analyze`는 캐시를 사용하지 않습니다. 캐시가 있어도 비활성 공급자를 우회하지 못합니다.
- 키는 공급자 계약 버전과 검증된 공개 조회 조건으로 만듭니다. 비교 기준은 원자료 선택을
  바꾸지 않으므로 제외하고, 승인마다 증감 폭/률·브리핑·요청 ID를 새로 만듭니다.
- `PUBLIC_DATA_CACHE_ENABLED=true`, 기존 `CACHE_TTL_SECONDS=3600`,
  `CACHE_MAX_ENTRIES=64`를 기본값으로 사용합니다. 외부 live 활성화 기본값은 그대로 false입니다.
  공급자별 완료 자료를 최대 64건 보관하고 최근 사용 순으로 제거합니다. 사용해도 만료를 연장하지 않습니다.
- TTL은 전체 조회·정규화 성공 시점부터 monotonic clock으로 판단합니다. 실패·부분 결과는
  저장하지 않으며 만료 후 재조회 실패 시 오래된 자료나 snapshot으로 대체하지 않습니다.
- 같은 키의 진행 중 요청은 하나의 작업을 공유합니다. 한 참가자의 요청 취소가 다른
  참가자의 조회를 취소하지 않습니다. 모두 취소해도 이미 시작한 조회는 기존 공급자 시간
  제한 안에서 마칠 수 있습니다. 서버 종료 시 진행 작업을 취소·회수하고 메모리를 비웁니다.
- `/execute`에만 nullable `cache` 메타데이터를 추가합니다. `miss|hit|coalesced`,
  저장·만료 시각, TTL·경과 초, `scope=process`를 반환합니다. mock/캐시 비활성은 null입니다.
  기존 `evidence.retrieved_at`과 연도별 조회 시각을 이번 승인 시각으로 덮어쓰지 않습니다.
- 참가자 화면의 브리핑·근거·조건 비교에 자료 재사용 여부와 시각을 표시합니다. 재사용한
  자료도 조건 승인 뒤에만 표시하며 검토 체크는 0/4로 시작합니다. 기사 사용 승인이 아닙니다.

프로세스 재시작 시 비워지며 Cloud Run의 여러 인스턴스/워커 사이에서는 공유하지 않습니다.
이 캐시는 행사 전체 호출 한도나 부하 시험을 대신하지 않습니다. 호출·동시 실행 제한,
명시적 snapshot fallback·접근코드·Secret Manager·배포는 다음 단위입니다.
이번 검증은 가짜 시계·모의 HTTP 전송과 화면 동작 테스트로 수행하며 실제 외부 호출은 없습니다.

계약·설정·검증 결과는 [공공자료 캐시 문서](../PUBLIC_DATA_CACHE.md)에 기록합니다.
