# ADR 0016: 개인 stage에서 세 공급자의 실제 연결 검증

- 상태: 개인 stage 실제 연결·배포 확인 완료, 행사 부하·인계는 후속 범위
- 날짜: 2026-09-17

## 결정

사용자는 Gemini 해석과 실제 OpenDART/KOSIS 조회를 함께 stage에서 검증하고, 기관 계정·
프로젝트 요청은 마지막 인계 단계로 미루도록 승인했다. ADR 0015의 개인 환경 예외를
live 검증까지 확대한다. 기관 제공 여부는 개발·live 시험의 선행 조건이 아니다.
기관 인계 시 소유자·결제·키·운영 책임을 다시 정하며 개인 키를 기관에 복사하지 않는다.
이번 승인은 개인 계정으로 실제 행사를 운영하거나 상시 서비스를 제공한다는 결정은 아니다.

- 기존 개인 stage 프로젝트·공개 URL+접근코드·서울·리소스·비용 알림을 유지한다.
- 기존 로컬 Gemini/OpenDART/KOSIS 개인 키를 같은 개인 프로젝트 Secret Manager에
  stdin으로 전달한다. 값은 출력·파일 복제·명령 인자·빌드 입력·Git에 넣지 않는다.
- 공급자마다 Secret을 분리하고 런타임에 해당 Secret 읽기 권한만 부여한다.
  숫자 버전으로 고정하며 빌드 계정에는 공급자 키 권한을 주지 않는다.
- 검증된 이미지 digest를 재사용하여 live 설정의 후보 리비전을 만든다. 기존 URL의
  트래픽은 확인 전까지 이전 리비전에 두고, 후보 확인 후 전환한다.
- Gemini API 키 인증과 기존 모델을 사용한다. Vertex나 새 데이터 공급자를 추가하지 않는다.
- 질문 해석과 자료 모드는 참가자가 명시적으로 선택한다. 조건 승인 전 실제 공공자료를
  조회하지 않으며 계산·검증·브리핑은 기존 결정론적 코드로 수행한다.
- 실패 시 자동 재시도·자동 mock 대체 없이 중단한다. 공식 저장 자료 전환은 참가자의
  선택·출처/시각 확인·별도 재승인이 필요하다. 모의 자료는 자동 테스트·오류 실습용으로 유지한다.

## 검증 범위와 복귀

기존 두 공개 예시 질문으로 해석·조건 수정·승인·실제 근거·검토·캐시 재사용을 확인한다.
수동 API 확인과 브라우저 확인, 필요한 수정 후 재확인을 합쳐 Gemini 최대 6회,
OpenDART HTTP 최대 8회, KOSIS HTTP 최대 4회로 제한한다. 캐시 성공 시 실제 공공자료
호출은 줄어든다. 자동 테스트는 계속 환경 파일과 외부 네트워크를 차단한다.

인증·계약·조건·메타데이터 검증 실패 시 원인을 확인하고 무작정 반복하지 않는다.
전체 연결 확인에 실패하면 이전 mock/저장 자료 리비전의 기본 트래픽을 유지한다.
전환 후 문제가 생기면 기록한 이전 리비전으로 복귀하고 후보 태그 접근도 정리한다.
키·모델 원문·공급자 원문은 보고서에 저장하지 않는다.

이는 소규모 통합 확인이며 30명 live 부하·장시간 운영·모델 품질 전반의 검증은 아니다.
두 질문의 후보 API 확인 19개 요청을 통과한 뒤 기존 URL의 트래픽을 전환했다.
실제 호출 수·검증 결과는 [확인 기록](../STAGE_LIVE_TEST.md)에 남긴다.
