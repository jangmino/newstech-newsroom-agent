# ADR 0013: 요청 ID와 허용 필드만 남기는 운영 로그

- 상태: 구현 완료
- 날짜: 2026-09-16

## 결정

M3에서 HTTP 요청마다 서버가 새 UUID를 생성하고 응답 헤더 `X-Request-ID`, 기존 성공
본문의 `request_id`, 완료 로그를 연결한다. 참가자 입력 헤더의 ID는 신뢰하거나 재사용하지
않는다. `/analyze`를 포함한 기존 성공/오류 본문의 필드는 유지한다.

- 로그는 stdout에 요청당 JSON 한 줄을 남긴다. 시각·심각도·고정 이벤트명·요청 ID·
  허용된 HTTP 메서드·고정 경로 분류·상태 코드·처리 시간·종료 상태·허용된 오류 코드만 기록한다.
  모르는 경로·메서드·오류 코드는 고정 분류로 치환한다.
- 질문/조건/응답 본문, 헤더, 접근코드, 키, URL 쿼리, IP, 사용자 에이전트,
  공급자 오류 원문·예외 메시지를 기록하지 않는다. Uvicorn 기본 access log는 끈다.
- 접근코드 거절, 요청 검증, 공급자 한도·장애, 저장 자료 오류도 같은 ID로 연결한다.
  응답 완료·관찰된 취소·전송 중단을 구분하며 취소를 성공으로 기록하지 않는다.
- 예상하지 못한 예외는 원문 없이 한국어 500 `internal_error`로 응답한다. 응답이 이미
  시작된 경우 기존 응답을 성공 500으로 교체할 수 없으므로 중단으로 기록하고 안전한
  고정 예외만 상위 서버에 전달한다. 생명주기/프로세스 시작 실패는 이 HTTP 경계 밖이다.
- 프론트엔드는 오류 응답 헤더의 UUID 형식을 검사한 뒤 ‘문의용 요청 번호’를 표시한다.
  서버 응답이 없는 네트워크 실패에는 번호를 만들지 않는다. 재시도·편집·나가기 시 이전
  오류 번호도 기존 오류와 함께 초기화한다. 입장 오류에도 동일하게 적용한다.
- ID는 개인·세션 식별자가 아니며 DB에 저장하지 않는다. 요청 ID별 로그 확인은 서버
  출력에서 수행하고 참가자에게 로그 조회 API·운영자 권한을 추가하지 않는다.

## 한계

외부 호출·추적 수집기·DB·새 배포 서비스·Cloud Logging 설정은 추가하지 않는다.
프록시/Cloud Run 플랫폼 로그의 보관·IAM·URL 처리 정책은 기관 stage 배포 때 별도로
검증한다. 공급자별 상세 span, 토큰/요금 집계, 분산 추적, 영구 통계·알림은 후속 범위다.
요청 시간은 이 ASGI 경계 안의 경과 시간이며 참가자 브라우저의 전체 대기 시간과 다르다.
