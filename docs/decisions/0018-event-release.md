# ADR 0018 — 10월 7일 행사 버전과 공식 제공 범위

- 상태: 승인됨, 구현·개인 stage 검증 완료; 현장 운영 확인 별도
- 결정일: 2026-09-18
- 근거: 사용자의 행사 버전 연속 구현 위임과 공식 제공 범위 확인 답변

## 결정

1부 안내형·2부 자유 질문에 동일한 행사 도구를 사용한다. 참가자 화면에서 가상 자료,
모의 해석, 고정 일반 응답 예시를 제거한다. 개발용 fixture와 기존 API는 회귀 검증용으로
유지한다. 실제 Gemini 해석 → 편집·승인 → 공식 조회 → 코드 계산 → 인용 브리핑 → 사람
검토를 따른다. 로딩 시 외부 API를 자동 호출하지 않는다.

질문 범위는 기업 공시 비교, 청년 고용 변화, 기업 재무 실적이다. 외부 API·계산은 서버만
실행하며 단일 오케스트레이터를 유지한다. DB·개인 인증·자동 기사 발행·자사 파일럿 작성·
임의 웹 검색·공시와 고용의 인과관계 결합은 추가하지 않는다.

### 공식 자료 계약

- OpenDART 상장회사 공식 목록으로 이름/코드를 확인한다. 재무는 한 회사, 매출액·영업이익·
  당기순이익, 연결/별도, 연간/분기, 당기/누적을 구분한다. 계정·통화·기간·보고서 버전이
  불명확하면 비교하지 않는다. 0/음수 기준 증감률을 만들지 않는다.
- 공시는 최대 두 회사, 최대 93일 접수 기간, 투자·지분·소송 분류를 사용한다. 목록 페이지
  누락, 정정/철회, 상세 미제공을 표시한다. 제목만으로 본문 사실을 만들지 않는다. 주요사항
  상세 API로 확인한 내용과 원문 확인이 필요한 목록을 구분한다. 접수일/종류의 정렬은
  뉴스 가치의 객관적 순위가 아니다.
- KOSIS 101/DT_1DA7015S: 시도 및 전국 공식 집계의 연간 고용률(T90).
- KOSIS 101/DT_1DA7031S: 시도 및 전국 공식 집계의 연간·월간 취업자 수(T30, 천명).
- KOSIS 101/DT_1DA7002S: 전국 공식 집계의 연간·월간 고용률(T90), 실업률(T80),
  취업자 수(T30). 지역 고용률을 평균하여 전국 값을 만들지 않는다.
- 연령은 각 표 메타데이터에서 직접 제공하는 15~29세, 20~29세, 15~64세로 제한한다.
  15~34세를 다른 연령으로 대체하지 않는다. 시도별 월간 고용률·시도별 청년 실업률은
  이 카탈로그에 없음을 안내한다. 사용자가 이 제공 범위를 명시적으로 승인했다.
- 2026-09-18 공식 ITM/PRD/CMMT 확인: 연간 최신 2025, 월간 최신 2026-08.
  검증 범위는 연간 2020~2025 중 최대 5년, 월간 2020-01~2026-08 중 최대 13개월.
  시도 경계 변경·통합 지역과 하위 지역의 중복 합산을 하지 않는다.

### 비교·실행 기록·사람 검토

실제 동일 Gemini 모델에 동일 질문과 승인 조건을 보내 일반 응답을 별도 요청한다.
공공자료 도구·웹 검색은 제공하지 않으며 프롬프트·모델·시각·도구 유무를 공개한다.
지식을 일부러 제한하거나 나쁜 응답을 강요하지 않는다. 이는 전체 챗봇 제품의 성능 평가가
아닌 도구 연결 유무의 실습이다. 무응답/추가 질문도 그대로 비교한다.

실행 기록은 실제 수행한 메타데이터 조회·자료 조회·캐시·계산·생성 상태만 포함한다.
숨은 사고 과정·키·전체 요청 URL은 노출하지 않는다. 참가자는 근거와 연결한 사실 두 개,
아직 뒷받침되지 않은 해석 한 개, 후속 질문 두 개, 데스크 확인 한 개를 기록한다.
검토 상태/이유·AI 원본·사람 수정·승인 조건·출처를 다운로드한다. 질문·조건·자료 변경 시
검토를 초기화한다. 실습 검토 완료는 기사 사용 승인이 아니다.

### 장애·운영

공식 저장 자료는 조건·조회 시각·원문·모델 생성 이력을 보존하고 참가자가 별도 선택하고
다시 승인한다. 실제 조회 실패를 몰래 저장 자료나 가상 자료로 바꾸지 않는다. Gemini
장애 때 사전 생성된 실제 출력은 정확히 일치하는 조건에서만 명시적으로 재생한다.

자동 테스트는 외부 호출을 금지한다. 실제 대조·개인 stage 검증은 예산을 정한 수동 검증으로
분리한다. 30명 검증도 모든 요청을 동시에 실제 API에 보내는 시험과 구분하고 승인·수정·
브리핑의 호출 수와 한도 응답을 기록한다. 물리적 행사장/Windows 확인은 실제 수행 전까지
미완료로 둔다. 기관 이전은 마지막 인계 단계다.
