# ADR 0020 — 자유 질문의 확인 질답과 조건 승인

- 결정일: 2026-09-30
- 상태: 구현·자동 검사·개인 stage 공개 반영 완료, 현장 검증 별도
- 근거: 사용자가 자유 질문의 범위 판단·후속 질답·조건 승인 흐름을 승인하고 세부 구현을 위임함.

1부는 ‘예제로 흐름 익히기’, 2부는 ‘내 질문으로 조사하기’로 구분한다. 같은 도구와
승인 경계를 사용하며 2부만 브리핑을 제공하는 것으로 소개하지 않는다.

계획 상태를 ready, needs_clarification, unsupported로 구분한다. 자료원 미정이나
조사 방향·대상에 대한 중요한 모호성이 있으면 조건 폼 대신 한 번에 한 확인 질문,
선택 답변(최대 3개), 직접 답변 입력을 제공한다. 미정 상태에는 지표·기간 기본값을
생성하지 않는다. 지원 불가 조건도 몰래 대체하지 않고 한계와 가능한 별도 조사 방향을
설명한다. 명시되지 않은 단순 조건은 기존처럼 제안하고 최종 폼에서 확인받는다.

계획 요청에 conversation을 추가한다. 완료된 확인 질문과 답변을 최대 8회, 질문
500자·답변 1000자 이내로 전달한다. 현재 답변도 포함하며 latest revision과 편집 조건을
함께 전달한다. 모델은 이 모두를 신뢰할 수 없는 참가자 입력으로 처리하고 최신 답변을
우선한다. 서버·DB·브라우저 저장소에 대화를 저장하지 않는다. 원 질문·실습·자료 모드
변경 시 대화와 결과·검토를 초기화한다. 실패·취소는 답변과 마지막 성공 계획을 유지하고
성공하지 않은 답변을 대화 이력에 중복 추가하지 않는다. 상한 도달 시 명시적 다시 시작과
공식 저장 자료 이용을 안내한다. 자동 모델 반복 호출은 없다.

기존 event plan JSON/stream에 status와 clarification을 추가하고 기존 입력과 API를
유지한다. 프론트엔드도 같은 계약을 사용한다. 자료 조회는 조건 승인 후에만 수행하며
공식 회사 목록 조회 예외·결정론적 계산·원문 대조·사람 검토 경계를 유지한다.
기사 초안·자동 발행·임의 웹 검색·복수 자료 결합·새 공급자·DB·인증은 추가하지 않는다.

참가자 답변 1회당 Gemini 계획 호출 1회가 추가된다(명시적 429 재시도 별도).
기존 공급자 한도·요청 대기·취소를 그대로 적용한다. 30명 기본 90회에서 질답을
각 2회 하면 총 150회다. 모든 질문을 강제로 질답에 넣지 않는다.

## 완료 조건

아래 기능·검사·제한된 실제 연결 확인을 완료하고 공개 `dialogueb`에 반영했다.
[검증 기록](../DIALOGUE_VALIDATION.md)에는 후보의 KOSIS 연결 실패와 최종 성공을 구분한다.

- 삼성전자 재무 이슈가 미정이면 고용 지표·기간 폼 없이 관련 확인 질문을 표시한다.
- 두 차례 이상 질답에서 원 질문·답변·편집 조건을 보존하고 최종 조건에 반영한다.
- 명확한 재무·공시·고용 질문은 바로 폼으로 이동하고 승인 후에만 조회한다.
- 지원 불가·일부 가능·회사 후보·모델 오류·취소·늦은 응답·이력 상한을 검증한다.
- 공식 저장 자료 재생과 기존 API 회귀, make check, git diff --check, 비밀정보 검사를 통과한다.
- UI 브라우저 확인과 기존 개인 stage의 제한된 실제 계획 검증을 별도로 기록한다.
  실제 조회 데이터 계약은 바꾸지 않으며 현장 30명 검증이나 기사 사용 승인으로 표현하지 않는다.
