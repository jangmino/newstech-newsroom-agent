# ADR 0012: 계정 없는 행사용 공유 접근코드

- 상태: 구현 완료
- 날짜: 2026-09-16

## 결정

M3의 다음 단위로 행사 참가자에게 전달한 공유 코드로 백엔드 API 접근을 제한한다.
사용자의 진행 승인에 따라 인증 범위를 이 방식으로 한정한다. 계정·DB·개인별 권한·
세션 저장소·쿠키·JWT·새 공급자·배포는 추가하지 않는다.

- 기존 `WORKSHOP_ACCESS_CODE`를 사용한다. 영문 대소문자·숫자·`_`·`-` 16~128자이며
  운영자는 충분히 무작위인 코드를 생성한다. 코드는 대소문자를 구분하고 자동 보정하지 않는다.
- local/test에서 빈 코드일 때만 제한을 끈다. 그 외 환경에서는 빈 코드나 잘못된 설정을
  503으로 차단한다. local에서도 값이 있는데 형식이 잘못되면 차단한다.
- `GET /api/v1/access`는 공개이며 `{required, available}`만 알려 준다.
  `POST /api/v1/access`는 `X-Workshop-Code` 헤더를 확인하고 같은 상태를 반환한다.
  코드·힌트·토큰·세션을 응답하지 않는다.
- `/api` 전체와 OpenAPI 문서 경로는 요청 본문 검증·질문 해석·공급자·캐시 전에 검사한다.
  공개 GET 상태, `/health`, 정적 UI, 허용 출처의 CORS 사전 요청은 코드 없이 접근한다.
  `/plan`, `/execute`, 이전 `/analyze`의 본문·승인 계약은 유지한다.
- 코드가 필요할 때 헤더 누락·오류·중복은 같은 한국어 401을 반환한다. 코드 확인에는
  고정 길이 SHA-256 digest의 `secrets.compare_digest`를 사용한다. URL·본문·쿠키의 코드는
  인증 수단으로 받지 않는다. API 응답은 `no-store`, `Vary: X-Workshop-Code`를 적용한다.
- 프론트엔드는 시작 시 접근 상태를 확인하고, 필요한 경우 입력 화면을 표시한다.
  확인 전 질문 분석·자료 조회는 없다. 확인한 코드는 현재 탭 메모리에만 유지하며 보호된
  같은 출처 API 요청의 헤더로만 보낸다. 브라우저 저장소·URL·분석 로그에 저장하지 않는다.
- 나가기·새로고침은 코드·질문·계획·결과·비교·검토를 지운다. 요청 중 나가기도 취소와
  요청 버전 검사로 늦은 응답을 무시한다. 401 또는 접근 설정 오류 시 화면을 잠그며 재입장
  이후에도 이전 요청을 자동 재실행하지 않는다. 조건 승인은 별도로 필요하다.

## 운영과 한계

공유 코드는 개인 식별·역할 분리·사용자별 사용량 제한이 아니다. 코드를 아는 사람은
동일한 권한을 가지므로 공개 저장소·URL·스크린샷·로그로 전달하지 않는다. HTTPS를 사용하고
행사별로 교체한다. 로컬 값은 `.env`, stage/event 값은 기관 Secret Manager에서 주입한다.
값 변경은 프로세스 재시작/새 배포가 필요하며 기존 요청을 소급 취소하지 않는다.
분산 무차별 시도 방어·운영자 전용 권한·접근 로그/운영 화면은 후속 범위다.
기존 공급자 호출 제한은 승인된 실제 외부 호출에 계속 적용한다.

자동 테스트와 로컬 UI 검증은 가상 코드와 mock/snapshot만 사용한다. 실제 코드 생성·
`.env` 변경·기관 리소스 설정은 이번 구현에 필요하지 않다.
