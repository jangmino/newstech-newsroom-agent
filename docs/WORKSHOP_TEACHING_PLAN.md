## 실습 목적과 인사이트

공식 자료를 확인할 수 있는 질문으로 구체화하고, 승인된 조건에 따라 조회·계산한 근거를
바탕으로 AI 브리핑을 작성한 뒤 사람이 검토한다. 웹앱은 이미 구현된 도구를 사용하며,
참가자가 코딩하거나 API 키를 발급받는 실습은 아니다.

핵심 메시지: AI가 답을 썼다는 데서 끝내지 않고, 어떤 조건과 자료로 그 답이 만들어졌으며
사람이 무엇을 더 확인해야 하는지 설명할 수 있어야 한다.

- 질문의 ‘최근’, ‘청년’, ‘실적 악화’는 기간·연령·지표·비교 기준으로 구체화해야 한다.
- 유창한 답변과 근거를 추적할 수 있는 답변은 각각 평가해야 한다.
- 공식 자료라도 단위·기간·회계 기준이 다르면 해석이 달라진다.
- 수치의 변화는 후속 취재의 단서이며 원인이나 기사 가치를 자동으로 입증하지 않는다.
- 자료 부족이나 지원 불가를 설명하고 멈추는 것도 올바른 결과다.
- 사람의 승인·원문 대조·수정·후속 질문이 뉴스룸 업무 흐름에 포함되어야 한다.

## 실습 1 진행안

같은 청년 고용 질문을 함께 따라가며 조건과 근거를 확인한다. 회계 용어를 먼저 설명할
필요가 없고 연령·기간·고용률과 취업자 수의 차이로 조건의 중요성을 보여주기 쉽다.

예시 질문: 서울의 청년 고용률은 최근 5년간 전국 집계와 비교해 어떻게 달라졌을까?
실제 조회 가능 기간을 화면에서 확인한다. 현재 검증된 연간 사례는 2021~2025년이다.

| 소요 | 활동 |
|---|---|
| 10분 | 질문 입력, Gemini가 제안한 자료원·조건 확인 |
| 15분 | 조건 승인, 근거·공식 원문·단위·계산식 확인 |
| 10분 | 동일 질문·조건의 일반 AI 응답과 근거 브리핑 비교 |
| 15분 | 조건 하나를 바꿔 재조회하고 결과 차이 설명 |
| 10분 | 확인한 사실과 미확인 해석 기록, 짝과 공유 |

## 실습 2 진행안

기업 재무, 투자·지분·소송 공시, 청년 고용 중 관심 주제를 선택한다. 자유 질문은
현재 지원 자료 범위 안에서 진행한다. 1·2부는 같은 도구를 사용하며 참가자가 스스로
판단하는 범위에 차이를 둔다. 서로 다른 기술을 사용하는 실습으로 설명하지 않는다.

화면 이름은 ‘1부 · 예제로 흐름 익히기’, ‘2부 · 내 질문으로 조사하기’다.
2부는 빈 질문 입력란에서 시작한다. ‘삼성전자의 최근 재무 이슈?’처럼 모호한 질문은
실적 변화인지 관련 공시인지 먼저 확인하고, 선택지 또는 직접 답변으로 방향을 정한다.
자료원이 정해지기 전에는 지표·기간 폼을 보여주지 않는다. 필요한 질답 후 제안 조건을
검토·승인해야 자료와 브리핑이 나타난다. 명확한 질문은 바로 조건 폼으로 이어진다.
지원 불가 범위는 가능한 별도 조사 방향을 참가자가 선택하며 임의로 대체하지 않는다.
질답 답변마다 Gemini 호출 1회가 추가되고 기존 대기 안내가 적용된다. 한 질문에서
확인 답변·자연어 수정은 최대 8회이며, 원 질문·실습·자료 모드 변경 시 이력은 초기화된다.
기사 초안 작성은 포함하지 않으며 브리핑·원문 대조·사람의 수정과 검토까지 진행한다.

예시: 현대자동차의 실적 악화 여부, NAVER·카카오의 공시 비교, 시도별 청년 고용 변화.
세 사례를 모두 수행하도록 요구하지 않고 하나를 선택해 깊이 검토한다.

| 소요 | 활동 |
|---|---|
| 5분 | 주제 선택과 취재 질문 작성 |
| 10분 | 확인 질답으로 범위 구체화, 조사 계획 수정, 조건 승인 |
| 15분 | 자료 조회·브리핑 확인, 필요한 조건 재검토 |
| 15분 | 원문 대조, AI 문장 수정, 사람 검토 기록 |
| 10분 | 2~3개 사례 공유: 무엇을 확인했고 무엇이 남았는가 |
| 5분 | 산출물 다운로드와 정리 |

최종 산출물은 근거가 연결된 사실 2개, 미확인 해석 1개, 후속 취재 질문 2개,
데스크 확인 사항 1개, 검토 상태·이유, 수정한 브리핑이다. 다운로드 형식은 JSON이다.
실습 완료는 기사 사용 승인이 아니다. 자사 파일럿 작성은 포함하지 않는다.

## PPTX 제작 구성

본편 약 25장과 기술·운영 부록으로 구성한다. 슬라이드는 설명 자료이자 실습 중
길잡이이며, 화면의 버튼 이름과 진행 순서를 그대로 사용한다.
실제 웹앱 화면을 이용하고 임의의 성공 결과를 만들어 넣지 않는다.

| 슬라이드 | 내용 | 핵심 |
|---|---|---|
| 1~3 | 목적·오늘 할 일·산출물 | 무엇을 만들고 어디까지 확인할 것인가 |
| 4~5 | 전체 시연·에이전트 구성도 | 질문→계획→사람 승인→조회·계산→브리핑→사람 검토 |
| 6~7 | OpenDART·KOSIS 개요·지원 범위 | 어느 질문을 어떤 자료로 확인할 수 있는가 |
| 8~10 | 질문·Gemini 계획·조건 수정과 승인 | 모호한 표현을 구체적인 조건으로 바꾸기 |
| 11~12 | 원자료·단위·계산식·원문 | 공식 출처가 있어도 조건과 해석 확인하기 |
| 13~14 | 일반 응답·조건 변경 전후 비교 | 유창함과 검증 가능성 구분하기 |
| 15 | 실습 1 정리 | 같은 질문도 조건에 따라 답이 달라진다 |
| 16~18 | 실습 2 과제·주제·자연어 수정 | 확인 질문에 답하며 조사 범위 판단하기 |
| 19~21 | 브리핑 검토·사실과 해석·문장 수정 | AI 초안을 검토하기 |
| 22~23 | 사람 검토·다운로드·사례 공유 | 확인한 것과 남은 질문 설명하기 |
| 24~25 | 실패·자료 부족·마무리 | 멈추거나 추가 확인하는 것도 올바른 결과다 |

### 구성도에서 구분할 역할

- 프론트엔드: 질문 입력, 조건 확인·수정·승인, 근거·브리핑·검토 표시.
- 백엔드: 단일 오케스트레이터, 조건 검증, 공식 API 호출, 단위 정규화,
  증감·순위 계산, 모델 출력 검증, 캐시와 공식 저장 자료 처리.
- Gemini: 지원 범위 안에서 질문 해석·자료원과 조건 제안·자연어 수정·근거 브리핑 작성.
  비교용 일반 응답은 별도 호출이다. 숫자의 최종 계산은 프로그램이 수행한다.
- 사람: 조건 승인, 원문·해석 확인, 브리핑 수정, 추가 취재 판단.

### 설명 시 지킬 범위

일반 응답 비교는 같은 Gemini에 공식 조회 결과와 웹 도구를 제공하지 않은 응답과의
비교다. ChatGPT 등 특정 제품 전체의 성능 비교로 설명하지 않는다.

시도별 월간 고용률, 15~34세 등 지원하지 않는 조합은 다른 지표나 연령으로 임의
대체하지 않는다. 공시 본문 일부 확인, 누락 자료, 실패도 화면에 표시된 범위대로 설명한다.
공시와 고용을 결합한 인과 분석이나 임의의 웹 검색을 지원한다고 소개하지 않는다.

공식 저장 자료는 실제 수집 자료와 당시 모델 출력의 재생이다. 최신 조회와 구분하며,
사례 선택 후 고정 조건을 다시 승인한다. 가상 mock은 참가자 화면에 없다.

### 실습 운영과 부록

- 접속·접근코드·버튼 위치·대기 중 연타 방지·오류 문구 전달 방법.
- 질문·조건·실습 전환과 재조회 시 결과·검토 초기화, 브라우저 종료 전 다운로드 안내.
- 단계별 요청을 분산하고 오류 시 공식 저장 자료로 이어가는 진행자 안내.
- API의 의미와 제공 범위, %와 %p, 연결·별도, 당기·누적 등 참고 설명.
- 실제 참가자·행사장 네트워크·Windows 파일 저장은 행사 전 별도 확인.

### 요청이 몰릴 때 참가자에게 보이는 화면

Gemini·OpenDART·KOSIS 호출이 앱의 동시 호출·분당 호출 한도에 도달하면,
접수된 요청은 순서를 기다렸다가 자동으로 진행한다. 화면에는 공급자 이름과
접수 후 경과 시간·누적 대기 시간이 약 1초마다 갱신된다. 아래 숫자는 화면 설명용 예시다.

> **요청 순서를 기다리고 있습니다.**  
> Gemini · 접수 후 25초 · 대기 20초  
> 순서가 되면 자동으로 진행합니다. 다시 누르거나 새로고침하지 않아도 됩니다. 대기는 최대 240초, 전체 처리는 최대 300초입니다.
> **[요청 취소]**

실행 버튼은 처리 중 비활성화된다. ‘내 앞에 몇 명’이나 완료 예상 시간은 표시하지
않으며, 최대 시간은 완료를 보장하는 시간이 아니다. 한 번의 요청에서 여러 공급자를
기다리면 대기 시간이 누적된다. 질문 계획·승인 후 조회·일반 응답 비교는 각각의 요청이다.

| 상황 | 화면 안내와 처리 | 참가자에게 안내할 행동 |
|---|---|---|
| 앱의 공급자 호출 한도 도달 | ‘요청 순서를 기다리고 있습니다.’와 공급자·시간 표시 | 다시 누르지 말고 자동 진행을 기다린다. |
| 같은 공식 자료를 이미 조회 중 | ‘승인한 공식 자료를 조회하거나 같은 자료의 조회 완료를 기다리고 있습니다.’ | 조회 완료를 기다린다. |
| 공급자가 제한 초과 응답과 짧은 재시도 대기 시간을 명시 | ‘공급자 안내에 따라 잠시 기다린 뒤 한 번 더 요청합니다.’ | 최대 1회 자동 재시도를 기다린다. 모든 오류를 재시도하는 것은 아니다. |
| 누적 대기 240초 또는 전체 처리 300초 초과 | 중단 이유와 재요청·공식 저장 자료 안내, 입력 유지 | 잠시 후 다시 요청하거나 조회 범위를 줄여 재승인한다. 저장 사례로 이어갈 수도 있다. |
| 처리·대기 요청이 합계 120개로 가득 참 | ‘현재 실습 요청이 많아 접수하지 못했습니다. 입력은 유지됩니다. 잠시 후 다시 요청해 주세요.’ | 접수되지 않은 요청이므로 잠시 후 직접 다시 요청한다. |
| 결제·인증 오류 또는 외부 API 연결 장애 | 오류 내용과 문의용 요청 번호 표시. 최대 대기 시간 전에 실패할 수도 있음 | 연속 재요청을 멈추고 진행자에게 오류 문구·요청 번호를 전달한다. |

‘요청 취소’를 누르면 입력한 조건은 유지되고 후속 결과는 표시하지 않는다.
이미 전송된 외부 호출은 끝날 수 있으므로 취소가 호출 취소나 비용 환불을 보장하지 않는다.
브리핑 작성만 실패하면 조회된 근거는 남을 수 있고, 일반 응답 비교가 실패해도 기존
근거 결과는 유지된다. 화면에 표시된 실패 단계를 확인한다.

### 진행자의 대기와 장애 대응 안내

최종 참가자81명 보강은 [81명 운영 절차](WORKSHOP_81_OPERATIONS.md)를 따른다.
대기 화면의 앞선 요청 수는 같은 공급자의 대기열 기준이다. A~E 비상용 고정 결과를
선택·승인하면 원래 시각을 표시한 자료·브리핑·일반 응답을 새 외부 호출 없이 재생한다.
공식 저장 원자료로 새 브리핑을 만드는 방식은 Gemini 호출을 사용하므로 구분해 설명한다.

시작 전에 다음과 같이 안내한다. “요청이 몰리면 순서를 기다린다는 안내가 나옵니다.
시간이 갱신되고 있으면 다시 누르지 마세요. 기다리는 동안 조회 조건이나 원문 확인
항목을 살펴보겠습니다. 오류가 나오면 문구와 문의용 요청 번호를 알려 주세요.”

오류가 이어지면 ‘조회 자료’에서 ‘공식 저장 자료’를 선택하고, 사례의 질문·고정 조건을
확인한 뒤 ‘이 조건으로 조회’를 다시 누르게 한다. 저장 자료는 실제 수집 자료와 당시
모델 응답의 재생이며 최신 조회가 아니다. 자동 전환되지 않고 참가자의 선택·재승인이
필요하다. 사례 전환 전 필요한 검토 기록은 내려받도록 안내한다.

PPTX 운영 부록에는 대기 화면, ‘요청 취소’, 오류 문구·요청 번호 전달, 공식 저장 자료
전환을 한 장의 안내로 포함한다. 장애를 시연하기 위해 실제 API에 과도한 요청을 보내지 않는다.

## 2026-10-05 추가: 2부의 다섯 조사 사례

기존 승인·근거·검토를 익힌 뒤 A 출생 회복, B 청년 이동, C 물가 기여도, D 보수 비교,
E 두 회사 성장 구조 중 조별 한 사례를 선택한다. [실습 흐름](INVESTIGATION_WORKSHOP.md)을
따르며 API 폼을 채우는 능력보다 ‘무엇을 비교해야 질문에 답할 수 있는가’를 경험한다.

- A: 전국 증가와 지역 감소가 함께 가능한가? 증가율·증가 인원·과거 수준을 구별한다.
- B: 순유출과 이동 목적지는 같은 수치인가? 인구 분모와 행정구역 경계를 확인한다.
- C: 가격이 많이 오른 품목과 물가에 영향이 큰 품목은 같은가? 가중치·근사치의 한계를 읽는다.
- D: CEO 보수/직원 평균은 무엇의 배율인가? 공시 법인·산정 분모·주식 보상을 확인한다.
- E: 양사 5개년 구성표와 최근 연도 증가분을 읽는다. 카카오 정정 전/후 표와 NAVER
  전기 비교액 차이를 보고 ‘숫자를 찾았다’와 ‘비교 기준을 확인했다’의 차이를 토론한다.

D/E는 운영자가 준비한 실제 공시 발췌로 매번 계산·새 AI 브리핑을 수행한다. 사전 자료를
가상 자료 또는 최신 실시간 조회로 설명하지 않는다. [E 구성·접수번호](INVESTIGATION_DATA.md)를
강의자 근거로 사용한다. 원문과 의미를 사람이 확인하며 자동 기사 작성·발행은 하지 않는다.

사례 선택 → 질문 질답 → 자연어 조사 계획 승인 → 상세 브리핑·비교표 → 실제 일반 응답 비교
→ 직접 확인한 사실2개·부족한 해석·후속 질문·데스크 항목 작성 → 검토 기록 내려받기로 진행한다.
추가 모델 비교와 질답마다 요청이 늘어난다. 동시 실습 시간·사례 배분은
[API·운영 후속 검토](INVESTIGATION_FOLLOWUPS.md) 후 확정한다.
