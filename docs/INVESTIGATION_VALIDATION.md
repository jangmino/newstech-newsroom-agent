## 자동 검증

- `git diff --check` 통과. 변경 파일에서 자격증명 패턴이 발견되지 않았으며 `.env`는 미추적 상태다.
- `make check`: Ruff, 백엔드 **884개**, 프론트엔드 **229개**, TypeScript, Vite와 Python 패키지 빌드 통과.
- 신규 백엔드 29개: 공식 원자료 재생, 계산·코드 결합, 허용 범위, 승인 전 수치 접근 금지,
  원자료 재사용 표시, 조건 불일치, 모델 실패 시 근거 유지, 공급자 코드/기간/중복 검증.
- 신규 프론트엔드 3개: API 폼 없는 계획 승인, D/E 사전 자료 고지와 승인 body,
  자연어 수정 시 결과·검토 무효화, 비교표·근거 링크·일반 텍스트 안전 표시.
- 30개 동시 승인(사례별6개)을 **오프라인** 재생: 원자료 계산5회 공유, 모델 시도30회 분리,
  실패 시 근거 보존, 호출자 수정이 캐시를 오염시키지 않음을 확인.
  실제 공급자30명 부하·p95 지연 검증이 아니다.
- API 자동 테스트는 외부 소켓과 `.env` 읽기를 차단한다. 프론트엔드도 네트워크·저장을 차단한다.
  Node 내장 localStorage와 jsdom의 차이로 드러난 기존 두 테스트의 환경 설정을 보정했다.
- Python 빌드는 처음 샌드박스 DNS 제한으로 PyPI 의존성 수집에 실패했다. 공식 PyPI 접근 후
  `make check` 전체 재실행으로 통과했다. 기존 Starlette/httpx 관련 deprecation 경고 2개가 남아 있다.
- 자료 재생성 스크립트로 10개 파일의 SHA-256 동일성을 확인했다. 빌드 wheel에 manifest 포함
  조사 JSON 11개가 들어 있는 것을 확인했다.

## 실제 호출과 원문 대조

수동 수집 ledger47회(메타7·검색3·DART JSON18·KOSIS 데이터9·DART 원문10)와
완성된 KOSIS 어댑터 검증8회, 합계 **공공자료55회**. 데이터 수집은 수동 승인 범위이며 자동 테스트가 아니다.
Gemini **13회**: 각 사례 계획5회, 브리핑8회. 최초 다섯 사례 모두 ready/complete,
이후 B 코드 순위 및 E 시작·종료 연도 사업 구성 보강 재확인3회도 성공했다.
관측한 계획+브리핑 한 사례의 직렬 소요는 약5.5~7.8초였다. 실제 동시 사용자 지연 보장은 아니다.

실제 KOSIS 어댑터만의 직렬 소요: A2.52초/3회, B7.49초/3회, C1.73초/2회.
주요 안전 검증 예: 카카오 정정 전/후 매출 선택, NAVER 전기 재작성 차이, 직원 평균 분모,
KOSIS 지역 코드 체계 차이, 군위 편입 경계, 공식 CPI/근사 기여도 차이.
접수번호·표 위치·원문 해시는 [자료 구성](INVESTIGATION_DATA.md)에 있다.
[비밀정보 없는 수동 검증 요약](validation/investigation-live-20261005.json)을 함께 보관한다.

모델 수치 슬롯·인용 검증은 문장 의미의 참까지 보장하지 않는다. 조사형 브리핑에도 한국어 조사
어미가 어색한 사례가 있었으며, 기사로 사용하지 않고 원문과 의미를 사람이 확인하는 경계를 유지한다.

## 2026-10-06 후보 배포 중 발견한 브리핑 오류

첫 후보에서 B는 실제 자료 조회에는 성공했지만 세 번의 브리핑이 출력 검증에서 거부됐다.
동일 근거를 사용한 진단에서 모델이 요약·한계·후속 질문에 연령 숫자를 슬롯 없이 직접 쓰는
문제를 재현했다. B의 작성 지시에 '승인한 청년 연령/청년층/세부 연령대' 표현을 명시했다.
승인 조건의 정확한 연령은 그대로 표시하며 숫자 슬롯·인용 검증은 완화하지 않는다.
추가 모델 재시도나 수치 자동 수정도 넣지 않았다. 보완 후 동일 입력의 실제 모델 호출이
통과했다. 요약·한계·후속 질문의 직접 숫자를 거부하고 근거를 보존하는 오프라인 회귀를
추가했다. 후보·공개 검증 결과와 전체 호출 수는 아래 배포 기록으로 구분한다.

### 기능·공식 자료

첫 후보에서 A~E 실제 Gemini 계획을 확인했다. A~C는 KOSIS 실제 조회,
D/E는 원문 대조한 공식 저장 원자료로 계산했다. A103개/B90개/C68개 근거의
값·단위·순위·계산식은 저장 자료 재계산과 모두 일치했다. D6개/E150개 근거와 상세 표도 확인했다.
이번 배포에서 사업보고서를 다시 수집하지는 않았다. 원문 대조 근거는 앞의 개발 검증을 따른다.

실제 브라우저에서 E 선택 → 승인 전 결과 없음 → 저장 원자료 고지 → 승인 → 상세 표·
새 브리핑 → 일반 모델 비교 → 사람 검토·수정 → JSON 다운로드를 확인했다.
다운로드에 승인 조건·근거·AI 원본·일반 응답·사람 수정이 포함되고, 자연어 조건 수정 시
결과·검토가 초기화됐다. 마지막 후보도 동일 웹 자산임을 바이트 단위로 확인했다.
후보 및 공개 주소의 입장 보호·승인 없는 실행422·저장 사례 재생도 통과했다.

### 오류 대응·동시 요청

첫 후보의 B 브리핑3건과 C1건이 모델 출력 검증에 거부됐다. 원자료·계산표는 남았으며
실패를 성공 브리핑으로 대체하지 않았다. B 연령 표현을 보완한 최종 후보에서는 B의
실제 조회2회와 저장 원자료1회가 모두 완료됐다. C 실제 조회도 완료됐다.

최종 후보의 **동시5건(공식 저장 원자료+각각 새Gemini 브리핑)**은4건 완료,
C1건 출력 검증 거부였다. 반환 시간4.63~7.29초이며 C는 근거를 보존한 채 명시적으로
재승인해5.84초에 복구했다. 최초 혼합 요청이5/5 성공했다고 해석하지 않는다.
이전 후보의 혼합5건은5/5 완료했지만, 어느 결과도30명 실제 부하의 성공률 보장은 아니다.
`HTTP200`이나 큐의 `completed`는 브리핑 성공을 뜻하지 않아 `brief.status`를 별도로 확인했다.
모델 출력 검증 실패는 계속 가능하며 자동 브리핑 재시도·검증 완화는 추가하지 않았다.
