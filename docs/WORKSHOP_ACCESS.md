# 행사용 접근코드 (M3)

계정 없이 운영자가 전달한 공유 코드로 실습 API 접근을 제한합니다.
[ADR 0012](decisions/0012-shared-workshop-access-code.md)의 범위이며, 참가자 개인 확인이나
기사 사용 승인이 아닙니다. DB·쿠키·JWT·서버 세션·개인별 권한은 추가하지 않았습니다.

## 참가자 흐름

1. 화면을 열면 서버의 입장 상태를 확인합니다. 실패하면 질문 화면을 열지 않습니다.
2. 코드가 필요한 환경에서는 **행사 접근코드**를 입력하고 **실습 입장**을 누릅니다.
   입력은 가려지고 제출 후 비워집니다. 틀린 코드·연결 오류는 한국어로 안내합니다.
3. 입장 뒤 기존 질문 → 조건 확인·편집 → **이 조건으로 조회** → 근거·브리핑·검토 순서를
   따릅니다. 입장 확인만으로 질문을 분석하거나 자료를 조회하지 않습니다.
4. 상단 **실습 나가기**는 코드·질문·계획·결과·비교·검토를 지우고 입장 화면으로 돌아갑니다.
   새로고침도 코드와 실습 상태를 지웁니다. 재입장해도 이전 요청을 자동 실행하지 않습니다.
5. 다음 요청에서 코드가 거부되거나 입장 설정 오류가 발생하면 이전 결과까지 숨깁니다.
   일반 공급자 장애는 입장을 유지하고 기존 오류·재승인 흐름을 사용합니다.

코드는 React 메모리에만 유지하며 URL·요청 본문·브라우저 저장소·쿠키에 넣지 않습니다.
기존 `/plan`·`/execute`의 같은 출처 요청에만 헤더로 전달하고 리다이렉트를 허용하지 않습니다.
요청 중 나가기/입장 취소는 abort와 요청 버전 검사로 늦은 응답을 무시합니다.
이미 서버에 도착한 조회를 취소하거나 발생한 비용을 되돌리는 기능은 아닙니다.

## 로컬 설정과 확인

`APP_ENV=local` 또는 `test`에서 `WORKSHOP_ACCESS_CODE`가 정확히 빈 문자열이면 기존처럼
코드 없이 사용합니다. 기존 로컬 설정은 변경하지 않았으므로 새 입장 화면을 보려면
백엔드 `.env`의 `WORKSHOP_ACCESS_CODE`에 직접 정한 코드를 넣고 API를 재시작합니다.
프론트엔드 환경변수나 `VITE_*`에는 넣지 않습니다.

- 영문 대소문자·숫자·`_`·`-`, 16~128자. 대소문자 구분, 앞뒤 공백 제거/정규화 없음.
- local에서도 값이 있는데 형식이 잘못되면 잠깁니다. 형식 제한은 무작위성을 보장하지 않으므로
  짧은 암기용 문구나 저장소의 테스트 문자열을 실제 행사 코드로 사용하지 않습니다.
- 코드 생성에는 로컬 터미널에서 `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`
  등을 사용합니다. 출력은 비밀정보이므로 채팅·Git·스크린샷·공개 문서로 전달하지 않습니다.
  [Python secrets](https://docs.python.org/3.12/library/secrets.html)의 무작위 생성과
  `compare_digest`를 사용합니다.
- 모의 규칙 + 모의 자료로 입장 → 분석 → 승인 → 검토 한 항목 선택 → 나가기 → 재입장을
  확인합니다. 저장 자료도 지원하며 외부 API를 켤 필요가 없습니다.
- 로컬 제한을 해제하려면 값을 비우고 API를 재시작합니다. 코드 입력 여부는
  `LIVE_API_ENABLED`, 자료 모드, 공급자 키와 독립적입니다.

이번 검증은 실행 프로세스에만 가상 코드를 주입한 뒤 원래 설정으로 되돌렸습니다.
실제 `.env`나 키를 수정하지 않았고, 실제 Gemini·OpenDART·KOSIS 호출도 하지 않았습니다.

## API 계약

| 요청 | 접근 | 응답 |
|---|---|---|
| `GET /api/v1/access` | 공개, 코드 전송 불필요 | `{ "required": boolean, "available": boolean }` |
| `POST /api/v1/access` | `X-Workshop-Code`로 확인, 본문 없음 | 같은 상태 객체, 토큰·코드·세션 없음 |
| `/api/*` | 코드가 설정되면 모든 메서드·자료 모드에 필요 | 기존 성공 본문·승인 계약 유지 |
| `/docs`, `/docs/*`, `/redoc`, `/openapi.json` | 같은 보호 적용 | 코드 없이는 문서도 401 |
| `/health`, UI/정적 파일 | 공개 | 기존 상태·입장 UI |

공개 GET 상태만 코드 검사에서 제외합니다. 허용 출처의 CORS 사전 요청은 기존 미들웨어가
처리합니다. CORS는 인증을 대체하지 않으며, 성공한 입장 요청 뒤에도 매 요청에 코드가
필요합니다. `/analyze`도 동일한 검사 대상이지만 mock 성공 응답의 기존 필드는 유지합니다.

`required=false, available=true`는 제한 없는 local/test입니다.
`required=true, available=false`는 코드 설정 오류이며 입력을 반복해서 해결할 수 없습니다.
stage/event를 포함한 local/test 이외 환경에서 코드가 비어 있으면 이 상태가 됩니다.
운영 환경은 `APP_ENV=stage|event`를 반드시 명시합니다.

| 상황 | HTTP | `detail.code` |
|---|---|---|
| 코드 누락·잘못된 값·중복 헤더 | 401 | `workshop_access_required` |
| 비어 있으면 안 되는 환경, 설정 코드 형식 오류 | 503 | `workshop_access_unavailable` |

두 오류는 기존 `{detail: {code, message, field_errors: {}}}` 구조입니다. 코드 원문·길이·
일치한 일부를 응답하지 않습니다. URL·본문·쿠키는 인증 수단으로 해석하지 않습니다.
API와 보호 문서 응답에 `Cache-Control: no-store`, `Vary: X-Workshop-Code`를 적용합니다.
이 브라우저/프록시 캐시 정책은 백엔드의 공공자료 메모리 캐시와 별개입니다.

`WorkshopAccessMiddleware`는 라우팅·본문 파싱·질문 해석·공급자·캐시 전에 검사합니다.
설정 값은 `repr`에서 제외하고, 입력 형식 확인 뒤 SHA-256 digest를 일정 시간 비교합니다.
미들웨어는 요청·헤더·코드·본문을 로그로 기록하지 않습니다.

## 기관 환경과 남은 한계

stage/event 코드는 기관 또는 주최 측 Secret Manager에서 `WORKSHOP_ACCESS_CODE`로
주입하고 HTTPS를 사용합니다. URL 쿼리에 코드를 넣으면 프록시 로그에 남을 수 있으므로
헤더 외 방식으로 보내지 않습니다. 추후 로그도 헤더와 요청 본문을 수집하지 않아야 합니다.
코드 교체는 프로세스 재시작 또는 새 배포가 필요합니다. 여러 인스턴스의 교체를 완료해야
기존 코드가 일관되게 차단되며 이미 시작한 요청은 소급 취소하지 않습니다.

공유 코드는 개인별 로그인·역할·퇴장 처리·요청량 제한이 아닙니다. 코드를 가진 참가자는
같은 API 권한을 가지며 나가기는 현재 탭의 상태만 지웁니다. 다른 탭의 코드도 취소하려면
운영자가 코드를 교체해야 합니다. 분산 무차별 시도 방어, 개인별 감사 이력, 운영자 전용
권한은 이번 범위가 아닙니다. 기존 Gemini·공공자료 호출 한도는 계속 적용됩니다.

**요청 ID를 연결한 구조화 로그**는 [로그 계약](REQUEST_LOGGING.md)으로 완료했습니다.
접근 거절·설정 오류도 문의 번호로 확인하며 코드·키·질문 원문은 기록하지 않습니다.
다음 최소 기능은 읽기 전용 실습 운영 상태 화면입니다. 이후
기관 Secret Manager·Cloud Run stage 배포, 30명 부하 시험·장애 리허설을 진행합니다.
