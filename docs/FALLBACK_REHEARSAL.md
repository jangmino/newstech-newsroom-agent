# 장애·공식 저장 자료 전환 리허설

## 이번에 확인하는 것

실제 조회 실패를 참가자에게 알리고, 입력 조건을 유지해 공식 저장 자료의 출처·시각·범위를
다시 확인한 뒤 별도 승인으로 실습을 이어갑니다. 저장 자료 성공은 실제 공급자의 복구나
최신 조회 성공을 뜻하지 않으며, 검토 체크 완료도 기사 사용 승인이 아닙니다.
[저장 자료 계약](SNAPSHOT_FALLBACK.md)과 [ADR 0011](decisions/0011-explicit-public-data-snapshot.md)을
그대로 사용합니다. 제품 UI·API 계약·배포·실제 API 설정을 변경하지 않는 운영 검증입니다.

실제 공급자는 켜지 않습니다. stage에서는 **비활성 설정에 의한 조회 차단**을 확인하고,
공급자 시간 초과·요청 제한·서비스 오류는 외부 네트워크가 차단된 로컬 테스트에서 재현합니다.
stage의 실제 공급자 장애를 발생시키거나 복구시킨 것으로 표현하지 않습니다.

## 진행자 준비

1. 승인된 stage URL과 접근코드를 사용합니다. 코드·키를 화면 공유·문서·오류 신고에 넣지 않습니다.
2. ‘실습 운영 상태 보기’에서 세 공급자가 비활성이고 KOSIS/OpenDART 저장 자료가 사용
   가능한지 확인합니다. 이 화면은 설정·파일 확인이며 외부 연결 성공 확인이 아닙니다.
3. ‘질문 해석 방식’은 **모의 규칙 · 외부 전송 없음**으로 둡니다. 저장 자료를 선택하더라도
   Gemini 해석을 선택하면 별도 모델 호출 경로가 되므로 이번 리허설에서는 사용하지 않습니다.
4. 아래 두 질문과 지원 범위를 사용합니다. 새로운 기업·기간·연령으로 임의 대체하지 않습니다.

| 자료원 | 질문 | 변경해서 확인할 조건 |
|---|---|---|
| KOSIS | 전국 시·도 15-29세 청년 고용률 2020-2024년 연간 증감 폭 비교 | 수도권 시·도, 2021-2024, 증감률 |
| OpenDART | 삼성전자 2022-2024년 연간 연결 매출액 증감 폭 비교 | 증감률, 나머지 조건 유지 |

## 참가자 화면에서 진행

**계획 단계에서 막힌 경우 — 현재 stage에서 직접 확인 가능**

1. ‘조회 자료’를 ‘공식 실제 자료’로 선택하고 위 질문을 분석합니다.
2. 실제 조회가 꺼져 있다는 한국어 오류와 문의용 요청 번호를 확인합니다. 조건·결과가
   없으므로 ‘저장 자료로 조건 다시 확인’ 버튼이 나타나지 않는 것이 현재 동작입니다.
3. ‘조회 자료’를 **공식 저장 자료 · 확보 시점 기준**으로 바꾸고 질문을 다시 분석합니다.
   질문은 유지되며 아직 편집 조건이 없던 단계이므로 지원 조건을 새로 확인합니다.
4. 원래 확보 시각·자료원·지원 범위·단위를 읽고 조건을 수정합니다. 아직 숫자·브리핑·
   검토 체크가 없어야 합니다. **이 조건으로 조회**를 누른 뒤에만 결과를 확인합니다.

**조건 승인 후 조회에 실패한 경우 — 로컬 모의 장애로 확인**

1. 계획을 확인하고 표의 조건으로 수정한 뒤 **이 조건으로 조회**를 누릅니다.
2. 시간 초과/요청 제한/서비스 오류가 한국어로 표시되는지 확인합니다. 실패 뒤 이전
   근거·브리핑·검토 체크가 보이면 진행을 중단합니다. 자동 재조회나 자동 자료 전환은 없습니다.
3. **저장 자료로 조건 다시 확인**을 한 번 누릅니다. 원래 오류·문의 번호가 ‘전환하기 전
   실제 조회 안내’로 남고, 수정한 조건이 유지되어야 합니다. 외부 질문 해석을 다시 하지 않습니다.
4. 원래 확보 시각·출처·지원 범위를 확인합니다. 이 버튼은 실행 승인이 아니므로 결과가
   나오면 안 됩니다. **이 조건으로 조회**를 별도로 눌러 저장 자료 결과를 표시합니다.
5. 최종 조회 조건이 승인한 값과 같고 ‘공식 저장 자료 · 최신 조회 아님’, 사람 검토
   **0/4**가 표시되는지 확인합니다. 하나를 체크하고 조건을 바꾸면 결과·체크가 숨겨져야 하며,
   재승인하면 새 검토가 0/4로 시작해야 합니다.

진행자 설명 예시: “실제 조회는 실패했습니다. 지금부터는 미리 확보한 공식 자료를 사용합니다.
저장 시점과 범위를 확인하고 다시 승인해 주세요. 최신 자료나 기사 사용 승인을 뜻하지 않습니다.”

## 멈추거나 다시 확인할 상황

| 상황 | 진행 방법 |
|---|---|
| 저장 자료 없음·무결성 오류·비활성 | 결과 없이 중단하고 운영자에게 문의 번호 전달. 가상 수치를 공식 자료로 대신 표시하지 않음 |
| 저장 자료 준비 자체가 실패 | 조회 버튼이 없는 상태로 중단. 복구 뒤 질문을 다시 분석하고 편집 조건을 다시 확인·입력해야 함 |
| 저장 자료 버전 변경(409) | 질문을 다시 분석하여 새 출처·시각·범위를 읽고 재승인. 이전 버전으로 계속 실행하지 않음 |
| 지원 범위 밖 조건(422/입력 안내) | 참가자에게 한국어 안내를 읽어 주고 명시적으로 지원 조건을 선택하게 함 |
| Gemini 해석 오류 | 모의 규칙을 명시적으로 선택하고 질문을 다시 분석. 자동 해석 대체로 설명하지 않음 |
| 접근코드 오류 | 다시 입장. 이전 결과·검토가 초기화되며 자동 재실행되지 않음 |
| 웹 앱 자체 또는 행사장 인터넷 장애 | 같은 서버의 snapshot도 접근할 수 없음. 실습을 중단하고 진행자의 설명 자료로 전환 |

오류 신고에는 자료 모드·자료원·단계·문의용 요청 번호만 우선 전달합니다. 코드·키·인증 헤더·
원문 네트워크 로그를 복사하지 않습니다. 서버에 참가자의 편집 조건·검토 이력을 저장하지
않으므로 질문 재분석·새로고침·재입장 후에는 조건을 다시 확인합니다.

## 재현 가능한 검사

오프라인 회귀 검사는 기존 테스트 실행기와 가상 코드·모의 전송만 사용합니다.

```bash
cd apps/api
UV_OFFLINE=1 UV_CACHE_DIR=../../.cache/uv uv run pytest tests/test_fallback_rehearsal.py -q
```

저장소 루트에서 UI 검사는 `pnpm --dir apps/web test SnapshotFlow.test.tsx`입니다.
실제 `.env`·키·외부 네트워크를 읽지 않으며 503/429·저장 자료 오류와 늦은 응답을 재현합니다.

stage API 리허설은 아래 명령으로 별도 실행합니다. URL은 승인된 stage origin으로 바꾸고,
보고서는 아직 없는 Git 제외 경로를 지정합니다. `make check`는 이 네트워크 검사를 실행하지 않습니다.

```bash
apps/api/.venv/bin/python scripts/stage_rehearsal.py \
  --base-url https://YOUR-STAGE.run.app \
  --access-code-file .cache/stage-workshop-code.txt \
  --report .cache/stage-rehearsal-result.json
```

기존 부하 도구의 HTTPS origin·코드 파일·비밀정보 없는 집계·타임아웃 검사를 재사용합니다.
live off와 저장 자료 상태를 먼저 검사하고 실패하면 중단합니다. 공급자 비활성을 확인한 뒤에만
live 계획/실행의 차단 응답을 검사합니다. 사전 검사 12회, 자료원별 7회, 사후 상태 1회로
**최대 27회**, 전체 90초·요청당 15초입니다. 재시도·외부 해석·설정 변경·재배포는 없습니다.
실패 응답·조건·키·코드·개인 프로젝트 주소는 보고서에 넣지 않습니다.
