# 공공자료 캐시와 동일 요청 합치기 (M3 첫 단위)

같은 공식 자료를 반복해서 요청하는 비용과 대기 시간을 줄입니다. 참가자는 매번 조건을
승인해야 하며, 재사용 여부와 원래 조회 시각을 확인합니다. 공식 자료의 최신성·기사 사용을
보증하는 기능이 아닙니다. [ADR 0009](decisions/0009-process-public-data-cache.md)를 따릅니다.

## 참가자 경험

1. 질문 해석·편집에는 외부 자료 조회나 캐시 읽기가 없습니다.
2. 승인 후 필요한 자료가 없으면 새로 조회하고 정규화합니다. 이때 ‘공식 자료를 새로
   조회했습니다’와 재사용 기한이 표시됩니다.
3. 같은 자료가 기한 안에 있으면 ‘보관된 공식 자료를 재사용했습니다’로 표시합니다.
   외부 API를 다시 호출하지 않았음을 알리고 원래 조회 시각을 유지합니다.
4. 같은 자료를 이미 조회 중이면 중복 요청을 보내지 않고 기다립니다. ‘같은 조건의 진행
   중 조회 결과를 함께 사용했습니다’로 표시합니다.
5. 비교 기준을 증감 폭에서 증감률로 바꾸면 원자료는 같아도 계산·브리핑·요청 ID는 새로
   만들어집니다. 조건 변경 중 결과를 숨기고 재승인 후 검토는 항상 0/4로 시작합니다.

근거·브리핑·조건 변경 전후 비교에 각각 재사용 여부를 표시합니다. 기한은 이 결과를
만든 시점의 안내이며, 화면이 열려 있는 동안 자동 재조회하지 않습니다. 기한이 지난
다음 승인에는 새 자료가 필요하고, 조회 실패 시 오래된 결과를 대신 보여주지 않습니다.
브라우저 새로고침은 화면 상태를 지우지만 서버의 공공자료 캐시를 삭제하지 않습니다.

## 보관 범위와 키

- KOSIS: 정규화한 지역 × 기간의 연간 자료 묶음 전체. 계약 버전과 표·항목·연령·지역
  코드·연간 주기·시작/종료 연도·공개 API 인자가 키입니다. 다른 대상·기간은 다른 조회입니다.
- OpenDART: 정규화한 두 연도 자료 한 쌍. 계약 버전·기업 코드·보고서·연결 구분·두 연도가
  키입니다. 한 연도만 성공한 부분 결과는 저장하지 않습니다.
- 비교 기준과 질문 문구는 자료 선택을 바꾸지 않으므로 키에서 제외합니다. 원자료만
  공유하며 조건 승인·브리핑·검토·질문이나 참가자 기록을 보관하지 않습니다.
- 키·값에 인증키·인증 URL·공급자 원문 응답을 넣지 않습니다. 캐시 키는 API에 노출하지
  않습니다. API 키를 변경할 때는 기존 절차대로 백엔드를 재시작하여 캐시도 비웁니다.
- 공급자의 성공 응답을 정규화한 후에만 저장합니다. 요청마다 반환 값을 복사하여 한
  응답을 수정해 다른 참가자의 원자료가 바뀌지 않게 합니다.

## 설정과 수명

```text
PUBLIC_DATA_CACHE_ENABLED=true
CACHE_TTL_SECONDS=3600
CACHE_MAX_ENTRIES=64
```

저장소 기본값입니다. live 활성화와 무관한 설정이며, 기본 mock에서는 사용하지 않습니다.
설정 변경은 백엔드 재시작 후 적용합니다. TTL은 1~86,400초, 완료 자료 상한은 공급자별
1~256건입니다. 기본값은 1시간·공급자별 64건이며 기한 내 사용해도 기한을 연장하지 않습니다.
상한에 도달하면 가장 오래 사용하지 않은 완료 자료부터 제거합니다. `false`로 끄면
이전처럼 각 승인마다 외부 조회하며 캐시와 진행 요청 공유를 모두 사용하지 않습니다.

만료는 시스템 시각 조정의 영향을 줄이기 위해 monotonic clock으로 검사합니다. 표시용
저장·만료 시각은 UTC이며 프론트엔드에서 현지 시각으로 표시합니다. TTL은 전체 자료의
조회·정규화가 끝난 시점부터 시작하고 `evidence.retrieved_at`은 원래 응답 수신 시각입니다.
OpenDART 연도별 조회 시각과 KOSIS 자료 최종수정일도 바꾸지 않습니다.

프로세스 메모리에만 있으며 DB·파일·브라우저 저장소가 없습니다. 재시작 시 사라지고
서로 다른 워커·Cloud Run 인스턴스끼리는 공유하지 않습니다. 여러 인스턴스에서 같은
자료를 각각 조회할 수 있으므로 행사 전체의 사용량 제한을 대신하지 않습니다.

## 승인·실패·동시 실행 경계

승인 플래그·지원 조건·질문과 자료원 일치·전역/공급자 활성화·키 유무를 캐시보다 먼저
검사합니다. 값이 이미 있어도 비활성 공급자를 우회하지 않습니다. `/plan`·mock·기존
`/analyze`에는 캐시가 없습니다. 캐시가 적용되는 경로는 승인된 live `/execute`뿐입니다.

같은 키의 진행 작업을 참조하고, 한 요청이 취소되어도 다른 참가자가 기다리는 작업은
유지합니다. 모두 취소해도 이미 시작한 조회는 기존 공급자 시간 제한 안에서 끝날 수
있습니다. 서버 종료 시 진행 작업을 취소·회수합니다. 구현은 Python의
[작업 참조와 취소 보호](https://docs.python.org/3.12/library/asyncio-task.html#shielding-from-cancellation)와
FastAPI의 [lifespan](https://fastapi.tiangolo.com/advanced/events/)을 사용합니다.

실패는 기다리던 요청 모두에 기존 안전한 오류로 전달합니다. 실패·부분 자료를 캐시하지
않으며 진행 목록에서 제거하므로 다음 명시적 승인으로 재시도할 수 있습니다.
만료 후 실패에도 오래된 자료·mock·snapshot을 반환하지 않습니다. 자동 재시도나 승인 없는
미리 조회는 없습니다. [공공자료 호출 제한](PUBLIC_DATA_LIMITS.md)은 실제 HTTP 경계에
적용하며 캐시 hit와 동일 조회를 기다리는 참가자는 추가 한도를 쓰지 않습니다.

같은 자료를 승인한 N개의 요청이 한 프로세스에서 기한 내 처리될 때 첫 조회 비용은
KOSIS 1회, OpenDART 2회입니다. 이후 동일 자료는 추가 조회하지 않습니다. Gemini 질문
분석은 이 캐시 대상이 아니며 각 분석 요청의 기존 호출·한도 규칙을 유지합니다.

## API 계약

`/execute`의 `ExecutionResponse`에만 nullable `cache`를 추가합니다.
mock 또는 캐시 비활성일 때는 `null`이며 `/plan`, `/analyze` 계약은 그대로입니다.

```json
{
  "cache": {
    "status": "hit",
    "scope": "process",
    "stored_at": "2026-09-16T00:00:00+00:00",
    "expires_at": "2026-09-16T01:00:00+00:00",
    "ttl_seconds": 3600,
    "age_seconds": 120
  }
}
```

`miss`는 이 승인이 새 조회를 시작함, `hit`는 완료 자료 재사용, `coalesced`는 진행 중
조회 공유입니다. `age_seconds`는 응답 구성 때의 저장 후 경과 초입니다. 원래 조회 시각을
이번 승인 시각으로 바꾸지 않으며 `data_mode=live`는 공식 자료의 출처를 의미합니다.
실제로 이번 승인에서 외부 API를 호출했는지는 반드시 `cache.status`와 함께 해석합니다.
재사용 여부는 사람 검토 상태와 별개이며 `review_required`를 바꾸지 않습니다.

## 검증과 다음 범위

2026-09-16 `UV_OFFLINE=1 make check`로 백엔드 490건·화면 84건, lint·타입·웹/패키지
빌드를 통과했습니다. 실제 외부 API 호출 없이 공개 fixture·모의 전송·가짜 시계를 사용했습니다.
기존 테스트 의존성의 deprecation 경고 2건은 남아 있습니다.
재시작한 로컬 서버의 mock 분석·승인과 새 응답 스키마도 확인했습니다. `git diff --check`와
Git 대상 파일 116개의 비밀정보 검사를 통과했으며 `.env`는 변경·스테이징하지 않았습니다.

- 저장 완료부터 TTL 적용·만료 경계·접근 시 기한 유지·시각 변경·크기 제한·응답 복사.
- 30개 동일 작업의 단일 조회, 다른 키의 독립 실행, 취소·전체 취소·실패 후 정리·서버 종료.
- 실제 API 경로에서 승인·활성화 차단, 두 공급자별 조회 공유, 조건별 키 분리, 계산 재실행,
  원래 조회 시각 보존, 정규화 실패와 부분 성공/만료 자료의 재사용 금지, mock·이전 API 호환.
- 화면에서 승인 전 숨김, 재사용·공유 안내, 원래 시각·기한 표시, 조건 비교·검토 초기화,
  재조회 실패 후 이전 결과 숨김.

이는 단일 프로세스의 동작 검증이며 행사 30명 부하 시험이 아닙니다. 후속 단위인
[공공자료의 호출·동시 실행 제한](PUBLIC_DATA_LIMITS.md)과 [명시적 snapshot](SNAPSHOT_FALLBACK.md)도
적용했습니다. [행사용 접근코드](WORKSHOP_ACCESS.md)도 완료했으며 캐시 재사용 전에 검사합니다.
다음 최소 단위는 요청 ID를 연결한 구조화 로그입니다. 운영 상태,
기관 Secret Manager·Cloud Run stage 배포·리허설은 남아 있습니다.
