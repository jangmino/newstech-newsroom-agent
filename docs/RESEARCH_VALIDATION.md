# 2부 실습 구현·실제 연결 확인

- 날짜: 2026-09-17
- 범위: [ADR 0017](decisions/0017-two-part-research-workshop.md), [2부 실습](RESEARCH_WORKSHOP.md)
- 자동 테스트와 실제 호출은 분리했다. 아래 수동 확인은 사용자가 승인한 개인 계정 범위다.

## 자동 검증

`make check`의 Ruff, 백엔드 761개 테스트, 프론트엔드 183개 테스트, TypeScript, Vite/Python
패키지 빌드를 통과했다. 2부 백엔드 동작 검사는 33개, 프론트엔드 검사는 8개다.
기존 1부의 mock/live/snapshot·승인·검토·접근코드·로그 회귀도 함께 실행했다.
환경 파일과 실제 네트워크는 기존 테스트 공통 설정에서 차단했다.

검사한 주요 경계는 승인 전 수치·브리핑 없음, 엄격한 승인 플래그, 회사명·코드 대조,
모호성·지원 밖 질문, 자연어 수정, 단일 시도, 음수·0·누락 계정, 원자료 캐시 재사용,
Gemini SDK의 구조화 출력, 잘못된 숫자/인용 거부, 생성 실패 시 근거 보존, 늦은 응답과 검토 초기화다.
개별 시도에는 순위를 만들지 않고 복수 지역의 순위는 반올림 전 코드 계산으로 정한다.

기존 FastAPI/Starlette 테스트 의존성의 deprecation 경고 두 종류는 남아 있으며 실패는 아니다.

## 브라우저 확인

로컬 Chrome에서 1부 기본 진입·2부 전환·모의 계획·승인 전 결과 없음·승인 후 브리핑과 근거
번호·검토 0→1개 확인을 실행했다. “삼성전자로 바꾸고 최근 2년 매출만 봐줘” 수정 요청 입력과
동시에 결과·검토가 사라지고, 반영 후 삼성전자·매출액·2023~2024년 계획에서 다시 승인을
기다리는 것을 확인했다. 폼·체크박스·버튼·원자료 표를 기존 색상과 카드 디자인에 맞춰 점검했다.

## 개인 stage

런타임 소스 `3295dcb`, Cloud Build `6c4c6026-4343-47ef-b7ba-881e81758aca`의 이미지를 사용했다.
이미지 digest는 `sha256:1c569d4cfd3f839efb5c7aea0fc5820055fa0868bd34c00ddda0ed4377ccbedf`다.
기존 네 Secret의 숫자 버전·공유 코드·공개 범위·리소스·비용 알림은 유지했다.
기본 트래픽 0% 후보에서 아래 순서로 확인했다.

| 확인 | 결과 |
|---|---|
| 1부 공식 저장 자료 계획·승인 실행 | 통과, 외부 공급자 호출 없음 |
| SK하이닉스 자유 질문·실제 조회·Gemini 브리핑 | 2023~2025년 매출액/영업이익, 근거 12개, 계획 약 5.7초·승인 실행 약 14.8초 |

최초 후보 `newsroom-stage-part2-20260917`에서는 KOSIS 요청과 한 번의 수동 재확인이 각각
20초 제한에 걸렸다. 로그의 오류는 `kosis_timeout`이었다. 원인 구분을 위해 이전 배포의
1부 경로·후보의 1부 경로·로컬 단일 지역 경로를 한 번씩 비교했다. 이전 배포와 로컬은
성공했고 후보의 기존 경로도 시간 초과였다. 이 결과만으로 공급자 전체 장애나 앱 코드
결함이라고 단정하지 않았다.

이미지·설정·키 버전·조회 조건을 바꾸지 않고 새 후보 `newsroom-stage-part2b-20260917`을
만들자 KOSIS 조회가 성공했다. 근본 연결 원인은 확정하지 못했다. 이때 Gemini 출력은
`invalid_planner_output`으로 거부돼 근거만 보존했다. 별도 재승인 한 번으로 기존 근거를
캐시에서 재사용하고 브리핑을 완성했다(약 6.4초, 근거 4개, 단일 지역 순위 없음).
실패한 브리핑이나 가상 수치를 성공 결과로 대체하지 않았으며 앱의 자동 재시도는 없다.

확인 후 새 후보에 기존 URL 트래픽 100%를 전환하고 임시 `live-check` 태그를 제거했다.
이전 검증 리비전 `newsroom-stage-live-20260917`은 복귀 지점으로 남겼다. 전환 후 10개
HTTP 요청으로 상태·코드 보호·1부/2부 정적 번들·2부 mock 계획/승인/결과·기존
`/api/v1/analyze` 호환성을 다시 확인했다. 이 후속 확인은 실제 공급자를 호출하지 않았다.

이번 stage HTTP 확인은 총 28회다. 200 20회, 의도한 401 2회·422 3회, KOSIS 시간 초과
503 3회였으며 200 중 한 건의 브리핑은 검증 실패 상태였다. 로컬을 포함한 공급자 호출은
**Gemini 11회, OpenDART 13회, KOSIS 7회**로, 실패한 호출도 포함한다. Gemini 11회 중
계획 5회·브리핑 6회이며 브리핑 하나는 출력 검증에서 중단됐다. KOSIS 7회 중 세 번이
시간 초과였다. 한두 사례의 성공이나 후보 교체를 지속적인 연결 품질 보증으로 해석하지 않는다.

Git 제외 기록은 `.cache/research-stage-check-20260917.json`,
`.cache/research-kosis-retry-20260917.json`, `.cache/kosis-compare-20260917.json`,
`.cache/research-kosis-fresh-candidate-20260917.json`, `.cache/research-kosis-reapproval-20260917.json`,
`.cache/research-promoted-check-20260917.json`, `.cache/research-stage-deployment-20260917.json`이다.
실패 기록도 보존했다. 최초 새 후보 확인 도구는 브리핑 검증 실패에서 중단됐으며 해당
요청의 KOSIS 성공·브리핑 거부는 200 응답과 안전한 오류 로그, 후속 cache hit로 확인했다.

## 마무리 검증

최종 `UV_OFFLINE=1 make check`에서도 백엔드 761개·프론트엔드 183개와 모든 정적 검사·빌드가
통과했다. `git diff --check`와 변경 문서 13개의 상대 링크 182개 검사도 통과했다.
Git 추적·추가 대상 181개 파일의 패턴 검사와 실제 키·접근코드 값 포함 검사에서 발견 0건이다.
`.env`의 브리핑 활성화 설정과 접근코드·개인 배포 설정·수동 보고서는
Git 제외로 유지하며 클라우드 이미지는 명시적 소스 묶음만 빌드한다.

## 남은 검증 범위

모든 회사·다양한 자유 질문 표현의 모델 품질, 분기·다른 통계표, 30명 live 지속 부하, 행사장
네트워크·브라우저, 기관 인계는 이번 소규모 확인으로 보증하지 않는다. Gemini의 근거 인용과
숫자 슬롯 검사는 문장의 의미·인과관계·기사 사용 가능성을 자동 승인하는 장치가 아니다.
