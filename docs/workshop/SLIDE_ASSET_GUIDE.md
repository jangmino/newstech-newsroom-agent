## 실제 프론트엔드 화면 촬영 목록

아래 표는 사전 촬영 설계다. 이후 사용자의 PPTX 제작 승인에 따라 2026-10-05
로컬 웹앱에서 고용·C·D·E를 실행해 실제 화면을 확보했다. 고용·C는 공식 실제 자료
모드, D·E는 원문 대조한 공식 저장 원자료 모드다. 새 Gemini 계획·브리핑과 고용·C의
별도 일반 응답을 확인했다. 승인 전 수치 자료를 실행하지 않았고, 사람 검토 완료를
연출하지 않았다. 비밀값·접근코드·브라우저 계정 화면은 포함하지 않았다.

| ID | 영역과 펼칠 항목 | 장 | 촬영에서 확인할 점 |
|---|---|---|---|
| C01 | 1부 01 질문·예제 | S10 | 질문과 실습 선택, 개인 브라우저 UI 제외 |

UI에서 공식 원문 링크를 열어 촬영할 경우 같은 기간·단위·표·접수번호를 맞춘다. 전체 스크롤 화면을 한 장에 축소하지 않는다. 새로고침이나 사례 변경 전에는 사용자 검토 기록을 보존한다. 접근코드·브라우저 계정·키·내부 운영 화면은 캡처하지 않는다. 촬영 파일에는 사용 사례·자료 방식·원자료 버전·촬영 시각·로컬/배포 구분을 별도 메타정보로 남긴다.

## 제작자가 피할 표현

- “Gemini가 인터넷과 API를 자유롭게 조사한다” → 지원 카탈로그·서버 실행·참가자 승인을 설명한다.
- “OpenDART API로는 D/E를 할 수 없다” → 원문은 제공하지만 정의·분류·정정 대조 작업이 남는다고 설명한다.
- “공식 저장 자료이므로 인터넷과 Gemini가 없어도 모두 된다” → archive와 사전 생성 결과 재생을 구분한다.
- “모델에 원문 전체와 출처 링크를 모두 보냈다” → 실제 선택된 facts와 입력 계약을 설명한다.
- “사람 검토 폼을 채우면 AI 초안도 고쳐진다” → 수정 브리핑은 직접 편집한다.
- “MCP나 IDE를 설치하면 사실 검증이 자동으로 된다” → 연결·개발·운영·검증 책임을 구분한다.

## 이번 사전 제작 검증

초안 34장의 서식·비율·글꼴·색·배치를 확인했다. 현재 코드의 Gemini 입력·출력과 UI 패널 명칭·검토 상태를 대조했다. 외부 대안 기술은 공식 문서를 확인했다. 본편 시간 합계는 20분·60분·휴식 10분·60분이며, 마지막 휴식에는 발표를 넣지 않았다.

## 완성 PPTX의 자료 배치

- S10·S11·S13·S16·S27·S30: 실제 로컬 화면의 질문·조건·근거·수정·계획·검토 영역을 잘라 사용했다.
- S12: 실제 고용 사례의 승인 조건을 편집 가능한 표로 옮겼다.
- S14: 실제 일반 응답과 근거 브리핑을 발췌했다. 일반 응답의 원인 설명을 사실로 승인하지 않고, 참가자가 근거 유무를 질문하도록 구성했다.
- S23·S28: 실제 C 실행의 호박·경유 값과 근거 번호를 발췌했다. 전체 순위표를 대체하거나 공식 기여도로 표현하지 않는다.
- S24: 공식 원문 대조 문서의 D 개인 보수·직원 평균·배율을 사용했다.
- S25: 실제 E 결과의 2025년 NAVER 사업별 비중을 편집 가능한 차트로 옮겼다. 원문 기준 분류를 유지했다.
- X06: `INVESTIGATION_DATA.md`의 정정·전기 비교액과 접수번호를 옮겼다.

표·차트·도해는 편집 가능한 개체다. 화면 캡처는 래스터 이미지다. 원고의 긴 설명은
발표자 노트로 옮겼고, 상세 모델 입력 JSON과 시스템 지시문은 기술 자료를 함께 참고한다.
원본 글꼴 Apple SD Gothic Neo를 유지했다. 글꼴을 포함한 파일은 아니므로 다른 OS에서
발표할 경우 글꼴 설치 여부와 대체 결과를 확인한다.
