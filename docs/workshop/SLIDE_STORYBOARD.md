# 실습 강의 슬라이드 원고와 진행 노트

2026-10-05 제작 원고. 초안 PPTX의 내용은 재사용하지 않았다. 표의 시간은 설명과 참가자 활동을 합친 시간이다. `S`는 본편, `X`는 선택 부록이다. 시연 중 생성되는 수치·문장은 고정하지 않고 실제 표시 결과를 읽는다.

## 도입과 시연 13시 30분부터 13시 50분

### S01 취재 질문에서 근거 기반 브리핑까지

- **시간:** 13:30–13:31, 1분.
- **화면 문안:** 뉴스룸 AI 에이전트 실습 / 오장민 / 2026년 10월 7일.
- **발표 노트:** “오늘은 브리핑을 만들고, 어떤 근거로 썼는지 데스크에 설명할 수 있는 상태까지 가 보겠습니다.” 코딩이나 API 키 발급은 참가자 과제가 아니다.
- **시각:** 초안의 단순 표지 구성. 장식 이미지 불필요.

### S02 오늘은 같은 흐름을 익힌 뒤 내 질문에 적용합니다

- **시간:** 13:31–13:33, 2분.

- **발표 노트:** 1부는 조건과 근거를 읽는 방법을 함께 익힌다. 2부는 A–E 중 한 질문을 선택해 무엇을 비교할지 스스로 판단한다. 16시 종료.
- **시각:** 일정표. 캡처된 공식 오후 일정과 시각 일치.

### S03 브리핑에 남길 것은 답과 확인 경로입니다

- **시간:** 13:33–13:35, 2분.
- **화면 문안:** 확인한 사실 2개 / 아직 근거가 부족한 해석 1개 / 후속 취재 질문 2개 / 데스크 확인과 수정 초안.
- **발표 노트:** “어떤 숫자가 있느냐”에 더해 대상·기간·단위·원문 위치를 남긴다. 자료가 부족하다고 설명하고 멈추는 것도 정상적인 결과다. 실습 완료와 기사 사용 승인은 다르다.
- **시각:** 본문 2열. 출처 확인과 사람 판단을 각각 강조.

### S04 OpenDART는 기업이 제출한 공시를 확인하는 출발점입니다

- **시간:** 13:35–13:38, 3분.
- **화면 문안:** 공시 목록과 원문 / 재무제표와 주요 계정 / 임원·직원·보수 정보. 질문: “매출 구성이 바뀌었나?”, “같은 기준의 보수인가?”
- **발표 노트:** 공시 접수일과 사업연도는 다르다. API는 원문의 일부 항목을 구조화하며, 정정 공시와 연결·별도·당기·누적·단위를 확인해야 한다. 공식 시스템에서 받았다는 사실만으로 기업의 주장과 해석이 검증되는 것은 아니다. 원문 다운로드도 API로 가능하지만 의미 대조가 자동으로 끝나지는 않는다.
- **시각:** 공시 → 구조화된 항목 → 원문 확인의 간단한 흐름. [공식 출처 O1–O3](SLIDE_SOURCES.md).

### S05 KOSIS는 같은 정의로 지역과 시점을 비교하게 합니다

- **시간:** 13:38–13:41, 3분.
- **화면 문안:** 통계표·항목·분류·시점 / 목록·자료·설명 API / 고용·출생·이동·물가 비교.
- **발표 노트:** 기업 한 건의 공시와 달리 통계는 여러 차원이 만나는 셀이다. 지역·연령·주기가 맞아야 비교할 수 있다. 없는 월간·지역·연령 조합을 AI가 만들어 줄 수 없으며 잠정치, 행정구역, 가중치와 개편 시점을 확인한다. 국가 집계와 지역 단순 평균도 다르다.
- **시각:** ‘지역 × 연령 × 시점 → 값과 단위’ 도식 또는 작은 표. [공식 출처 K1](SLIDE_SOURCES.md).

### S06 두 자료원은 원문과 계산을 함께 가르치기 좋습니다

- **시간:** 13:41–13:43, 2분.
- **화면 문안:** 기업과 사회 현상을 함께 다룸 / 공식 식별자·단위·기간으로 대조 가능 / 반복 취재 질문에 적용 / 자료만으로 원인은 설명되지 않음.
- **발표 노트:** 선정은 교육·개발 목적에 따른 판단이다. 모든 취재 질문을 두 API로 해결한다는 뜻은 아니다. 단순 가격·기사 검색이나 비공개 기업 정보, 임의 자료 간 인과분석은 별도 설계가 필요하다.
- **시각:** 두 열 비교. OpenDART의 ‘보고서·법인’과 KOSIS의 ‘통계표·모집단’을 대비.

### S07 화면과 서버는 서로 다른 일을 맡습니다

- **시간:** 13:43–13:45, 2분.
- **화면 문안:** 화면은 입력·승인·검토 / 서버는 키·조회·계산·검증 / 개발은 두 프로세스 / 배포는 Cloud Run 한 서비스.
- **발표 노트:** React·TypeScript·Vite로 화면을 만들고 Python·FastAPI로 데이터 처리와 AI 호출을 만든다. 역할은 나누되 배포 서비스 수를 줄였다. 브라우저에 API 키를 넣지 않고 서버에서 공통 검증을 강제한다. 웹 화면은 브라우저에서 실행되며 Cloud Run이 정적 파일과 API를 함께 제공한다.
- **시각:** [01 구성도](diagrams/01_architecture.svg). 출처: ADR 0001과 현재 패키지 정의.

### S08 Gemini는 계획과 설명을 맡고 코드는 계산을 맡습니다

- **시간:** 13:45–13:48, 3분.
- **화면 문안:** Gemini 질문 해석 → 서버의 지원 범위 검사 → 사람 승인 → 도구·코드 계산 → Gemini 브리핑 → 출력 검사.
- **발표 노트:** 하나의 조정 흐름이 허용된 도구를 호출한다. 모델이 임의 URL·통계표·프로그램을 실행하는 구조가 아니다. 수치와 순위는 Python 코드가 만들며, 모델은 근거 번호와 숫자 슬롯으로 설명한다. 슬롯 검사는 임의 숫자 삽입을 줄이지만 인과관계나 문장 의미까지 완전 검증하지는 못한다.
- **시각:** 구성도에서 서버와 Gemini 부분 확대. `{{F1.value}}` 한 줄만 설명하고 전체 계약은 X02로 보낸다.

### S09 승인과 사람 검토가 전체 흐름을 연결합니다

- **시간:** 13:48–13:50, 2분.
- **화면 문안:** 01 질문 → 02 계획·승인 → 조회·계산·브리핑 → 03 응답 비교 → 비교표 → 04 근거 → 05 사람 검토.
- **발표 노트:** 화면 순서와 실행 순서는 조금 다르다. 승인 후 근거 브리핑이 먼저 생성되며, 일반 응답은 별도 버튼으로 호출한다. 비교표·근거·검토는 응답을 읽는 단계이지 각각 Gemini를 새로 호출하는 단계가 아니다. 실행 기록은 내부 사고 과정이 아니다.
- **시각:** [02 파이프라인](diagrams/02_pipeline.svg).

## 실습 1 13시 50분부터 14시 50분

### S10 공통 질문으로 조건과 근거를 함께 확인합니다

- **시간:** 13:50–13:55, 5분. 설명·접속 2분, 조작 3분.

- **발표 노트:** 주소·접근코드는 운영자가 별도로 안내한다. 본편 파일에 접근코드를 넣지 않는다. 제공 종료 시점은 화면에서 확인한다. 공동 실습의 기준은 2021~2025년·15~29세·연간 고용률이지만 화면의 현재 제공 범위와 맞는지 먼저 확인한다.
- **시각:** 촬영 C01, 질문 영역만 확대.

### S11 최근과 청년이라는 표현을 조건으로 바꿉니다

- **발표 노트:** Gemini의 제안이 질문 의도와 맞는지 참가자가 말로 설명한다. 모호하면 확인 질문에 답한다. 앱이 지원하지 않는 연령·주기를 다른 값으로 자동 대체했다고 오해하지 않도록 한다.
- **시각:** 촬영 C02, 제안 조건과 안내 문구.

### S12 승인한 조건이 결과의 기준이 됩니다

- **시간:** 14:03–14:13, 10분. 설명 2분, 조작·대기·확인 8분.
- **화면 문안:** 대상·지표·기간·비교 기준 확인 / 이 조건으로 조회 / 승인 조건과 결과 조건 대조.
- **발표 노트:** 조건을 수정한 표시를 확인하고 승인한다. 승인 전에는 수치와 브리핑을 보여주지 않는다. 대기 중 반복 클릭하지 않는다. 질문이나 조건을 바꾸면 결과와 검토가 초기화된다.
- **시각:** 촬영 C03. 호출 중 화면은 성공 결과처럼 정지 화면을 꾸미지 않는다.

### S13 한 문장을 원문까지 따라갑니다

- **시간:** 14:13–14:20, 7분. 안내 1분, 원문 대조 6분.
- **화면 문안:** 브리핑의 근거 번호 → 04의 값·단위·식 → 공식 원문 / 대상과 시점을 동일하게 맞추기.
- **발표 노트:** 원문 표가 열렸다고 끝내지 말고 같은 연령·기간·지역·단위인지 확인한다. `%`와 `%p`의 차이는 X05를 필요할 때만 연다. 원문 링크·조회 시각은 모델이 지어내는 값이 아니라 서버가 연결한다.
- **시각:** 촬영 C06. 근거 행 한 개를 크게 보여준다.

### S14 같은 질문에도 받은 근거에 따라 답이 달라집니다

- **시간:** 14:20–14:27, 7분. 설명 2분, 비교 5분.
- **화면 문안:** 실제 일반 모델 응답 비교하기 / 유창함·확인 가능한 수치·출처·한계의 네 관점.
- **발표 노트:** 두 응답의 모델이 같아도 역할과 입력·출력 제약이 다르다. 일반 응답도 맞을 수 있고 모른다고 답할 수 있다. 특정 챗봇 제품 전체의 성능 비교나 엄밀한 단일 변수 실험으로 소개하지 않는다.
- **시각:** 촬영 C04, 나란히 나온 두 응답. 긴 본문 전체 대신 비교할 문단만 사용.

### S15 비교 버튼은 무엇을 모델에 보냈을까요

- **시간:** 14:27–14:32, 5분. 설명 2분, 펼쳐 읽기 3분.
- **화면 문안:** 질문·승인 조건은 공통 / 일반 응답은 도구와 공식 근거 없음 / 근거 브리핑에는 계산한 사실과 한계 추가.
- **발표 노트:** ‘일반 응답에 전달한 질문·조건·지시문’을 펼친다. 시스템 지시문과 사용자 메시지는 API의 서로 다른 입력이다. `approved_conditions`는 앱의 약속이며 Gemini 표준 명령이 아니다. `tool: prices`라는 글자도 실행 권한이나 도구 연결을 뜻하지 않는다.
- **시각:** [03 입력 비교](diagrams/03_model_inputs.svg), 촬영 C05. 전문은 [기술 자료](SLIDE_TECHNICAL_REFERENCE.md).

### S16 조건 하나를 바꾸면 무엇을 다시 확인해야 할까요

- **시간:** 14:32–14:40, 8분. 안내 1분, 재조회·대조 7분.
- **화면 문안:** 다른 조건은 유지 / 비교 기준 또는 지원 연령 하나만 변경 / 재승인 / 단위와 해석 비교.
- **발표 노트:** 증감 폭과 증감률 변경을 우선 예제로 삼는다. 연령 변경은 해당 표에서 지원하는 선택지를 사용한다. 서로 다른 조건의 결과를 직접 빼서 ‘효과’라고 쓰지 않는다. 다시 조회하기 전에 보존할 기록을 내려받는다.
- **시각:** 직전·이번 승인 조건 비교 화면 또는 두 조건의 간단한 표.

### S17 대기와 자료 부족도 실습 결과입니다

- **발표 노트:** 호출 한도 도달 시 앱 대기열로 들어가지만 접수 한계·기한을 넘으면 실패할 수 있다. 무제한 대기는 아니다. 실제 과부하를 일부러 만들지 않는다. 저장 자료 전환은 선택·승인이 필요하며, 저장 원자료만으로 Gemini 장애를 해결하지 못한다.
- **시각:** 대기 문구는 ‘설명 예시’로 표기하거나 실제 캡처. X08에서 상세 행동 안내.

## 선택 부록

### X01 실제 기술 스택과 배포

React 18·TypeScript·Vite / Python 3.12·FastAPI·Pydantic·httpx / google-genai SDK / 단일 EventService / Cloud Build·Artifact Registry·Cloud Run·Secret Manager. 로컬 두 프로세스와 stage 단일 컨테이너를 구분한다. 코드에 Vertex AI 지원 경로가 있다는 이유로 실제 운영 인증 방식을 단정하지 않는다. API 키·개인 계정·접근코드·프로젝트 식별자는 싣지 않는다.

### X02 시스템 지시문과 사용자 메시지

[기술 설명](SLIDE_TECHNICAL_REFERENCE.md)의 표와 코드 발췌를 사용한다. `system_instruction`, `contents`의 user JSON 문자열, `response_json_schema`를 구분한다. 스키마는 형식을 검사하며 내용의 진실성까지 보장하지 않는다.

### X03 숫자와 근거 인용을 검증하는 방법

서버 `facts` → `{{F1.value}}` 등 슬롯을 사용한 JSON 초안 → 근거 ID·슬롯·직접 숫자 검사 → 신뢰된 값 치환 → UI의 원문 링크. 출처 URL·조회 시각은 현재 브리핑 facts 입력에서 제외하고 UI가 원래 근거와 연결한다. 의미 오류·누락·편향은 사람 검토가 남는다.

### X04 A부터 E까지의 제공 범위

A 2005-01~2026-07 분석, 전년 비교용 앞 12개월 확보 / B 2023~2025·20~34세·경북 시군 상세 / C 2025-09와 2026-09·458품목·2022 가중치 / D NAVER·카카오 2025 연간 공시 법인 / E 동일 두 회사 2021~2025. [자료 구성](../INVESTIGATION_DATA.md)을 기준으로 하며, 촬영 직전 카탈로그와 재대조한다.

### X05 비교 기준이 다른 숫자는 바로 합칠 수 없습니다

%와 %p / 인원과 인구 대비 비율 / 당기와 누적 / 연결과 별도 / 공시 접수일과 사업연도. 숫자를 새로 만들지 말고 현재 공식 근거 한 행을 사용한다. %p = 종료 비율−시작 비율, 증감률 = (종료값−시작값)/시작값×100. 시작값 0·적자 전환·결측은 별도 처리가 필요하다.

### X06 D와 E의 원문 대조 사례

D 직원 합계의 공식 평균과 대표이사 개인 보수 구성을 확인한다. E 카카오 정정 후 표와 NAVER의 다음 해 보고서 전기 비교액을 사용한 이유를 보여준다. 해당 숫자는 [자료 구성 문서](../INVESTIGATION_DATA.md)의 접수번호·표 위치와 함께 옮긴다. ‘API가 원문을 제공하지 못한다’가 아니라 ‘원문 제공 후 의미·정의·분류 대조가 남는다’고 설명한다.

### X07 확장 기술은 서로 다른 층의 선택지입니다

직접 구현은 실행 흐름 통제, MCP는 도구 연결 규약, Antigravity IDE는 개발 환경, ADK·LangGraph는 실행 흐름을 만드는 프레임워크에 해당한다. Antigravity SDK는 IDE와 별도의 런타임 선택지다. 반드시 최신 공식 문서의 제공 범위로 구분한다. 자세한 비교와 뉴스룸 역할은 [기술 설명](SLIDE_TECHNICAL_REFERENCE.md).

### X08 대기와 오류가 나왔을 때

대기는 자동 진행·중복 클릭 금지 / 입력을 바꾸기 전 기록 저장 / 요청 취소는 이미 전송한 호출의 비용 취소를 보장하지 않음 / 문의 번호 전달 / 명시적 저장 자료 선택과 재승인. 앱 기본 대기·전체 시간·접수 상한은 운영 설정을 확인한 뒤 숫자를 넣는다. D/E 저장 원자료는 Gemini 중단의 완전한 대체 수단이 아니다. 행사 시작·중단·재개 판단은 운영자 가이드에 따른다.
