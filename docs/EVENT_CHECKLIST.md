**상태: 미실행.** 이 파일은 빈 양식입니다. 과거 테스트 통과를 행사 확인으로 체크하지 않습니다.
[운영자 가이드](OPERATOR_GUIDE.md)의 절차를 수행한 담당자가 시각과 근거를 적습니다.
예: Git에서 제외되는 `.cache/event-checklist-YYYYMMDD.md`에 새 사본을 만들거나 주최 측의
제한된 문서 공간을 사용합니다. 기존 기록을 덮어쓰지 않습니다.
키·접근코드·인증 헤더·개인 취재 질문·원문 응답은 기록하지 않습니다.

## 전날 준비

- [ ] 실제 행사는 기관/주최 측 자원·자격증명으로 전환했다. 개인 stage 확인과 구분했다.
- [ ] 사용할 모드·공급자별 검증 기록과 지원 질문 범위를 확인했다.
- [ ] 행사 조건의 부하·동시 입장·행사장 브라우저/네트워크를 확인했다.
- [ ] 실제 모드를 쓸 경우 stage 실제 연결·할당량·비용 확인을 완료했다.
      사용하지 않으면 실행 사본에 ‘해당 없음: 모의 규칙+mock/저장 자료’를 적는다.
- [ ] 공유 코드 전달 경로·기술 담당자 권한·비용 알림 수신·로그 보관 기한을 정했다.
- [ ] 장애 전환을 연습하고 서버/인터넷 장애용 진행자 설명 자료를 준비했다.

근거/확인 시각/담당자: 미기록

## 시작 30분 전

- [ ] 대상 URL·리비전·운영 모드가 검증한 대상과 같다.
- [ ] 새 탭 입장 화면과 코드 보호가 정상이다. `/api/v1/access`가 required/available 모두 true다.
- [ ] 코드 없는 실습 API 요청이 거절되고 정상 코드로 입장할 수 있다.
- [ ] 운영 상태를 갱신하여 확인 시각·공급자 설정·두 저장 파일·프로세스 한도를 읽었다.
- [ ] 운영 상태의 ‘설정상 허용’과 실제 연결 확인을 구분했다.
- [ ] 두 질문에서 승인 전 결과 비노출 → 조건 수정 → 명시적 승인 → 승인 조건 일치를 확인했다.
- [ ] 자료 모드·출처·단위·원래 조회 시각·계산식·한계·검토 0/4를 확인했다.
- [ ] 검토 1/4 후 조건 변경 시 숨김, 재승인 시 0/4 초기화를 확인했다.
- [ ] 요청 ID 한 건과 서버 앱 로그를 대조했다.
- [ ] 참가자에게 현재 자료 모드·지원 범위·장애 대응·기사 사용 승인이 아님을 안내했다.

시작 결정: **미정** / 허용 모드: 미정 / 시각·결정자·근거: 미기록

확인이 실패하면 해당 모드의 시작을 보류한다. 모드 변경도 확인·결정·참가자 안내를 남긴다.

| 항목 | 기록 |
|---|---|

| HTTP 상태·오류 코드·문의용 요청 ID | 미기록 — 없는 값은 ‘없음’ |
| 반복 조회 중지·참가자 안내 시각 | 미기록 |

- [ ] 이전 결과 사용과 반복 조회를 멈추고 오류/요청 ID를 기록했다.
- [ ] 저장 자료 전환 시 원래 시각·지원 범위를 확인하고 별도로 승인했다.
- [ ] 저장 자료 성공을 실제 공급자 복구나 최신 조회로 설명하지 않았다.
- [ ] 복구 뒤 입장·승인 조건·출처·검토 초기화를 확인했다.
- [ ] 실패한 범위를 해소한 근거와 주최 측 재개 결정을 기록했다.

## 종료 후

- [ ] 참가자에게 ‘실습 나가기’를 안내했다. 서버 접근 종료와 별개임을 확인했다.
- [ ] 종료 후 공개 범위를 적용했다. 유지 시 이유·기한·책임자를 기록했다.
- [ ] 공개 접근을 닫는 경우 Invoker IAM 검사 활성화·allUsers invoker 제거를 모두 확인했다.
- [ ] 기존 서비스/태그 URL에 인증 없는 새 요청이 거절되는지 확인했다.
      공개 유지 결정이면 위 두 항목을 실행 사본에 ‘해당 없음: 공개 유지’로 기록한다.
- [ ] 코드 유출이 있으면 공개 차단·코드 교체·이전 리비전 접근 점검을 완료했다.
      유출이 없으면 ‘해당 없음’으로 기록한다. Secret 비활성화만으로 종료를 판단하지 않는다.
- [ ] 비용·알림 수신·남은 자원·로그 보관·Secret/자원 정리 담당자와 일정을 확인했다.
- [ ] 롤백에 필요한 이미지·Secret 버전과 기관 이전 필요성을 확인한 뒤 폐기 일정을 정했다.
