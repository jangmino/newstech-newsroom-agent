## M2 — Live providers

계산 기초는 M1 비교 화면 다음에 작은 mock 수치 자료로 먼저 구현합니다. 이를 M1의
조건 변경에 따른 결과 비교에 사용한 뒤 실제 공급자를 연결합니다. 구현 순서는
[개발 하네스](CODEX_HARNESS.md#2-한-번에-하나의-제품-단위)를 따릅니다.

- [x] M2 준비: 기존 청년 고용 질문의 가상 수치·증감 폭/률·순위·단위·누락값 검증
- [x] M2 준비: 질문 구조화 어댑터·출력 계약·모호성·오류 검증 (mock)
- [x] Gemini 구조화 질문 계획 연결 코드·모의 전송 검증 (기본 비활성화)
- [x] Gemini 로컬 API 키·모델 접근과 두 질문의 최소 해석 확인 (모호/명확 각 2건, 실제 4회)
- [x] OpenDART 삼성전자 연간 연결 매출액 어댑터·정규화·모의 전송 검증
- [x] OpenDART 두 연도 실제 응답과 공시 원문 대조
- [x] OpenDART 기업·재무 시나리오 (삼성전자 2022·2024 연결 매출액·증감 폭/률)
- [x] KOSIS 공식 통계표·차원·단위 계약 (15~29세 고용률, 17개 시도, 2020~2024년)
- [x] KOSIS 청년고용 시나리오 (승인 후 15~29세 고용률 조회·증감 폭/률·시도 순위·근거·검토)
- [x] 실제 공급자 자료의 정규화·단위·누락값 검증 (승인 실행에 적용, 자동 검증은 오프라인)
- [x] 검증된 fixture (OpenDART 원문 대조, KOSIS API 메타데이터·85개 셀 대조; 사람 검토 별도)

현재 위치는 **M1·한정된 M2 완료 + M3 운영 준비 진행 중**입니다.
OpenDART와 KOSIS 모두 실제 자료 선택·조건 승인 뒤에만 조회합니다. 자동 테스트는
계속 모의 전송만 사용합니다. [OpenDART 기록](OPENDART_SMOKE_TEST.md),
[KOSIS 기록](KOSIS_SMOKE_TEST.md)과 각 자료 계약에 지원 범위·확인 한계를 남깁니다.
다른 기업·지표·기간·연령까지 지원하는 것은 아니며 넓은 Gemini 품질 검증도 남아 있습니다.
공공자료의 프로세스 내부 캐시·동일 요청 합치기를 완료했습니다. 재사용 표시와 원래 조회
시각·기한을 유지합니다. 자료원별 HTTP 호출·동시 실행 제한과 한국어 429 안내도 적용했습니다.
공식 저장 자료의 명시적 선택·범위 안내·별도 재승인도 완료했습니다.
[저장 자료 계약·확인 방법](SNAPSHOT_FALLBACK.md)을 따릅니다. 계정·DB 없는 공유 접근코드도
완료했습니다. [접근 계약·확인 방법](WORKSHOP_ACCESS.md)을 따릅니다.
요청 ID와 허용 필드만 기록하는 [구조화 로그](REQUEST_LOGGING.md)도 완료했습니다.
[읽기 전용 실습 운영 상태 화면](OPERATIONS_STATUS.md)도 완료했습니다.
기관 계정이 준비되기 전 사용자 승인으로 [개인 임시 stage 배포](STAGE_SMOKE_TEST.md)를
완료했습니다. [30명 단기 API 부하 시험](STAGE_LOAD_TEST.md)도 mock/저장 자료로 통과했습니다.
[장애·저장 자료 전환 리허설](FALLBACK_REHEARSAL.md)도 로컬 모의 장애와 stage 비활성 경로로
완료했습니다. [운영자 가이드](OPERATOR_GUIDE.md)와 [미실행 행사 점검표](EVENT_CHECKLIST.md)도
작성했습니다. 다음 최소 단위는 **stage Gemini 질문 해석의 Secret 연결·소규모 실제 확인**입니다.
공공자료는 mock을 유지하며 OpenDART/KOSIS stage 연결은 이후 공급자별로 확인합니다.

## M3 — Event readiness

- [x] 공공자료의 프로세스 내부 캐시·동일 요청 합치기·재사용 메타데이터
- [x] 공공자료의 프로세스 내부 호출·동시 실행 제한
- [x] 명시적 snapshot fallback (저장 자료 표시·선택·재승인)
- [x] 행사용 공유 접근코드·입장/나가기·요청별 검사
- [x] 요청 ID·구조화 로그·오류 문의 번호
- [x] 읽기 전용 실습 운영 상태 화면 (설정·저장 파일·프로세스 한도, 외부 호출 없음)
- [x] 개인 임시 stage 배포 (전용 프로젝트·Secret Manager·비용 알림·mock/저장 자료)
- [ ] 기관 stage로 재배포·기관 키 전환
- [ ] stage 실제 공급자 Secret 연결·소규모 live 확인
- [x] 30명 단기 API 부하 시험 (mock/저장 자료, 766회 요청)
- [ ] 행사 조건의 부하 확인 (live·지속 사용·동시 최초 입장·행사장 브라우저)
- [x] 장애·snapshot fallback 리허설 (로컬 모의 장애·stage 비활성 경로, 실제 공급자 장애 제외)
- [x] 운영자 가이드·시작/중단/종료 점검표 (절차 작성, 실제 행사 운영 기록은 별도)

Gemini와 공공자료에는 각각 프로세스 내부 한도를 적용했습니다. 여러 인스턴스를 포함한 행사
전체의 제한·인스턴스 간 정책·부하 검증은 위 항목의 남은 범위입니다.
[캐시 검증](PUBLIC_DATA_CACHE.md)의 30개 동시 작업 검사는 행사 부하 시험을 대신하지 않습니다.
[호출 제한 계약·검증](PUBLIC_DATA_LIMITS.md)에 HTTP 계산 단위와 적용 범위를 기록합니다.
stage는 프론트엔드 정적 빌드와 FastAPI를 단일 Cloud Run 서비스로 제공합니다.
현재 개인 임시 stage는 [ADR 0015](decisions/0015-temporary-personal-stage.md)의 승인된 예외입니다.
행사는 기관/주최 측 프로젝트·자격증명과 Secret Manager로 교체한 뒤 진행합니다.
