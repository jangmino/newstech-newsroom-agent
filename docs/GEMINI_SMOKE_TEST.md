# Gemini 실제 질문 해석 확인 (M2)

기존 두 질문의 계정·모델 접근과 최소 해석 품질을 수동으로 확인합니다.
이 절차는 `make test`나 CI에 포함하지 않습니다. 자동 테스트는 항상 모의 전송을 사용합니다.
이 확인 당시 Gemini는 질문 조건만 해석하며 자료 조회·계산 입력값·브리핑은 mock이었습니다.
후속으로 선택형 [OpenDART 실제 조회](OPENDART_SMOKE_TEST.md)를 별도 확인했습니다.

## 시작 조건

1. 운영자가 로컬 `.env`에 백엔드용 `GEMINI_API_KEY`를 설정합니다. 키를 채팅이나 화면에
   붙여 넣지 않으며, 파일 내용이나 원래 공급자 오류를 확인 기록에 복사하지 않습니다.
2. `LIVE_API_ENABLED=true`, `GEMINI_PLANNER_ENABLED=true`, `PUBLIC_DATA_MODE=mock`,
   `GEMINI_AUTH_MODE=api_key`를 설정하고 백엔드를 다시 시작합니다.
3. `/health`에서 `gemini_planner_enabled=true`, `public_data_mode=mock`을 확인합니다.
   이 값은 설정 확인이며 실제 인증·모델 접근 성공을 뜻하지 않습니다.
4. 화면의 ‘질문 해석 방식’에서 ‘Gemini · 실제 모델’을 선택합니다. 선택만으로 요청하지
   않으며 ‘질문 분석’ 한 번당 모델 요청이 한 번 발생합니다.

시간·출력·요청 한도와 인증 설정은 [환경 문서](ENVIRONMENTS.md#gemini-질문-해석-활성화)를
따릅니다. 기본 모델은 서버에서 관리하며 참가자 입력으로 변경하지 않습니다.

## 최대 네 번의 확인

아래 순서대로 한 번씩 분석하고 화면을 확인합니다. 오류나 예상과 다른 해석이 발생하면
다음 질문으로 넘어가지 않고 원인을 점검합니다. 자동 재시도·다른 모델로의 자동 전환은
하지 않습니다. 수정 후 재확인도 실제 요청 수에 포함하며, 이번 확인은 합계 4회 이내입니다.

| 순서 | 입력 질문 | 확인할 해석 |
|---|---|---|
| 1 | 최근 5년 동안 청년 고용이 가장 좋아진 지역은 어디인가? | KOSIS. 지표·실제 연도·비교 기준·청년 연령을 임의로 채우지 않고 한국어 확인 안내 표시 |
| 2 | 전국 시·도 청년 고용률을 2020년과 2024년 사이의 증감 폭으로 비교해줘. 연령은 15-29세, 주기는 연간이야. | 전국 시·도 / 고용률 / 2020-2024 / 증감 폭 / 15-29세 / 연간 |
| 3 | 삼성전자의 최근 실적은 악화됐는가? | OpenDART / 삼성전자. 지표·실제 연도·비교 기준·연결/별도를 임의로 채우지 않고 확인 안내 표시 |
| 4 | 삼성전자의 2022년과 2024년 연간 연결재무제표 매출액을 증감률로 비교해줘. | 삼성전자 / 매출액 / 2022-2024 / 증감률 / 연결 / 연간 |

모호한 질문의 대상 범위도 명시되지 않았다면 비워둘 수 있습니다. 주기는 기존 실습의
연간 기본값을 허용합니다. 모든 사례에서 Gemini 해석 방식·모델 이름과 mock 자료 표시를
구분하고, 승인 전에는 근거·브리핑·검토 체크가 없어야 합니다.

## 승인과 검토 확인 (모델 추가 호출 없음)

명확한 질문의 계획이 도착한 뒤 다음을 수동 확인합니다.

1. 비교 기준을 한 번 수정하고 ‘수정됨’ 표시를 확인합니다. 아직 결과는 없어야 합니다.
2. ‘이 조건으로 조회’를 누르고 최종 조회 조건이 수정·승인한 값과 같은지 확인합니다.
3. 청년 고용은 가상 숫자·계산식·단위를, 기업 실적은 수치 없는 모의 조회 설계를 확인합니다.
4. 사람 검토 항목을 체크하고 질문이나 해석 방식을 바꾸면 결과와 검토가 사라지는지 확인합니다.

조건 편집·승인은 Gemini를 다시 호출하지 않습니다. 기사 사용 승인이나 공식 데이터 확인으로
표현하지 않으며 `review_required` 상태를 유지합니다.

## 확인 기록

날짜, 서버 모델 이름, 실제 요청 횟수, 사례별 통과/실패/미실행, 확인한 조건과 안전한 오류
코드만 기록합니다. 모델의 원래 출력·공급자 응답·인증 헤더·키·비밀 설정은 저장하지 않습니다.
네 사례 통과는 전체 자연어 품질이나 행사 운영 준비 완료를 뜻하지 않습니다.

### 2026-09-16 확인 결과

- 로컬 API 키 인증, 모델 `gemini-3.8-flash`, 실제 질문 해석 요청 **4회**, 모두 성공.
- `.env` 내용과 키를 직접 조회·출력하지 않았습니다. 기존 설정은 백엔드가 사용했으며,
  두 활성화 값과 `PUBLIC_DATA_MODE=mock`은 이번 실행의 환경 변수로 지정했습니다.
- 사례 1: KOSIS 선택. 대상·지표·기간·비교 기준·연령은 비우고 연간만 표시했습니다.
- 사례 2: 명시한 여섯 조건과 일치했습니다. 비교 기준을 증감률로 수정해 승인한 뒤
  최종 조회 조건에도 증감률이 표시되고 가상 수치 결과가 생성됐습니다.
- 사례 3: OpenDART·삼성전자 선택. 지표·기간·비교 기준·재무제표 기준은 비웠습니다.
- 사례 4: 명시한 여섯 조건과 일치했습니다. 비교 기준을 증감 폭으로 수정해 승인한 뒤
  최종 조회 조건에도 증감 폭이 표시됐습니다. 기업 결과는 수치 없는 모의 조회 설계입니다.
- 네 계획 모두 승인 전 근거·브리핑을 표시하지 않았습니다. 수정 표시, 별도 승인,
  새 결과의 검토 0/4, 질문·해석 방식 변경 시 결과·검토 초기화를 확인했습니다.
- 실제 OpenDART·KOSIS 호출은 없었습니다. 자동 테스트는 계속 모의 전송만 사용합니다.

이는 API 키 인증과 위 네 질문의 소규모 확인입니다. Vertex 인증, 다른 표현·언어·장문,
반복 실행의 일관성, 부하·비용·행사 운영 적합성까지 확인한 결과는 아닙니다.

## mock 전환 시점

- 이번 단계: Gemini 질문 해석만 실제 호출합니다. `PUBLIC_DATA_MODE=mock`을 유지합니다.
- 다음 OpenDART 단위: 실제 재무 자료의 조회·정규화·단위·오류 처리와 승인 흐름을 검증한 뒤
  해당 시나리오에 한해 실제 자료를 허용합니다.
- 이후 KOSIS 단위: 통계표·분류·기간·단위·누락값 검증을 마친 시나리오부터 전환합니다.

이 최초 확인 당시 `/plan`·`/execute`의 `mode`는 `mock`만 받았습니다. 이후 OpenDART/KOSIS
실제 조회와 공식 저장 자료 계약을 구현했으며, 현재는 [개인 stage 통합 확인](STAGE_LIVE_TEST.md)에서
Gemini 해석과 실제 자료를 함께 사용합니다. 위 순서는 최초 연결 당시의 기록입니다.
실제 해석 확인을 마친 뒤 기본 개발 상태로 돌아가려면 두 활성화 설정을 `false`로 바꾸고
백엔드를 다시 시작합니다.
