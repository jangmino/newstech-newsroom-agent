# 읽기 전용 실습 운영 상태

M3의 운영 화면입니다. [ADR 0014](decisions/0014-read-only-operations-status.md)에 따라
실제 공급자를 호출하지 않고 현재 프로세스의 공개 설정과 패키지 저장 자료만 확인합니다.
별도 관리자 권한·운영 제어·새 환경변수는 없습니다.

## 화면에서 확인하기

1. 기존 실습 화면에 입장한 뒤 제목 아래 **실습 운영 상태 보기**를 누릅니다.
2. Gemini 질문 해석, OpenDART/KOSIS 실제 자료의 설정 상태를 확인합니다.
3. 공식 저장 자료의 파일 확인 여부·지원 범위·원래 조회 시각을 확인합니다.
4. 공공자료 캐시 설정과 Gemini·자료원별 호출 제한을 확인합니다.
5. **상태 다시 확인**은 같은 서버의 상태 API만 다시 요청합니다. 자동 갱신하지 않습니다.
   **운영 상태 닫기**를 누르면 패널의 상태와 진행 요청을 지웁니다.

질문·조건·승인 결과·비교·검토 체크는 열기·닫기·다시 확인으로 바뀌지 않습니다.
입장 전에는 보이지 않으며 상태 요청도 기존 접근코드 헤더를 사용합니다. 401 또는
접근 설정 오류에는 기존 규칙대로 전체 실습 화면을 잠그고 결과·검토를 초기화합니다.
일반 상태 오류에는 실습을 유지하고 한국어 안내와 다시 확인 버튼을 제공합니다.
진행 중 닫기·나가기·언마운트는 요청을 취소하며 늦게 도착한 응답을 무시합니다.

## API 계약

`GET /api/v1/operations`는 본문 없이 호출합니다. 접근코드가 필요한 환경에서는
`X-Workshop-Code`를 요구합니다. `Cache-Control: no-store`, `Vary: X-Workshop-Code`,
`X-Request-ID`를 반환합니다. GET 외 변경 메서드는 허용하지 않습니다.
`/health`, `/plan`, `/execute`, `/analyze`의 기존 본문 계약은 유지합니다.

| 필드 | 의미 |
|---|---|
| `checked_at` | 서버 상태를 확인한 UTC 시각; 원자료 조회 시각과 별개 |
| `external_calls_made` | 항상 `false`; 이 상태 요청에서 외부 호출하지 않음 |
| `providers.gemini/opendart/kosis` | `disabled`, `missing_configuration`, `configured` |
| `snapshots.opendart/kosis.status` | `disabled`, `unavailable`, `available` |
| `snapshots.*.metadata` | 사용 가능하면 기존 `SnapshotMetadata`, 아니면 `null`; 숫자 원자료 없음 |
| `cache` | `scope=process`, `enabled`, `ttl_seconds`, `max_entries_per_source` |
| `limits` | `scope=process`, `window_seconds=60`, 아래 두 한도 설정 |
| `limits.gemini` | `requests_per_minute`, `max_concurrent_requests` |
| `limits.public_data_per_source` | 같은 두 필드; OpenDART·KOSIS 각각에 적용 |

자료원 활성화 조건은 기존 실행 경계와 같습니다.

- Gemini: `LIVE_API_ENABLED`와 `GEMINI_PLANNER_ENABLED`. 켜져 있으면 API 키 방식의
  키 존재, 또는 Vertex 방식의 프로젝트·리전 존재를 확인합니다. ADC를 생성/탐색하지 않습니다.
- OpenDART/KOSIS: `LIVE_API_ENABLED`, `PUBLIC_DATA_MODE=live`, 각 공급자의 활성화 설정.
  켜져 있으면 해당 키 존재를 확인합니다. 다른 공급자의 설정에 의존하지 않습니다.
- 비활성화가 우선하며 비활성 공급자의 키 설정 여부를 따로 공개하지 않습니다.
- `configured`는 **설정상 허용 · 실제 연결 미확인**입니다. 유효한 키·ADC 권한·모델 접근·
  공급자 가동·남은 할당량을 보증하지 않습니다. 모의 규칙·자료는 독립적으로 사용할 수 있습니다.
- 저장 자료는 `FALLBACK_SNAPSHOT_ENABLED`가 꺼져 있으면 파일을 읽지 않습니다.
  켜져 있으면 기존 로더의 파일·SHA-256·차원·단위 검증을 거칩니다. 한 파일의 예상된 오류는
  해당 자료원만 `unavailable`로 표시합니다. 오류 원문·파일 경로는 응답하지 않습니다.

설정 객체 전체를 직렬화하지 않습니다. 키·접근코드·프로젝트·리전·모델 설정 원문·
파일 경로·환경 원문은 필드에 포함하지 않습니다. 로그에는 기존 HTTP 요청 메타데이터만
남깁니다. 출처 메타데이터 외 실제 수치·근거·브리핑은 반환하지 않습니다.

## 설정과 운영 범위

공공자료 캐시는 실제 조회 원자료에만 적용하고 Gemini·mock·snapshot에는 적용하지 않습니다.
화면의 최대 건수는 자료원별 **설정값**이며 현재 저장 건수가 아닙니다.
공공자료 한도는 HTTP 시작 기준이며 OpenDART 두 연도는 2회, KOSIS는 1회입니다.
캐시 재사용·동일 조회의 공유 대기는 공공자료 한도를 추가로 쓰지 않습니다.

캐시·호출 한도는 한 서버 프로세스에서만 적용합니다. 재시작 시 초기화하며 여러 worker·
Cloud Run 인스턴스가 공유하지 않습니다. 현재 사용량·남은 사용량·기관 할당량·요금·
행사 전체 한도를 보여 주는 화면이 아닙니다. 상태 확인은 캐시나 제한기를 생성·갱신·
초기화하지 않습니다. 설정 변경은 기존 환경 설정과 서버 재시작 절차를 따릅니다.

저장 파일 확인은 최신 자료 조회·사람 검증 완료·기사 사용 승인이 아닙니다. 저장 자료도
기존 조회 자료 선택 → 질문 분석 → 조건 확인·승인 흐름을 거쳐야 합니다.

자동 테스트는 환경 파일과 외부 네트워크를 차단합니다. 설정 조합·Vertex 설정 존재·
저장 파일 누락/손상·비활성 파일 읽기 차단·비밀정보 비노출·접근 검사·변경 메서드 거절·
공급자/캐시/제한기 비실행을 확인합니다. 화면에서는 승인 전 비노출·수동 갱신·로딩/오류·
잘못된 상태 응답·입장 헤더·접근 오류·취소/늦은 응답·기존 결과/검토 유지를 검사합니다.

로컬 브라우저에서 기존 설정의 세 공급자를 ‘설정상 허용 · 실제 연결 미확인’으로 표시하고,
두 저장 파일의 사용 가능 여부·범위·원래 시각을 확인했습니다. 모의 규칙·모의 자료로
조건 승인 전 브리핑 비노출, 승인 결과의 검토 1/4 표시가 운영 상태 열기·갱신·닫기 뒤에도
유지됨을 확인했습니다. 이 확인에서는 실제 공급자 호출이 없었습니다.
Git 추적·추가 대상 145개 파일의 비밀정보 검사에서 발견 0건이며 `.env`는 변경하지 않았고
Git 제외 상태를 확인했습니다.

2026-09-17 사용자 승인으로 [개인 임시 stage 배포](STAGE_SMOKE_TEST.md)를 완료했습니다.
[30명 단기 API 부하 시험](STAGE_LOAD_TEST.md)도 mock/저장 자료로 통과했습니다.
[장애·공식 저장 자료 전환 리허설](FALLBACK_REHEARSAL.md)도 로컬 모의 장애와 stage 비활성
경로로 완료했습니다. [운영자 가이드](OPERATOR_GUIDE.md)와 [행사 점검표](EVENT_CHECKLIST.md)에
시작 전 상태 확인·장애 대응·종료 절차를 정리했습니다. 운영 상태 화면은 읽기 전용이며
공개 접근 종료나 공급자 활성화 기능은 없습니다. 기관 환경 재배포와 기관 Secret 연결·
플랫폼 로그 정책, 여러 인스턴스의 호출 정책, 행사 조건의 부하 확인은 남아 있습니다.

현재 live 리비전의 화면은 **설정상 허용 · 실제 연결 미확인**을 표시합니다. 별도 수동
실제 연결 확인이 성공해도 이 읽기 전용 API가 공급자 연결을 검사하는 것으로 바꾸지 않습니다.
개인 live 검증은 계속 진행하고 기관 계정·환경 전환은 마지막 인계 단계로 미룹니다.
# 2부 브리핑 설정 추가

`/api/v1/operations`의 `briefing`은 `disabled|missing_configuration|configured` 중 하나입니다.
`GEMINI_BRIEFING_ENABLED`와 전역 live 허용·인증 설정만 검사하며 실제 호출은 없습니다.
화면에 ‘Gemini 브리핑 작성’을 표시합니다. 기존 `providers` 세 항목과 한도는 유지합니다.
