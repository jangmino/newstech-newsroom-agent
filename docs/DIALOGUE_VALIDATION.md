# 자유 질문 확인 질답 검증

검증일: 2026-09-30. 기준: [ADR 0020](decisions/0020-event-planning-dialogue.md).

## 기능

- 자료원 미정·중요 조건 미확정·지원 불가 상태에서는 승인 폼 대신 확인 질문을 표시한다.
  선택 답변과 직접 답변을 지원하며 자료원 미정에 고용 지표·기간을 넣지 않는다.
- 지원 불가 이유와 다음 질문을 함께 보여준다. 연령 등 지원 범위를 바꿀 때 참가자의
  답변을 요구하며, ‘전체’로 잘못 표현한 연령 대안을 피하도록 모델에 명시한다.
- 원 질문, 마지막 편집 조건, 최대 8회 확인 답변·자연어 수정 이력을 계획 요청에 전달한다.
  실패·취소는 입력을 유지하고 완료 이력을 늘리지 않는다. 늦은 응답은 무시한다.
- 1부 ‘예제로 흐름 익히기’와 2부 ‘내 질문으로 조사하기’는 같은 조사·검토 도구다.
  2부는 빈 입력란에서 시작한다. 자료 조회·AI 브리핑·사람 검토는 최종 승인 뒤에 표시한다.
- 기사 초안·자동 발행·임의 웹 검색·자료원 결합·DB·인증은 추가하지 않았다.

`UV_OFFLINE=1 make check` 통과: 백엔드 846개, 프론트엔드 211개 테스트,
Ruff·TypeScript·Vite·Python 배포 패키지 빌드 성공. 기존 deprecation 경고 2개.
자동 테스트는 모의 모델·모의 전송·공식 저장 자료만 사용한다.
4개 공식 저장 사례의 원래 조건·시각·브리핑 재생과 승인 거부 회귀를 포함한다.

로컬 Chrome에서 삼성전자 질문 → 실적/공시 선택 → 재무 조건 폼을 확인했다.
고용 지표·비활성 조회 버튼이 질답에 나타나지 않고, 재무 폼에 맞는 지표·입력 스타일과
활성 조회 버튼이 표시된다. 이 브라우저 확인의 모델은 오프라인 대역이다.
강의 계획과 한 장짜리 사용 가이드에 새 이름·질답 절차를 반영하고 Word 렌더를 확인했다.

## 실제 모델과 자료 연결

첫 후보 `dialoguea`의 Gemini 계획 9회에서 다음을 확인했다.

| 사례 | 결과 |
|---|---|
| 삼성전자의 최근 재무 이슈? | 실적 변화/투자·지분·소송 공시 확인 질문, 미정 지표·기간은 비어 있음 |
| 실적 변화와 2024~2025 연간 조건으로 답변 | 삼성전자 공식 코드 확인 후 ready |
| 두 번째 답변으로 2025-Q2~2026-Q2 당기 전년 동기 비교 | 원 회사·지표를 유지하고 분기 조건으로 변경 |
| 명확한 현대차 재무·NAVER/카카오 공시·서울/전국 고용 | 세 질문 모두 바로 ready |
| 기업 실적과 고용 인과관계 기사 요청 | unsupported, 조사 방향 선택 안내 |
| 위 요청을 삼성전자 연간 실적만으로 명시적으로 좁힘 | ready로 전환 |
| 서울 15~34세 월간 고용률 | unsupported, 대안 선택 안내 |

계획 응답 9회는 약 2.15~7.33초. 수치·브리핑은 계획 응답에 없었다.
미리 정한 삼성전자 2024~2025 연결 매출액·영업이익을 별도 승인하여 자료·브리핑까지
5.50초에 확인했다. 승인 조건과 결과 조건이 같았다. API·정규화·계산 계약은 변경하지
않았으며, 이번 작업에서 새로운 공식 원문 표본 대조를 수행했다고 주장하지 않는다.
원문 대조의 기존 증거는 [행사 검증 기록](EVENT_VALIDATION.md)을 따른다.

## 오류 대응과 KOSIS 연결

첫 후보의 새 대전 20~29세 2021~2025 고용률 조회는 20.03초에 `kosis_timeout`으로
실패했다(요청 번호 `2e4a362c-63aa-49ec-937d-de34e0f7e965`). 안전한 진단 로그는
`provider_transport_timeout`, `phase=connect`였다. 이는 DNS·TCP 연결 단계이며 두 원인을
분리하지 못한다. TLS·응답 본문 단계의 실패로 단정할 수 없다.

같은 조건을 당시 공개 `queuee` 인스턴스에서 1회 조회하여 15.83초에 자료·브리핑을
확인했다. 이 차이는 기존 인스턴스별 간헐 연결 문제의 재현이며 질답 로직으로 고친
것이 아니다. 인증·키·TLS 검증·타임아웃·네트워크 토폴로지는 바꾸지 않았다.
첫 후보 결과를 전체 성공으로 기록하지 않는다. 최종 후보 확인은 아래에 별도 기록한다.

오프라인에서는 지원 불가 이유 표시, 모호한 회사 후보, 없는 연령 유지, 질답 상한,
오류 후 같은 답변 재시도, 취소 후 입력 유지, 원 질문 변경 뒤 늦은 응답 차단,
공식 저장 사례로 전환 후 재승인을 검증했다. 기존 요청 대기·시간 상한은 유지한다.

## 행사 운영

최종 `dialogueb`에서 삼성전자 확인 질문 → 답변 후 ready, 지원 불가 이유·정확한 연령
대안 표시를 실제 계획 3회로 재확인했다(2.30~5.10초). 새 대전 고용 조건도 실제 KOSIS
1회·Gemini 브리핑 1회로 4.24초에 성공했다. 후보와 공개 전환 후 각각 공식 저장 사례
4개의 조회·일반 응답 스트림 8개, 승인 거부·접근 보호·health 검사를 통과했다.
공개 주소에서 삼성전자 질문 계획 1회로 확인 질문과 두 선택지를 다시 확인했다.
정적 JS/CSS는 로컬 검증 빌드와 바이트가 일치하며 진행 요청은 0이었다.

최종 공개 리비전은 `newsroom-stage-dialogueb-20260930`이며 트래픽 100%, 임시 태그 없음.
이미지는 `sha256:8adb8d11702595bfdfba1a71bc84d6783d0637647c6a0b85f79ba81dc0140f74`.
빌드 입력 97개가 최종 소스와 일치한다. 전체 수동 확인의 실제 호출 시작 수는
Gemini 16회, OpenDART 4회, KOSIS 3회(실패 1회 포함)다. 저장 재생은 외부 호출이 없다.
처음 실패와 최종 성공은 [집계 기록](validation/event-dialogue-20260930.json)에 함께 보존했다.
KOSIS가 이번에도 새 인스턴스에서 정상인 것을 확인했지만 근본 연결 원인 해결은 아니다.

`git diff --check`와 Git 대상 파일의 실제 비밀 값·자격증명 파일 혼입 검사를 통과했다.
새로고침 전 필요한 검토 기록을 내려받고, 새 화면에서 접근코드를 다시 입력한다.

이번 변경은 30명 부하 시험을 다시 수행한 것이 아니다. 질답 한 번당 Gemini 계획
호출이 1회 추가되며 기존 대기·분당·
동시 한도를 공유한다. 행사장 네트워크·Windows 저장·실제 30명·운영 책임 인계는
여전히 별도 확인 대상이다. KOSIS는 행사 직전 새 조건 연결 확인과 공식 저장 자료
전환 안내를 유지한다.
