# 질문 구조화 계약 · 선택형 Gemini 해석

M2의 질문 해석을 공급자 어댑터로 분리하고 Gemini 연결 코드를 추가한 단위입니다.
기본 해석기는 `MockQuestionPlanner`이며 외부 클라이언트나 네트워크를 사용하지 않습니다.
운영자가 서버의 두 활성화 설정을 켜고 참가자가 Gemini를 선택해야 모델을 호출할 수 있습니다.
자동 테스트에서는 모의 HTTP 전송만 사용합니다. 2026-09-16 수동으로 실제 모델의
네 질문 해석을 확인했으며, [확인 기록](GEMINI_SMOKE_TEST.md)에 범위와 한계를 남깁니다.
대상 질문은 기존 청년 고용·삼성전자 실적 두 유형입니다.

## 흐름과 책임

```text
/plan → QuestionPlanner.interpret(question) → 신뢰하지 않는 JSON 문자열
      → 형식·자료원·지원 조건 검증 → 편집 가능한 계획과 한국어 확인 안내
      → 참가자 수정·승인 → /execute → 승인 조건 검증·선택 모드의 자료 조회/계산·검토용 브리핑
```

- `providers/planner.py`: 해석기 인터페이스와 `PlannerUnavailable` 오류 경계.
- `providers/mock_planner.py`: 기존 명시적 문자열 해석. 모르는 값은 `null`,
  복수 후보는 `uncertain_fields`로 표시합니다. 연간 기본값은 기존 실습 규칙입니다.
- `providers/gemini_planner.py`: JSON Schema 요청·타임아웃·단일 호출·사용 한도·
  안전한 오류 변환. 모델에는 도구·검색·조회·승인 권한을 주지 않습니다.
- `planning.py`: 내부 `StructuredQuestion` 계약과 검증, 공개 `PlanResponse` 생성.
- `conditions.py`: 공통 선택값·기간 검증·두 질문 유형의 결정론적 자료원 범위 검사.
- `main.py`: 요청의 해석 방식에 따라 어댑터를 주입하고, 서버 설정으로 Gemini를 제한합니다.

`/execute`는 해석기를 다시 호출하지 않습니다. 승인한 조건과 질문의 자료원 범위를
결정론적으로 검증하고 승인 값을 그대로 사용합니다. 계획을 서버에 저장하지 않으며
계획 토큰·인증·승인 이력 증명도 추가하지 않습니다. 모델은 조건 승인이나 계산·조회
실행 권한을 갖지 않습니다. 근거·브리핑은 선택한 mock 또는 OpenDART live 경로에서 생성합니다.

## 내부 출력 계약

어댑터는 다음 JSON 객체를 문자열로 반환합니다. 모든 최상위 키가 필수이며,
확정할 수 없는 조건은 `null`로 반환합니다. 이 객체는 실행 API 요청이 아닙니다.

```json
{
  "selected_source": "kosis",
  "entity": "전국 시·도",
  "metric": null,
  "period": null,
  "comparison": null,
  "filters": {"age_range": null, "frequency": "연간"},
  "uncertain_fields": ["metric", "comparison"]
}
```

- 자료원은 `kosis`, `opendart`, `undetermined`만 허용합니다.
- 조건·필터 값은 최대 100자의 문자열 또는 `null`입니다. 숫자·boolean을 문자열로
  강제 변환하지 않습니다. 필터는 최대 10개이며 해당 자료원의 필터만 허용합니다.
- `uncertain_fields`는 자료원·기본 조건·지원 필터 경로의 목록입니다. 값이 유효해도
  이 목록에 있으면 입력란을 비웁니다. 자료원이 불확실하면 모든 조건을 비우고 질문
  구체화를 요청합니다. 빠진 필터 값도 참가자가 선택해야 합니다.
- 출력은 최대 8,192자입니다. 깨진 JSON, 코드 블록, 앞뒤 설명, 중복 키, 비정상 타입,
  필수 키 누락, 알 수 없는 키·자료원·필터는 거부합니다. `approved`, `tool_calls`,
  `brief`, 검증 상태, 선택 이유 등을 해석기 출력으로 받아 실행하거나 표시하지 않습니다.
- 공개 선택 이유·확인 질문·필수 항목·선택 목록은 서버가 생성합니다. 지원하지 않는
  대상·지표·비교 기준·기간·필터 값은 비우고 한국어 안내를 남깁니다. 다른 지원 값으로
  자동 대체하지 않습니다.
- 기업공시와 국가통계 단서가 함께 있는 질문은 단서 개수로 한쪽을 고르지 않고 질문을
  나누도록 안내합니다. 질문 범위와 해석한 자료원이 충돌하면 출력을 거부합니다.

형식 검증과 지원 범위 검사는 모델이 질문의 뜻을 정확하게 이해했다는 보증이 아닙니다.
현재 범위 검사는 기존 키워드 규칙이므로 Gemini를 선택해도 자유로운 질문 전체를 지원하는
것은 아닙니다. 실제 자연어 표현·모호성 평가는 별도로 필요하며, 지원 값이라도 참가자의
확인·승인은 계속 필요합니다.

## 공개 계약과 참가자 화면

`/plan` 요청에 선택형 `interpretation_method: "mock_rules" | "gemini"`를 받습니다.
생략하면 `mock_rules`이며 `mode`는 `mock|live`를 허용합니다. 응답에는 사용한
`interpretation_method`와 `interpretation_model`(모의 규칙은 `null`, Gemini는 서버의
모델 이름)을 반환합니다. 프론트엔드 타입도 같은 계약을 사용합니다.

화면의 기본값은 ‘모의 규칙 · 외부 전송 없음’입니다. Gemini 선택 시 입력한 질문을
Google로 전송한다는 안내를 표시하고, ‘질문 분석’을 눌러야 요청합니다. 선택만으로
호출하지 않습니다. 계획에는 모의 규칙 또는 Gemini와 모델 이름을 표시하며 자료 모드를 별도로 표시합니다. 처음 해석할 때의 확인 안내는 접어 펼칠 수 있으며,
조건 편집 후의 조회 가능 여부는 입력란 아래의 현재 검증 안내가 판단합니다.
자료원을 정하지 못한 경우에는 조건 입력 대신 질문 구체화 안내를 표시합니다.

형식·자료원 계약 실패는 503 `invalid_planner_output`, 일반 공급자 오류는
503 `planner_unavailable`입니다. Gemini 비활성화는 503 `planner_disabled`, 설정 누락은
503 `planner_configuration_error`, 시간 초과는 503 `planner_timeout`, 프로세스 한도나
공급자 429 응답은 429 `planner_rate_limited`로 구분합니다. 각 오류는 한국어 안내와 빈
`field_errors`를 반환합니다. 원래 출력·검증 예외·공급자 오류 내용은 응답이나 로그에 기록하지 않습니다.
어댑터는 예상 가능한 공급자 오류를 `PlannerUnavailable`로 변환해야 합니다.
자동 재시도·다른 해석기로의 fallback은 하지 않습니다.

계획 실패 시 질문과 해석 방식은 유지하고 이전 조건·결과·비교·검토를 숨깁니다.
해석 방식을 변경하면 질문은 유지하고 조건·결과·비교 기준·검토를 초기화합니다. 다시 분석한 뒤에도
명시적 승인 전에는 근거·브리핑을 표시하지 않습니다. `review_required`는 유지합니다. `/analyze`는 기존 라우팅·응답을 유지하는 호환 경로이며
새 해석기나 메타데이터를 사용하지 않습니다. `/execute`에 해석 방식이나 모델 선택을
전달할 수 없으며, 승인된 조건만 사용합니다.

## Gemini 연결과 제한

서버의 `GEMINI_PLANNER_ENABLED=true`와 `LIVE_API_ENABLED=true`가 모두 필요합니다.
키·모델·시간 제한은 백엔드 설정이며 참가자가 모델 이름·키·호출 한도를 지정하지 않습니다.
기본 HTTP 타임아웃은 20초, 출력 한도는 2,048토큰, 모델 후보는 하나입니다.
프로세스 내부 한도는 분당 30회·동시 8회이며 시도한 실패 요청도 분당 한도에 포함합니다.
클라이언트 생성은 활성화·설정·한도 확인 후에만 진행합니다.

고정 시스템 지시와 참가자 질문을 분리하고, JSON Schema 응답을 요청한 뒤 내부 계약으로
다시 검증합니다. 차단·출력 잘림·빈 응답·도구 호출은 거부합니다. SDK 자동 재시도와
자동 함수 실행은 비활성화합니다. 브라우저 취소는 이미 보낸 모델 요청의 비용을 되돌리지
못합니다. 제한은 단일 프로세스 개발용이며 행사 전체의 분산 제한이나 예산 보증은 아닙니다.
활성화 절차와 인증 방식은 [환경 문서](ENVIRONMENTS.md#gemini-질문-해석-활성화), 결정 근거는
[ADR 0004](decisions/0004-gemini-planning-with-mock-evidence.md)를 참고합니다.

## 검증과 다음 범위

백엔드 테스트는 정상 계약, 필수 키·타입·길이·중복 키, 지원하지 않는 조건,
자료원 충돌, 모호성 우선 처리, 오류 내용 비노출, 재시도, 승인 후 해석기 미호출을
검증합니다. 실제 SDK에 모의 HTTP 전송을 주입하여 요청 형식·한 번의 호출·타임아웃·
안전 차단·출력 잘림·설정·동시/분당 한도·안전한 오류 변환도 검사합니다.
프론트엔드는 해석 방식 기본값·전송 안내·선택만으로 요청하지 않음·수정 후 별도 승인·
실패 후 질문과 방식 보존·방식 변경 시 결과와 검토 초기화·늦은 응답 무시를 검사합니다.
기존 두 질문과 세 실습도 회귀 검증합니다.
테스트는 환경 파일과 실제 네트워크를 사용하지 않습니다.

**기존 두 질문의 소규모 실제 Gemini 해석 확인**을 완료했습니다. 로컬 API 키 인증으로
공개 예시와 명확한 조건을 쓴 변형을 합쳐 4회 수동 확인했습니다. 모호한 조건을 비우고,
명시 조건을 해석하며, 참가자의 수정·승인 조건을 최종 결과에 유지하는 것을 확인했습니다.
Vertex 인증과 더 넓은 자연어 품질·반복 실행·부하는 남아 있습니다.
후속으로 [OpenDART 승인 조회](OPENDART_REVENUE.md)를 완료했습니다. live 계획은
삼성전자 2022·2024년 연결 매출액의 지원 범위를 적용합니다. 다른 값은 자동 대체하지 않고
비워 참가자의 확인을 요청합니다. `data_mode`를 계획 응답에 추가했습니다.
KOSIS live도 [확인된 자료 계약](KOSIS_EMPLOYMENT.md)에 따라 15~29세·고용률·연간·
2020~2024년과 명시한 시도 그룹만 허용합니다. mock의 15~34세·취업자 수 선택지는 유지하며
live에서는 자동 대체하지 않습니다. Gemini 해석을 선택해도 같은 모드별 검증을 적용하고,
실제 자료는 별도 승인 후에만 조회합니다. KOSIS/OpenDART 활성화 설정은 서로 독립적입니다.
