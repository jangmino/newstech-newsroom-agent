# NewsTech Newsroom Agent

뉴스룸 종사자가 자연어로 질문하면 OpenDART 또는 KOSIS의 공식 데이터를 조회하고, 조회 조건·출처·단위·계산 근거가 포함된 검토용 브리핑을 만드는 워크숍 애플리케이션입니다.

현재 저장소는 **M1·한정된 M2를 마치고 M3 운영 준비를 진행 중인 개발용 MVP**입니다. 실제 Gemini·OpenDART·KOSIS 호출은 기본적으로 꺼져 있습니다.

참가자는 질문 분석 후 대상·지표·기간·비교 기준을 확인하고 수정할 수 있습니다.
‘이 조건으로 조회’를 누르기 전에는 자료와 브리핑이 표시되지 않습니다. 미해결 조건은
한국어로 안내하며, 수정한 조건과 승인된 최종 조회 조건을 화면에서 확인할 수 있습니다.
청년 고용 mock 실습은 가상 지역 4곳의 2020~2024년 숫자로 변화값과 순위를 계산합니다.
입력값·단위·계산 불가 이유를 함께 표시하며, 공식 통계가 아니므로 실제 취재에 사용할 수 없습니다.
실제 자료를 선택하면 청년 고용은 17개 시도의 15~29세 연간 고용률, 기업 실적은
삼성전자 2022·2024년 연결 매출액을 조회합니다. 모든 결과는 사람의 검토가 필요합니다.

승인 후에는 같은 질문의 일반 응답 예시와 근거 기반 브리핑을 나란히 비교합니다.
일반 응답은 미리 작성한 모의 문장입니다. 근거 기반 응답은 선택한 자료 모드에 따라
모의 자료 또는 승인 후 조회한 OpenDART 공시/KOSIS 통계와 결정론적 계산을 사용합니다.
조회 조건·자료원·단위·계산식·한계가 얼마나 드러나는지 살펴볼 수 있습니다.

결과 아래에서 승인 조건·자료 출처·계산 근거·해석 한계를 체크하며 실습 검토 진행 상태를
확인할 수 있습니다. 모든 항목을 체크해도 사실 검증 완료나 기사 사용 승인이 아닙니다.
질문·조건 변경, 다시 분석·조회, 새로고침 시 검토 표시는 초기화됩니다.
자세한 동작은 [사람 검토 흐름](docs/REVIEW_FLOW.md)에 정리했습니다.

같은 질문에서 조건을 바꾸고 다시 승인하면 직전 성공 결과와 이번 결과를 비교합니다.
바뀐 조건을 강조하고, 지역별 입력값·변화값·순위를 각 결과의 출처와 단위로 표시합니다.
편집·조회 중에는 비교를 숨기며 질문 변경·재분석·새로고침 시 초기화됩니다.
검토 체크는 새 결과로 이어받지 않습니다. [조건 변경 전후 비교](docs/CONDITION_COMPARISON.md)를 참고하십시오.

‘막히는 상황 체험’에서 모호한 질문, 지원 범위 밖 기간, 0 기준값·누락값을 순서대로
살펴보고 조건을 수정할 수 있습니다. 예시 조건을 넣은 뒤에도 직접 승인해야 조회합니다.
기간을 바꾸는 실습은 비교 범위를 바꾸는 것이며 원래 기간의 누락값을 해결하지 않습니다.
[실습 안내](docs/WORKSHOP_SCENARIOS.md)에 단계별 동작과 확인할 점을 정리했습니다.

질문 해석은 기본적으로 모의 규칙을 사용하며, 서버에서 활성화한 경우 Gemini로 질문을
해석할 수 있습니다. 요청 전에 질문의 외부 전송을 안내하고, 성공 후 해석 방식과 모델을 표시합니다.
질문 해석 방식과 조회 자료 모드는 독립적이며, 일반 응답 예시는 계속 mock입니다. 해석 결과는 별도 계약으로
검증하고, 지원하지 않거나 불확실한 조건은 비워 참가자가 확인하도록 합니다.
형식이 잘못된 출력은 한국어 재시도 안내로 중단합니다. 승인 후에는 질문을 다시
해석하지 않고 승인 조건을 검증·실행합니다. [질문 구조화 계약](docs/QUESTION_PLANNING.md)을
참고하십시오. Gemini 연결 코드는 모의 전송으로 검증했으며 실제 호출은 기본 비활성화입니다.
로컬 API 키로 네 질문의 실제 해석도 확인했습니다. [실제 확인 결과](docs/GEMINI_SMOKE_TEST.md)와
[활성화 방법](docs/ENVIRONMENTS.md#gemini-질문-해석-활성화)을 참고하십시오.

OpenDART는 삼성전자 2022·2024년 연간 연결 매출액의 실제 응답·공시 원문 대조와
승인 화면 연결을 완료했습니다. 조회 자료에서 ‘공식 실제 자료 · OpenDART / KOSIS’를 선택한 뒤
`삼성전자 2022-2024년 연결 연간 매출액 증감률 비교`로 분석하고 승인하면 됩니다.
증감 폭/률, 원문 링크, 계정, 연도별 조회 시각을 확인할 수 있습니다. 키는 백엔드만 사용합니다.
[활성화 방법](docs/ENVIRONMENTS.md#opendart-실제-자료-활성화),
[매출액 조회 계약](docs/OPENDART_REVENUE.md), [실제 확인 기록](docs/OPENDART_SMOKE_TEST.md)을
참고하십시오. OpenDART의 다른 기업·지표·연도·별도·분기는 아직 지원하지 않습니다.

KOSIS도 승인 후 실제 조회·계산·근거·검토 연결과 공식 통계표 대조를 마쳤습니다.
같은 실제 자료 선택에서 `전국 시·도 15-29세 청년 고용률 2020-2024년 연간 증감 폭 비교`로
분석·승인합니다. 대상은 전국/수도권/비수도권의 각 시도, 기간은 2020~2024년 내 두 연도,
비교 기준은 증감 폭/률입니다. 연간 공표값·통계 코드·최종수정일·조회 시각·원표 링크도 제공합니다.
15~34세·취업자 수로 자동 대체하지 않습니다. [지원 범위](docs/KOSIS_EMPLOYMENT.md),
[활성화 방법](docs/ENVIRONMENTS.md#kosis-실제-자료-활성화),
[실제 확인 기록](docs/KOSIS_SMOKE_TEST.md)을 참고하십시오.

## 구조

M3 첫 단위로 [공공자료 캐시와 동일 요청 합치기](docs/PUBLIC_DATA_CACHE.md)를 적용했습니다.
승인 후 같은 원자료를 기본 1시간 동안 재사용하고, 재사용 여부·원래 조회 시각·기한을
표시합니다. 비교 기준을 바꾸면 같은 원자료로 다시 계산하며 검토는 새로 시작합니다.
캐시는 단일 프로세스 메모리이며 재시작 시 비워집니다. 실패·만료 자료를 자동 대체하지 않습니다.
[공공자료 호출 제한](docs/PUBLIC_DATA_LIMITS.md)은 자료원마다 최근 60초 HTTP 시작 30회·
동시 2회를 기본으로 적용합니다. 캐시 재사용에는 추가 한도를 쓰지 않고 초과 시 한국어로
안내합니다. 입력 조건을 유지하며 참가자가 직접 재승인해야 합니다.
[공식 저장 자료](docs/SNAPSHOT_FALLBACK.md)도 선택할 수 있습니다. 출처·원래 조회 시각·
지원 범위를 확인하고 승인한 뒤에만 계산합니다. 실제 조회 오류 뒤의 전환도 별도로
선택·재승인하며 자동 대체하지 않습니다. 모의 규칙과 함께 선택하면 외부 호출 없이 확인할 수 있습니다.

```text
apps/web      React + Vite 프론트엔드
apps/api      FastAPI 백엔드와 단일 에이전트 오케스트레이터
docs          제품 범위, 아키텍처, 환경 전환, 공공데이터 준비, Codex 하네스
fixtures      공식 저장 자료 준비 및 가상 계산 실습 안내
infra         Cloud Run 단일 컨테이너 배포 준비
```

개발 중에는 프론트엔드와 백엔드를 별도로 실행합니다. 스테이징에서는 프론트엔드를 빌드해 FastAPI가 함께 제공하므로 Cloud Run 서비스 하나로 운영할 수 있습니다.

## 처음 시작하기

필요 도구:

- Node.js 20
- pnpm 9
- Python 3.12
- uv
- Docker Desktop(선택)
- Google Cloud CLI(스테이징부터)

```bash
cp .env.example .env
pnpm install
cd apps/api && uv sync --dev && cd ../..
```

터미널 두 개에서 실행합니다.

```bash
make dev-api
make dev-web
```

- 프론트엔드: http://localhost:5173
- 백엔드 상태 확인: http://localhost:8000/health

로컬의 `WORKSHOP_ACCESS_CODE`가 비어 있으면 기존처럼 바로 실습합니다. 코드를 설정하고
API를 재시작하면 입장 화면이 표시됩니다. [행사용 접근코드 안내](docs/WORKSHOP_ACCESS.md)를
참고하십시오. 입장과 조회 조건 승인은 별도이며 코드는 현재 탭에서만 유지합니다.

또는 VS Code에서 `Terminal > Run Task > Dev: web + api`를 실행할 수 있습니다.

## 검증

```bash
make check
```

`make check`는 백엔드 테스트, 프론트엔드 동작 테스트, 타입 검사와 빌드를 실행합니다.
검토 UI만 확인하려면 `make test-web`을 실행합니다. UI 테스트는 모의 응답을 사용하고
dotenv 로딩과 실제 요청을 차단합니다.

## 환경 전환

| 단계 | 모델·인프라 소유자 | 데이터 방식 | 목적 |
|---|---|---|---|
| local | 개발자 개인 | mock 우선, 개인 키로 제한적 실험 | 기능 개발 |
| 임시 stage | 개발자 개인, 사용자 승인 | mock·공식 저장 자료, Secret Manager 접근코드 | 기관 계정 전 배포 검증 |
| stage | 건국대학교·주최 측 | 기관 키 + 저장 자료 fallback | 부하 시험·리허설 |
| event | 건국대학교·주최 측 | 기관 키 + 모니터링 + fallback | 워크숍 운영 |

개인 키를 Git에 커밋하거나 브라우저 코드에 넣지 않습니다. 자세한 내용은 [환경 전환 문서](docs/ENVIRONMENTS.md)를 확인하십시오.

## 현재 범위

- 포함: 단일 오케스트레이터, 조건 편집·승인, 응답·조건 비교, 오류 실습, 결정론적 계산·검증, 근거·사람 검토, Gemini 질문 해석, OpenDART/KOSIS의 한정된 실제 조회, Cloud Run 이미지 구조
- 후속 구현: M3 기관 stage 배포·행사 운영 준비, Gemini 추가 표현·반복 실행 품질 검증
- 제외: 멀티에이전트, 기사 자동 발행, CMS 연동, 모든 공공데이터 자유 질의, 행사 이후 상시 운영

제품 범위는 [제품 개요](docs/PRODUCT_BRIEF.md)에 정리되어 있습니다.
현재 **M1과 기존 두 질문의 한정된 M2 실제 연결을 완료**했으며,
M3 캐시·동일 요청 합치기·프로세스 내부 호출 제한·명시적 snapshot fallback·공유 접근코드까지
구현했습니다. [요청 ID·구조화 로그와 오류 문의 번호](docs/REQUEST_LOGGING.md)도 완료했으며,
[읽기 전용 실습 운영 상태 화면](docs/OPERATIONS_STATUS.md)도 완료했습니다. 제목 아래
‘실습 운영 상태 보기’에서 외부 호출 없이 설정·저장 파일·캐시/호출 한도를 확인합니다.
[개인 임시 stage](docs/STAGE_SMOKE_TEST.md)도 Cloud Run·Secret Manager·비용 알림과 함께
배포했습니다. 현재 stage의 실제 공급자는 꺼져 있으며 mock·저장 자료로 확인했습니다.
[30명 단기 API 부하 시험](docs/STAGE_LOAD_TEST.md)도 766개 요청으로 통과했습니다.
[장애·저장 자료 전환 리허설](docs/FALLBACK_REHEARSAL.md)도 모의 장애와 stage 비활성 경로로
완료했습니다. 다음은 행사 운영자 가이드와 시작·중단·종료 점검표입니다.
기관 환경 재배포·실제 공급자 Secret 연결·
지속 부하와 행사장 확인·넓은 모델 품질 검증은 남아 있습니다.
전체 진행 상태는 [로드맵](docs/ROADMAP.md)을 참고하십시오.
가상 숫자로 비교 기준과 오류를 체험하는 방법은 [계산 실습 안내](fixtures/synthetic/README.md)를 참고하십시오.
